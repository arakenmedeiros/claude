## 3.1 A roupa suja vem antes do modelo

Todo cozinheiro sabe: antes de cozinhar, é preciso **lavar, descascar e cortar** os ingredientes. Com dados é igual. Os dados reais chegam sujos: células vazias, números em escalas muito diferentes, categorias escritas como texto.

![f3_lavanderia](Figura 3.1 — Cada problema dos dados tem sua ferramenta. O pipeline de pré-processamento aplica todas, sempre na mesma ordem.)

Esse trabalho é chamado de **pré-processamento**. É a base de qualquer projeto de aprendizado de máquina e é parte do que o AutoML precisa decidir. O Auto-sklearn, por exemplo, inclui no seu espaço de busca métodos de preparo dos dados e de pré-processamento de atributos (Feurer *et al.*, 2015). Levantamentos de AutoML também revisam o pipeline passo a passo (Zöller; Huber, 2021).

:::atencao Atenção
O AutoML pode escolher **como** tratar os dados, mas não adivinha **o que significam**. Uma coluna "999" pode ser idade ou um código para "não informado". Essa interpretação continua sendo humana.
:::

## 3.2 Os dados deste capítulo

Para praticar, vamos criar um conjunto de dados **propositalmente sujo**. Partiremos do conjunto **Wine** (UCI), com 13 medidas químicas de 178 vinhos (Dua; Graff, 2019). Acrescentaremos, por simulação, dois problemas comuns:

- uma coluna **categórica** de texto (a "safra" do vinho);
- **valores ausentes** (8% de células vazias em quatro colunas).

É importante dizer: esses problemas foram inseridos por nós, para fins didáticos. Em um projeto real, os dados já chegam assim.

```python
#@nb
#@saida
import numpy as np
import pandas as pd
from sklearn.datasets import load_wine

rng = np.random.default_rng(0)
df = load_wine(as_frame=True).frame.copy()

# Coluna categórica simulada ("safra"), levemente ligada à classe do vinho
safras = np.array(["2018", "2019", "2020"])
df["safra"] = np.where(rng.random(len(df)) < 0.8, safras[df["target"].values % 3], rng.choice(safras, len(df)))

# 8% de valores ausentes, ao acaso, em quatro colunas
for coluna in ["alcohol", "malic_acid", "flavanoids", "proline"]:
    df.loc[rng.random(len(df)) < 0.08, coluna] = np.nan

y = df.pop("target")
X = df
print("Formato de X:", X.shape)
print("\nValores ausentes por coluna:")
print(X.isna().sum()[X.isna().sum() > 0].to_string())
print("\nColunas numéricas:", X.select_dtypes("number").shape[1], "| colunas de texto:", X.select_dtypes(exclude="number").shape[1])
```

## 3.3 O que acontece se ignorarmos a sujeira?

Vamos tentar treinar um modelo diretamente nesses dados.

```python
#@nb
#@saida
from sklearn.linear_model import LogisticRegression

try:
    LogisticRegression().fit(X, y)
except ValueError as erro:
    print("O scikit-learn recusou os dados:")
    print(str(erro).splitlines()[0][:110])
```

O modelo recusa dados com valores vazios e com texto. Precisamos tratar cada problema.

## 3.4 Valores ausentes: imputação

**Imputar** é preencher os valores que faltam com um palpite razoável. As opções mais comuns:

- **Média** ou **mediana** da coluna. A mediana é mais robusta quando há valores extremos.
- **Valor mais frequente**, para colunas categóricas.
- **Vizinhos mais próximos** (`KNNImputer`): usa os exemplos mais parecidos para preencher.
- **Indicador de ausência**: cria uma coluna extra dizendo "este valor estava faltando". Às vezes **o fato de faltar** já é informação (por exemplo, quem não informa renda).

**Analogia:** você esqueceu o sal na lasanha. Pode usar "uma pitada média" (a média), "a quantidade da receita mais comum" (a mediana) ou copiar a quantidade de uma receita parecida (vizinhos).

:::dica Dica
Escolher *como* imputar é um hiperparâmetro do pipeline. Você pode deixar o AutoML testar média, mediana e vizinhos, e escolher o melhor pela validação.
:::

## 3.5 Escalas diferentes: padronização

Observe os números do Wine: o álcool varia de 11 a 15, enquanto a prolina vai de quase 300 a mais de 1600. Para um algoritmo baseado em distância, como o k-vizinhos, a prolina vai **dominar tudo**.

![f3_escalas](Figura 3.2 — Sem padronização, a prolina "grita" mais alto que o álcool em qualquer cálculo de distância. Padronizado, as duas medidas pesam parecido.)

As técnicas mais usadas:

- **Padronização** (`StandardScaler`): subtrai a média e divide pelo desvio padrão. O resultado tem média 0 e desvio 1.
- **Min-máx** (`MinMaxScaler`): leva os valores para o intervalo de 0 a 1.
- **Robusta** (`RobustScaler`): usa mediana e quartis, e sofre menos com valores extremos.

Nem todo algoritmo precisa disso. **Árvores e florestas** não se importam com a escala, pois só comparam "maior ou menor". Mas **k-vizinhos, SVM, regressão logística e redes neurais** dependem dela.

```python
#@saida
from sklearn.datasets import load_wine
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)   # versão completa (sem ausentes) só para este teste
sem = cross_val_score(KNeighborsClassifier(), X, y, cv=5).mean()
com = cross_val_score(make_pipeline(StandardScaler(), KNeighborsClassifier()), X, y, cv=5).mean()
print(f"k-vizinhos sem padronizar: {sem:.3f}")
print(f"k-vizinhos padronizado   : {com:.3f}")
```

Uma simples padronização muda muito o resultado. Um bom AutoML considera a escala como parte da busca.

## 3.6 Categorias em texto: codificação

Modelos entendem números, e não palavras. É preciso **codificar** as categorias.

Uma ideia ingênua é trocar "Recife", "Natal" e "Salvador" por 1, 2 e 3. Mas isso ensina ao modelo uma **ordem que não existe** (como se Salvador fosse "maior" que Natal). A solução usual é a **codificação one-hot**.

![f3_onehot](Figura 3.3 — Na codificação one-hot, cada categoria vira uma coluna de 0 ou 1.)

Use a **codificação ordinal** (1, 2, 3) apenas quando existe ordem natural, como "baixo, médio, alto". Para categorias com **milhares de valores** (como CEP), o one-hot gera colunas demais, e são necessárias técnicas especiais.

:::atencao Atenção
Na produção, podem aparecer **categorias novas**, que o modelo nunca viu. Com `OneHotEncoder(handle_unknown="ignore")`, elas são codificadas como "todos zeros", em vez de derrubar o sistema.
:::

## 3.7 Pipelines: uma linha de montagem em código

Fazer cada passo à mão é trabalhoso e propenso a erros. O scikit-learn oferece duas peças para organizar tudo (Pedregosa *et al.*, 2011):

- **`Pipeline`**: encadeia etapas, em que a saída de uma é a entrada da próxima. O último passo é o modelo.
- **`ColumnTransformer`**: aplica tratamentos **diferentes** a grupos diferentes de colunas.

![f3_colunas](Figura 3.4 — Colunas numéricas e categóricas recebem tratamentos próprios. No fim, tudo se junta e alimenta o modelo.)

```python
#@nb
#@saida
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score

colunas_num = X.select_dtypes(include="number").columns.tolist()
colunas_cat = ["safra"]

preparo = ColumnTransformer([
    ("num", Pipeline([("imputar", SimpleImputer(strategy="median")),
                      ("escala", StandardScaler())]), colunas_num),
    ("cat", Pipeline([("imputar", SimpleImputer(strategy="most_frequent")),
                      ("onehot", OneHotEncoder(handle_unknown="ignore"))]), colunas_cat),
])

pipeline = Pipeline([("preparo", preparo), ("modelo", LogisticRegression(max_iter=2000))])

notas = cross_val_score(pipeline, X, y, cv=5)
print("Notas:", notas.round(3), "| média =", round(notas.mean(), 3))
```

Pronto: um único objeto que **recebe a tabela suja e devolve previsões**. Ao chamar `.fit(X, y)`, cada etapa aprende o que precisa (a mediana, a média, as categorias) usando apenas os dados de treino. Ao chamar `.predict(X_novo)`, aplica as mesmas transformações.

## 3.8 O perigo do vazamento de dados

Chegamos a um dos conceitos **mais importantes** do livro: o **vazamento de dados** (*data leakage*).

Vazamento ocorre quando **informação do conjunto de validação (ou teste) "escapa" para o treino**. O modelo parece melhor do que é, e você só percebe quando ele falha na vida real.

![f3_vazamento](Figura 3.5 — Calcular a escala com todos os dados antes de dividir deixa a validação "espiar" o treino. O certo é aprender tudo apenas com o treino.)

**Analogia:** estudar com a prova na mão. A nota sobe, mas não mede aprendizado.

Um estudo de grande escala encontrou vazamento em dezenas de campos que usam aprendizado de máquina, afetando centenas de artigos e levando a conclusões exageradas (Kapoor; Narayanan, 2023). Não é um erro só de iniciantes.

### Um experimento revelador

Um exemplo clássico, descrito por Hastie, Tibshirani e Friedman (2009), mostra o estrago. Criamos dados **totalmente aleatórios**: 100 exemplos, 2000 atributos sem nenhuma relação com o alvo. Qualquer método honesto deve acertar cerca de 50%.

Fazemos de duas formas. Na **errada**, escolhemos os 20 "melhores" atributos olhando *todos* os dados e só depois validamos. Na **certa**, a escolha dos atributos fica *dentro* do pipeline, refeita a cada divisão.

```python
#@saida
import numpy as np
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(0)
X = rng.normal(size=(100, 2000))     # atributos sem nenhuma relação com y
y = rng.integers(0, 2, 100)          # alvo sorteado

# ERRADO: seleciona atributos com TODOS os dados, depois valida
X_sel = SelectKBest(f_classif, k=20).fit_transform(X, y)
errado = cross_val_score(LogisticRegression(), X_sel, y, cv=5).mean()

# CERTO: a seleção está DENTRO do pipeline (refeita em cada divisão)
certo_pipe = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression())
certo = cross_val_score(certo_pipe, X, y, cv=5).mean()

print(f"Seleção fora do pipeline (errado): acurácia = {errado:.3f}")
print(f"Seleção dentro do pipeline (certo): acurácia = {certo:.3f}")
```

No jeito errado, a acurácia fica **muito acima de 50%**, e isso é impossível em dados sem sinal! A seleção olhou os rótulos da validação. No jeito certo, o resultado volta para perto do acaso (a pequena diferença em relação a 50% é ruído, natural em uma amostra de apenas 100 exemplos).

:::memorize Regra de ouro contra o vazamento
**Toda etapa que aprende algo dos dados** (imputação, escala, seleção de atributos, redução de dimensões) deve estar **dentro do `Pipeline`**. Assim, ela é reaprendida só com o treino em cada divisão.
:::

## 3.9 O pipeline como espaço de busca

Agora a ligação com o AutoML. Cada etapa do pipeline tem **escolhas**: como imputar, qual escala usar, se haverá seleção de atributos, qual algoritmo. Juntas, formam o espaço de busca.

![f3_espaco](Figura 3.6 — Mesmo com poucas opções por etapa, o número de pipelines cresce rápido, antes de contar os hiperparâmetros.)

O scikit-learn permite buscar **dentro do pipeline** usando nomes com dois sublinhados (`__`), que indicam "etapa, parâmetro". Etapas inteiras também podem ser trocadas, como o tipo de escala.

```python
#@nb
#@saida
from sklearn.model_selection import GridSearchCV
from sklearn.preprocessing import MinMaxScaler, RobustScaler

busca_pipe = Pipeline([
    ("preparo", ColumnTransformer([
        ("num", Pipeline([("imputar", SimpleImputer()), ("escala", StandardScaler())]), colunas_num),
        ("cat", Pipeline([("imputar", SimpleImputer(strategy="most_frequent")),
                          ("onehot", OneHotEncoder(handle_unknown="ignore"))]), colunas_cat),
    ])),
    ("modelo", LogisticRegression(max_iter=3000)),
])

grade = {
    "preparo__num__imputar__strategy": ["mean", "median"],
    "preparo__num__escala": [StandardScaler(), MinMaxScaler(), RobustScaler()],
    "modelo__C": [0.1, 1, 10],
}
busca = GridSearchCV(busca_pipe, grade, cv=5, n_jobs=-1).fit(X, y)

print("Combinações testadas:", len(busca.cv_results_["params"]))
print("Melhor nota de validação:", round(busca.best_score_, 3))
for nome, valor in busca.best_params_.items():
    print(f"  {nome} = {valor}")
```

Isto já é um **mini-AutoML** sobre pipelines: um espaço de busca, uma estratégia (grade) e uma estimativa (validação cruzada). Nos próximos capítulos, a estratégia ficará muito mais inteligente.

## 3.10 Outras transformações úteis

Além de imputar, padronizar e codificar, há outras transformações que um pipeline pode incluir.

- **Transformações de cauda** (`PowerTransformer`, `QuantileTransformer`): deixam distribuições muito assimétricas (como renda) mais parecidas com um sino.
- **Remoção de colunas quase constantes** (`VarianceThreshold`): descarta atributos que quase não mudam.
- **Seleção de atributos** (`SelectKBest`): fica com os atributos mais ligados ao alvo (veja o Capítulo 8).
- **Redução de dimensionalidade** (`PCA`): resume muitas colunas em poucas, preservando a maior parte da variação.
- **Desbalanceamento de classes:** use `class_weight="balanced"` em muitos algoritmos, ou ajuste a métrica (Capítulo 2).

Todas elas entram no pipeline como mais uma etapa, e todas podem ser escolhidas por uma busca automática.

## 3.11 Salvando e reutilizando o pipeline

Depois de treinar, você precisará **guardar** o pipeline para usá-lo mais tarde, em outro programa ou servidor. Como o pré-processamento faz parte do objeto, nada se perde: quem receber o arquivo aplica exatamente as mesmas transformações.

```python
#@nb
#@saida
import joblib

melhor_pipeline = busca.best_estimator_            # já treinado com todos os dados
joblib.dump(melhor_pipeline, "/tmp/pipeline_vinho.joblib")

recarregado = joblib.load("/tmp/pipeline_vinho.joblib")
posicoes = [0, 30, 70, 100, 140, 170]              # vinhos de classes diferentes, com ausentes e texto
novos = X.iloc[posicoes]
print("Classes reais            :", y.iloc[posicoes].tolist())
print("Previsões do original   :", melhor_pipeline.predict(novos).tolist())
print("Previsões do recarregado:", recarregado.predict(novos).tolist())
```

Esse hábito será essencial no Capítulo 14, quando falarmos de colocar modelos em produção.

:::atencao Atenção
Arquivos do `joblib` (e do `pickle`) podem executar código ao serem abertos. **Nunca carregue** um arquivo de origem desconhecida.
:::

## Resumo do capítulo

:::memorize Cartões de memorização
- **Pré-processamento:** imputar (ausentes), padronizar (escalas), codificar (categorias).
- **Escala:** importa para k-vizinhos, SVM, regressão e redes; não importa para árvores.
- **One-hot** evita inventar uma ordem entre categorias.
- **Pipeline** encadeia etapas; **ColumnTransformer** trata colunas de tipos diferentes.
- **Vazamento:** informação da validação "espiando" o treino. A nota fica falsamente alta.
- **Regra de ouro:** tudo que aprende dos dados fica dentro do pipeline.
- **O pipeline inteiro é o espaço de busca** do AutoML. Use `etapa__parametro` para buscar dentro dele.
- **Salve o pipeline completo**, não só o modelo.
:::
