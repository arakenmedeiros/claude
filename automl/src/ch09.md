## 9.1 Aprender com a experiência

Imagine dois médicos diante de um paciente com um quadro novo. O **médico iniciante** pede todos os exames possíveis. O **médico experiente** reconhece o caso: "parece com outros que já vi" e vai direto aos exames mais prováveis de ajudar.

![f9_medico](Figura 9.1 — O meta-aprendizado dá ao AutoML a experiência de problemas anteriores.)

Nos capítulos anteriores, cada busca de hiperparâmetros **começava do zero**, como o médico iniciante: nada se sabia sobre o novo conjunto de dados. Mas já resolvemos muitos problemas parecidos! Será que essa experiência pode ajudar?

É a ideia do **meta-aprendizado** (*meta-learning*, ou "aprender a aprender"): usar os resultados de **conjuntos de dados anteriores** para decidir mais depressa e melhor o que fazer em um **novo**. Esse é um dos temas centrais do AutoML moderno, com livros dedicados (Brazdil *et al.*, 2022) e capítulos no livro de referência da área (Hutter; Kotthoff; Vanschoren, 2019).

Neste capítulo, vamos ver duas formas de aproveitar essa experiência e uma terceira ideia, independente, que tornou o AutoML muito forte: **combinar modelos**.

## 9.2 O quadro de Rice: escolher o algoritmo por características do problema

Já mencionamos o **problema da seleção de algoritmos**, formulado por Rice (1976): dado um problema, qual algoritmo resolve melhor? Rice o descreveu com **quatro espaços**.

![f9_rice](Figura 9.2 — O quadro de Rice: extrair características do problema, aprender uma regra de seleção e recomendar um algoritmo, avaliando o desempenho.)

1. **Espaço dos problemas:** os conjuntos de dados.
2. **Espaço das características:** descrições resumidas de cada problema, os **meta-atributos**.
3. **Mapeamento de seleção:** a regra (um modelo, o **meta-modelo**) que, dadas as características, escolhe o algoritmo.
4. **Medida de desempenho:** o quanto o algoritmo escolhido acerta naquele problema.

Em outras palavras: se pudermos **descrever** cada conjunto de dados por alguns números, podemos **treinar um modelo** que aprenda "que tipo de problema se dá bem com que tipo de algoritmo".

## 9.3 Meta-atributos

Os **meta-atributos** (*meta-features*) são descrições de um conjunto de dados inteiro. Eles são calculados rápido, sem treinar modelos caros.

![f9_metaatributos](Figura 9.3 — Quatro famílias de meta-atributos.)

- **Simples e estatísticos:** número de exemplos, de atributos e de classes; assimetria média dos atributos.
- **Teoria da informação:** entropia das classes (quão balanceadas são).
- **Complexidade do problema:** medidas de sobreposição entre classes e de suavidade da fronteira (Lorena *et al.*, 2019).
- **Landmarkers:** a nota de **modelos simples e rápidos** (uma árvore rasa, por exemplo) no problema. É uma "sonda" do tipo de estrutura que os dados têm.

A literatura mostra que a descrição, a organização e o cálculo dos meta-atributos variam entre trabalhos, o que dificulta a reprodução (Rivolli *et al.*, 2022). Vamos calcular oito meta-atributos de quatro conjuntos de dados reais.

```python
#@nb
#@saida
import numpy as np
import warnings; warnings.filterwarnings("ignore")
from scipy.stats import skew, entropy
from sklearn.datasets import make_classification, load_iris, load_wine, load_breast_cancer, load_digits
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.svm import SVC
from sklearn.linear_model import LogisticRegression
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier, HistGradientBoostingClassifier
from sklearn.model_selection import cross_val_score, StratifiedKFold, train_test_split
from sklearn.metrics import accuracy_score, log_loss

NOMES = ["log(n)", "log(d)", "n/d", "classes", "entropia", "assimetria", "correlação", "landmarker"]

def meta_atributos(X, y):
    n, d = X.shape; c = len(np.unique(y)); p = np.bincount(y) / n
    assim = np.abs(skew(X, axis=0))                                      # assimetria de cada atributo
    cor = np.abs(np.corrcoef(X.T)); np.fill_diagonal(cor, 0)             # correlação entre atributos
    landmarker = cross_val_score(DecisionTreeClassifier(max_depth=1, random_state=0), X, y, cv=3).mean()
    return [np.log(n), np.log(d), n / d, c, entropy(p) / np.log(c), np.nanmean(assim), np.nanmean(cor), landmarker]

print(f"{'conjunto':8s} | " + " | ".join(f"{n:>11s}" for n in NOMES))
for nome, carregar in [("Iris", load_iris), ("Wine", load_wine), ("Cancer", load_breast_cancer), ("Digits", load_digits)]:
    X, y = carregar(return_X_y=True)
    print(f"{nome:8s} | " + " | ".join(f"{v:11.2f}" for v in meta_atributos(X, y)))
```

Repare como os conjuntos têm "retratos" diferentes: o Digits tem muitos exemplos e atributos e 10 classes; o Iris é minúsculo, com 3 classes balanceadas. Um meta-modelo pode aprender com essas diferenças.

## 9.4 Construindo um meta-aprendizado do zero

Vamos montar um **meta-conjunto**: uma coleção de problemas, cada um descrito por seus meta-atributos e rotulado com o **melhor algoritmo** entre quatro candidatos (k-vizinhos, SVM, regressão logística e floresta). Depois, treinamos um **meta-modelo** que prevê o melhor algoritmo a partir dos meta-atributos.

Como não temos centenas de conjuntos reais à mão, vamos **simular 150 conjuntos de dados** com `make_classification`, variando tamanho, número de atributos, de classes, separabilidade e ruído. Mais adiante, testaremos o meta-modelo em **conjuntos reais** que ele nunca viu.

Para avaliar com honestidade, usamos a validação **"deixe um conjunto de fora"**: para cada conjunto, o meta-modelo é treinado com os outros 149 e testado no conjunto excluído. Como linha de base, comparamos com a regra boba "recomendar sempre o algoritmo que mais vence".

```python
#@nb
def gerar_conjunto(rng, i):
    n = int(rng.integers(150, 500)); d = int(rng.integers(8, 40)); inf = int(rng.integers(4, min(d - 2, 12) + 1)); c = int(rng.integers(2, 5))
    return make_classification(n_samples=n, n_features=d, n_informative=inf, n_redundant=int(rng.integers(0, (d - inf) // 2 + 1)),
                               n_classes=c, n_clusters_per_class=int(rng.integers(1, 3)), class_sep=float(rng.uniform(0.4, 2.0)),
                               flip_y=float(rng.uniform(0, 0.1)), random_state=i)

ALGORITMOS = {"knn": lambda: make_pipeline(StandardScaler(), KNeighborsClassifier()),
              "svm": lambda: make_pipeline(StandardScaler(), SVC()),
              "logistica": lambda: make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
              "floresta": lambda: RandomForestClassifier(60, random_state=0, n_jobs=-1)}

def avaliar_todos(X, y):
    cv = StratifiedKFold(3, shuffle=True, random_state=0)
    return {nome: cross_val_score(f(), X, y, cv=cv).mean() for nome, f in ALGORITMOS.items()}
```

```python
#@nbx
#@saida
import collections

rng = np.random.default_rng(0)
M, R = [], []
for i in range(150):
    X, y = gerar_conjunto(rng, i)
    M.append(meta_atributos(X, y)); R.append(avaliar_todos(X, y))
M = np.array(M); melhor = np.array([max(r, key=r.get) for r in R])
print("Quantas vezes cada algoritmo foi o melhor nos 150 conjuntos:", dict(collections.Counter(melhor)))

acertos, perdas = [], []
for i in range(len(M)):
    treino = np.arange(len(M)) != i
    previsto = RandomForestClassifier(200, random_state=0).fit(M[treino], melhor[treino]).predict(M[i:i+1])[0]
    acertos.append(previsto == melhor[i]); perdas.append(max(R[i].values()) - R[i][previsto])

frequente = collections.Counter(melhor).most_common(1)[0][0]
perdas_freq = [max(r.values()) - r[frequente] for r in R]
print(f"\nAcerto do meta-modelo ao indicar o melhor algoritmo : {np.mean(acertos):.3f}")
print(f"Acerto de 'sempre {frequente}' (linha de base)           : {collections.Counter(melhor)[frequente] / len(M):.3f}")
print(f"Perda média de acurácia frente ao melhor: meta-modelo = {np.mean(perdas):.4f} | sempre {frequente} = {np.mean(perdas_freq):.4f}")

meta_modelo = RandomForestClassifier(300, random_state=0).fit(M, melhor)
print("\nTeste em conjuntos REAIS (nunca vistos pelo meta-modelo):")
for nome, carregar in [("Iris", load_iris), ("Wine", load_wine), ("Cancer", load_breast_cancer), ("Digits", load_digits)]:
    X, y = carregar(return_X_y=True); notas = avaliar_todos(X, y)
    rec = meta_modelo.predict(np.array(meta_atributos(X, y))[None])[0]
    real = max(notas, key=notas.get)
    print(f"  {nome:7s} recomendado = {rec:9s} ({notas[rec]:.3f}) | melhor de verdade = {real:9s} ({notas[real]:.3f})")
```

![f9_metaresultado](Figura 9.4 — O meta-modelo contra a regra "sempre o mais frequente" em 150 conjuntos simulados.)

O resultado é **humilde**. O meta-modelo acerta o melhor algoritmo na mesma proporção que a regra boba (cerca de 59%), e a perda média de acurácia é só ligeiramente menor. Nos conjuntos reais, ele recomenda o SVM, que vai bem em todos, ainda que não seja o primeiro colocado em Iris e Cancer, com perdas pequenas.

Por que o ganho foi pequeno? Porque (1) nossos 150 conjuntos são **poucos e simulados**; (2) usamos apenas **oito meta-atributos** simples; (3) com só quatro algoritmos "padrão", as diferenças entre eles costumam ser pequenas, e o SVM é muito competitivo na maioria dos casos. Sistemas reais usam **centenas de conjuntos** (por exemplo, do repositório OpenML; Vanschoren *et al.*, 2014) e meta-atributos mais ricos.

:::memorize Memorize
Recomendar o **algoritmo** é a forma mais difícil de meta-aprendizado. Há uma forma mais robusta e mais usada na prática: recomendar **por onde começar a busca** (configurações iniciais). É o *warm start*.
:::

## 9.5 Warm start: partida a quente

Imagine que você precisa ajustar o SVM em um conjunto novo. A busca aleatória ou bayesiana começa com valores sorteados, muitos dos quais são ruins. Mas a experiência anterior diz que certas combinações de *C* e *gamma* costumam funcionar bem em **muitos** problemas. Por que não **começar por elas**?

Essa é a ideia do ***warm start*** (partida a quente). Feurer, Springenberg e Hutter (2015) propuseram inicializar a otimização bayesiana com configurações que se saíram bem em conjuntos de dados parecidos, como fazem os especialistas, e obtiveram ganhos modestos na busca de hiperparâmetros de um algoritmo e maiores no problema CASH.

Vamos reproduzir a ideia com um **portfólio**: um conjunto pequeno de configurações **complementares**, escolhidas para funcionar bem em conjunto. O procedimento:

1. Avaliar 25 configurações do SVM (5 valores de *C* × 5 de *gamma*) em 40 conjuntos simulados de **origem**.
2. Montar um portfólio de 3 configurações pelo critério guloso: cada nova configuração é a que mais melhora, na média, o **melhor resultado do portfólio** nos conjuntos de origem.
3. No conjunto **alvo** (real), testar essas 3 configurações primeiro e comparar com 3 configurações sorteadas.

Um detalhe técnico importante: o melhor *gamma* depende do número de atributos *d*. Para que as configurações sejam transferíveis, usamos um *gamma* **relativo**: `gamma = gamma_rel / d`.

```python
#@nbx
#@saida
C_VALORES = [0.1, 1, 10, 100, 1000]
G_RELATIVOS = [1e-3, 1e-2, 1e-1, 1, 10]
CONFIGS = [(c, g) for c in C_VALORES for g in G_RELATIVOS]

def desempenho_svm(X, y):
    cv = StratifiedKFold(3, shuffle=True, random_state=0)
    return np.array([cross_val_score(make_pipeline(StandardScaler(), SVC(C=c, gamma=g / X.shape[1])), X, y, cv=cv).mean() for c, g in CONFIGS])

rng = np.random.default_rng(5)
origem = []
for i in range(40):
    n = int(rng.integers(150, 500)); d = int(rng.integers(8, 40)); inf = int(rng.integers(4, min(d - 2, 12) + 1)); c = int(rng.integers(2, 5))
    X, y = make_classification(n_samples=n, n_features=d, n_informative=inf, n_redundant=int(rng.integers(0, (d - inf) // 2 + 1)),
                               n_classes=c, n_clusters_per_class=int(rng.integers(1, 3)), class_sep=float(rng.uniform(0.4, 2.0)),
                               flip_y=float(rng.uniform(0, 0.1)), random_state=1000 + i)
    origem.append(desempenho_svm(X, y))
origem = np.array(origem)

portfolio = []
for _ in range(3):                                           # escolha gulosa
    candidatos = [j for j in range(len(CONFIGS)) if j not in portfolio]
    portfolio.append(max(candidatos, key=lambda j: np.mean(np.max(origem[:, portfolio + [j]], axis=1))))
print("Portfólio (C, gamma relativo):", [CONFIGS[j] for j in portfolio])

print("\nMelhor acurácia após k tentativas, no conjunto alvo (real):")
print(f"{'alvo':8s} | portfólio: 1, 2, 3 tentativas | aleatório: 1, 3, 6 tentativas | melhor possível")
for nome, carregar in [("Iris", load_iris), ("Wine", load_wine), ("Cancer", load_breast_cancer), ("Digits", load_digits)]:
    X, y = carregar(return_X_y=True); p = desempenho_svm(X, y); r = np.random.default_rng(0)
    port = [p[portfolio[0]], p[portfolio[:2]].max(), p[portfolio].max()]
    aleat = [np.mean([p[r.choice(len(CONFIGS), k, replace=False)].max() for _ in range(500)]) for k in (1, 3, 6)]
    print(f"{nome:8s} |        {port[0]:.3f}, {port[1]:.3f}, {port[2]:.3f}      |       {aleat[0]:.3f}, {aleat[1]:.3f}, {aleat[2]:.3f}      |      {p.max():.3f}")
```

![f9_warmstart](Figura 9.5 — Com o warm start, as primeiras tentativas já chegam perto do melhor resultado; o sorteio aleatório precisa de mais tentativas.)

Aqui o ganho é **claro**: com apenas **3 configurações do portfólio**, chega-se perto do melhor valor possível em todos os conjuntos reais. O sorteio aleatório de 3 configurações fica visivelmente atrás, e mesmo com 6 tentativas ele só alcança, no melhor caso, o que o portfólio já tinha com 3. O benefício é maior no **começo** da busca, quando cada tentativa vale mais.

É essa ideia, e não a recomendação do algoritmo, que está no coração do Auto-sklearn. A segunda geração do sistema levou a ideia adiante, com um portfólio construído **sem meta-atributos**, e uma estratégia de alocação de orçamento inspirada nos métodos de bandidos do Capítulo 6 (Feurer *et al.*, 2022).

:::dica Dica
No Optuna, você pode dar um *warm start* com `study.enqueue_trial({...})`, que coloca configurações conhecidas na fila das primeiras tentativas, antes do amostrador começar a trabalhar.
:::

## 9.6 Ensembles: a sabedoria das multidões

Mudamos agora de assunto, para uma ideia independente e muito poderosa: em vez de escolher **um** modelo, **combinar vários**.

**Analogia:** o concurso do "boi gordo" de uma feira. Cada visitante chuta o peso do animal. Individualmente, os chutes erram bastante. Mas a **média** dos chutes costuma ficar muito próxima do peso verdadeiro, porque os erros de uns compensam os erros de outros.

Com modelos acontece o mesmo, **desde que eles errem de maneiras diferentes**, isto é, tenham **diversidade**.

![f9_diversidade](Figura 9.6 — Três modelos desenham fronteiras diferentes e erram em lugares diferentes. A votação combina os três e fica à frente de cada um.)

Os principais tipos de combinação são:

- **Bagging e florestas:** treinam muitos modelos do mesmo tipo com amostras diferentes e fazem a média ou votação (Breiman, 2001).
- **Boosting:** treina modelos em sequência, cada um corrigindo os erros dos anteriores (Friedman, 2001).
- **Votação:** combina modelos **de tipos diferentes** por média das probabilidades ou por maioria.
- **Stacking:** um **meta-modelo** aprende a melhor forma de combinar os outros (Wolpert, 1992).

![f9_stacking](Figura 9.7 — No stacking, um meta-modelo aprende a combinar as previsões dos modelos de base.)

No *stacking*, as previsões usadas para treinar o meta-modelo devem ser feitas **fora do treino** (por validação cruzada). Caso contrário, o meta-modelo confiaria demais em modelos que apenas decoraram os dados.

Para ver o efeito de verdade, precisamos de um problema em que os modelos **discordem**. O conjunto Digits é fácil demais: o melhor modelo sozinho já acerta 98,7%. Vamos usar um problema **simulado e difícil**: 2.000 exemplos, 3 classes, 20 atributos e 8% de ruído nos rótulos.

```python
#@nb
#@saida
from sklearn.ensemble import VotingClassifier, StackingClassifier

X, y = make_classification(n_samples=2000, n_features=20, n_informative=8, n_redundant=4, n_classes=3,
                           n_clusters_per_class=3, class_sep=0.9, flip_y=0.08, random_state=1)
Xa, Xte, ya, yte = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)      # Xte: teste final

base = [("svm", SVC(C=10, gamma=0.02, probability=True, random_state=0)),
        ("knn", KNeighborsClassifier(5, weights="distance")),
        ("lr", LogisticRegression(C=1, max_iter=2000)),
        ("rf", RandomForestClassifier(100, random_state=0, n_jobs=-1))]
cv = StratifiedKFold(5, shuffle=True, random_state=0)

print("Validação cruzada (5 partes) no conjunto de treino:")
for nome, modelo in base:
    print(f"  {nome:20s} acurácia = {cross_val_score(modelo, Xa, ya, cv=cv).mean():.3f}")
print(f"  {'votação (soft)':20s} acurácia = {cross_val_score(VotingClassifier(base, voting='soft'), Xa, ya, cv=cv).mean():.3f}")
print(f"  {'stacking':20s} acurácia = {cross_val_score(StackingClassifier(base, final_estimator=LogisticRegression(max_iter=2000), cv=5), Xa, ya, cv=cv).mean():.3f}")
```

A votação e o *stacking* ficam **acima do melhor modelo individual**, e o *stacking* vai um pouco mais longe. Note que a regressão logística, sozinha, é fraca (esse problema tem fronteiras não lineares), mas o *stacking* a aproveita onde ela ajuda.

## 9.7 Seleção de ensembles (Caruana)

E se tivermos **dezenas de modelos** já treinados, por exemplo, todos os testados durante a busca de hiperparâmetros? Em vez de jogar fora os "perdedores", podemos usá-los. Foi o que propuseram Caruana e colaboradores (2004): construir um ensemble a partir de uma **biblioteca de modelos**, por **seleção gulosa para frente**.

O algoritmo é simples:

1. Comece com um ensemble vazio.
2. Em cada passo, **acrescente o modelo da biblioteca que mais melhora** o ensemble nos dados de **validação** (a mesma pode ser escolhida **mais de uma vez**: isso funciona como um peso maior).
3. Repita até um número máximo de passos. As contagens finais viram os pesos.

Vamos implementá-lo. A biblioteca terá 40 modelos de cinco tipos, com hiperparâmetros sorteados (como numa busca aleatória). Dividimos os dados de treino em treino e **validação** (a validação serve para escolher o ensemble), e deixamos o **teste final** intocado.

```python
#@nb
#@saida
Xtr, Xva, ytr, yva = train_test_split(Xa, ya, test_size=0.33, stratify=ya, random_state=0)
rng = np.random.default_rng(0)
biblioteca = []
for i in range(40):
    tipo = str(rng.choice(["svm", "knn", "lr", "rf", "hgb"]))
    if tipo == "svm":   m = SVC(C=10 ** rng.uniform(-1, 3), gamma=10 ** rng.uniform(-4, -0.5), probability=True, random_state=0)
    elif tipo == "knn": m = KNeighborsClassifier(int(rng.integers(1, 25)), weights="distance")
    elif tipo == "lr":  m = LogisticRegression(C=10 ** rng.uniform(-3, 2), max_iter=2000)
    elif tipo == "rf":  m = RandomForestClassifier(int(rng.integers(20, 120)), max_depth=int(rng.integers(3, 20)), random_state=0, n_jobs=-1)
    else:               m = HistGradientBoostingClassifier(learning_rate=10 ** rng.uniform(-1.7, -0.3), max_iter=60, max_leaf_nodes=int(rng.integers(4, 30)), random_state=0)
    m.fit(Xtr, ytr)
    biblioteca.append((tipo, m.predict_proba(Xva), m.predict_proba(Xte)))

nota_val = [accuracy_score(yva, pv.argmax(1)) for _, pv, _ in biblioteca]
nota_teste = [accuracy_score(yte, pt.argmax(1)) for _, _, pt in biblioteca]
melhor = int(np.argmax(nota_val))

# Seleção gulosa para frente, com reposição, minimizando a perda logarítmica na validação
escolhidos, atual = [], None
for passo in range(25):
    melhor_j, melhor_perda = None, np.inf
    for j, (_, pv, _) in enumerate(biblioteca):
        candidato = pv if not escolhidos else (atual * len(escolhidos) + pv) / (len(escolhidos) + 1)
        perda = log_loss(yva, candidato, labels=range(3))
        if perda < melhor_perda: melhor_j, melhor_perda = j, perda
    atual = biblioteca[melhor_j][1] if not escolhidos else (atual * len(escolhidos) + biblioteca[melhor_j][1]) / (len(escolhidos) + 1)
    escolhidos.append(melhor_j)

pesos = np.bincount(escolhidos, minlength=len(biblioteca))
ensemble_teste = sum(pesos[j] * biblioteca[j][2] for j in range(len(biblioteca))) / pesos.sum()
media_todos = sum(pt for _, _, pt in biblioteca) / len(biblioteca)

print(f"Melhor modelo escolhido pela validação ({biblioteca[melhor][0]}): validação = {nota_val[melhor]:.3f} | TESTE = {nota_teste[melhor]:.3f}")
print(f"Média simples dos 40 modelos                        : TESTE = {accuracy_score(yte, media_todos.argmax(1)):.3f}")
print(f"Ensemble de Caruana ({(pesos > 0).sum()} modelos diferentes)        : TESTE = {accuracy_score(yte, ensemble_teste.argmax(1)):.3f}")
print(f"(Melhor modelo individual no teste, com informação do futuro: {max(nota_teste):.3f})")
print("Modelos mais usados:", [(biblioteca[j][0], int(pesos[j])) for j in np.argsort(-pesos)[:5] if pesos[j] > 0])
```

![f9_caruana](Figura 9.8 — À esquerda, os 40 modelos da biblioteca (cores = tipo) e a linha do ensemble. À direita, a comparação no teste final.)

O resultado é instrutivo. O ensemble (0,738) supera o **melhor modelo escolhido pela validação** (0,684) e fica um pouco acima da **simples média de todos os modelos** (0,730). Ele apenas **empata** com o melhor modelo individual no teste (0,738), mas esse "campeão" só seria conhecido olhando o futuro: na prática, ninguém consegue escolhê-lo. Ou seja, o ensemble não vence o oráculo; ele nos protege de escolher mal. Grande parte do ganho vem da própria diversidade (a média simples já chega perto), e a seleção gulosa acrescenta um pouco, ao dar mais peso a modelos bons e diferentes entre si.

:::atencao Atenção
A seleção de ensemble usa os dados de validação para escolher os pesos. Como vimos no Capítulo 4, isso também pode causar sobreajuste à validação. Por isso mantemos o **teste final intocado** e relatamos a nota nele.
:::

## 9.8 O Auto-sklearn: tudo junto

Agora podemos entender o **Auto-sklearn** (Feurer *et al.*, 2015), um dos sistemas mais influentes da área. Ele combina três ideias:

![f9_autosklearn](Figura 9.9 — A arquitetura do Auto-sklearn: meta-aprendizado, otimização bayesiana e construção de ensembles.)

1. **Meta-aprendizado para o *warm start*:** usa o desempenho em conjuntos de dados anteriores para começar a busca por configurações promissoras.
2. **Otimização bayesiana** sobre um grande espaço de busca (15 classificadores, 14 métodos de pré-processamento de atributos e 4 de pré-processamento de dados, com 110 hiperparâmetros) (Feurer *et al.*, 2015).
3. **Construção automática de ensembles** a partir dos modelos avaliados durante a otimização, no espírito da seleção de Caruana.

Os autores relatam que o sistema superou de forma substancial o estado da arte da época em mais de 100 conjuntos de dados (Feurer *et al.*, 2015). Na versão 2.0, o foco foi um sistema "sem configuração manual", com meta-aprendizado **sem meta-atributos** e uma estratégia de bandidos para alocar o orçamento; em 39 conjuntos de um *benchmark* aberto, os autores reportam redução de erro relativo de até 4,5 vezes em relação a outras ferramentas e à versão anterior, e desempenho em 10 minutos equivalente ao que a versão 1.0 obtinha em 1 hora (Feurer *et al.*, 2022).

:::atencao Atenção
O Auto-sklearn não pôde ser instalado no ambiente em que este livro foi preparado, por isso **não há código executado** dele aqui. No Capítulo 10, você verá uma visão de conjunto das ferramentas e o código de uso, com os devidos avisos.
:::

Observe o que todos os ingredientes têm em comum com o que aprendemos: busca bayesiana (Capítulo 5), orçamento por bandidos (Capítulo 6), pipelines (Capítulo 3), validação honesta (Capítulos 2 e 4). O AutoML é uma **orquestra** dessas ideias.

## 9.9 Boas práticas

1. **Use o warm start** quando houver configurações conhecidas que funcionam em problemas parecidos (inclusive as suas, de projetos anteriores).
2. **Seja cético com a recomendação de algoritmos:** o ganho sobre "SVM ou floresta" costuma ser pequeno sem um meta-conjunto grande.
3. **Procure diversidade** ao montar ensembles: modelos de tipos diferentes e hiperparâmetros variados.
4. **Teste a média simples** antes de métodos sofisticados de combinação: ela costuma capturar boa parte do ganho.
5. **Escolha os pesos do ensemble na validação e meça no teste final.**
6. **Considere o custo:** um ensemble de 30 modelos custa 30 vezes mais em memória e tempo de previsão. Em produção, isso pesa (Capítulo 14).
7. **Perda de interpretabilidade:** um ensemble é mais difícil de explicar do que um modelo simples (Capítulo 13).

## Resumo do capítulo

:::memorize Cartões de memorização
- **Meta-aprendizado:** usar a experiência de problemas anteriores (conjuntos, modelos, resultados).
- **Quadro de Rice:** problemas → meta-atributos → meta-modelo → algoritmo → desempenho.
- **Meta-atributos:** simples, teoria da informação, complexidade e landmarkers.
- **Recomendar algoritmo** é difícil: no nosso experimento, ficou no nível da regra "sempre o mais frequente".
- **Warm start** (portfólio de configurações): ganho claro nas primeiras tentativas.
- **Ensembles:** combinar modelos diversos; votação, stacking e seleção gulosa de Caruana.
- **Média simples** captura boa parte do ganho; a seleção acrescenta um pouco.
- **Auto-sklearn:** meta-aprendizado + otimização bayesiana + ensemble.
:::
