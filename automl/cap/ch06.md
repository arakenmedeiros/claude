## 6.1 A peneira de talentos

Pense em uma **peneira** de um clube de futebol. Chegam 270 jovens. O clube não pode treinar todos por um ano inteiro. O que faz?

1. Dá **um treino curto** para todos e dispensa os que se mostram fracos.
2. Os que ficam recebem **mais treino**, e outra rodada de cortes acontece.
3. Ao fim, poucos jogadores, os mais promissores, recebem **o treino completo**.

![f6_peneira](Figura 6.1 — A peneira de talentos. Candidatos fracos saem cedo e gastam pouco; os fortes recebem cada vez mais treino.)

Com hiperparâmetros é a mesma lógica. Nos capítulos anteriores, cada configuração era treinada **até o fim** antes de recebermos a nota. Isso é um grande desperdício: muitas configurações ruins já mostram sua fraqueza **logo no início** do treino.

Os métodos deste capítulo são chamados de **multifidelidade** (*multi-fidelity*). Eles avaliam muitos candidatos de forma **barata e aproximada** e reservam a avaliação **cara e precisa** para os mais promissores.

## 6.2 O que é fidelidade?

**Fidelidade** é o quanto uma avaliação "se parece" com a avaliação completa. Uma avaliação de **baixa fidelidade** é barata, mas aproximada. Uma de **alta fidelidade** é cara, mas precisa.

![f6_fidelidade](Figura 6.2 — Formas de criar versões baratas de uma avaliação cara: menos épocas, menos dados, menos atributos, imagens menores, menos partes na validação.)

Os exemplos mais comuns:

- **Épocas:** treinar o modelo por poucas voltas (épocas) nos dados e continuar apenas se promissor.
- **Quantidade de dados:** treinar com 10%, depois 30%, depois 100% das linhas.
- **Atributos:** testar primeiro com um subconjunto de colunas.
- **Resolução:** imagens pequenas antes das grandes.
- **Partes da validação cruzada:** começar com poucas partes.

A grande **aposta** de todos esses métodos é: **o ranking em baixa fidelidade se parece com o ranking em alta fidelidade**. Isto é, quem vai bem no começo tende a ir bem no fim. Se a aposta for falsa, o corte precoce descarta justamente os campeões. Voltaremos a esse risco na seção 6.9.

## 6.3 Successive Halving: dividir ao meio, repetidamente

O método mais simples é o ***Successive Halving*** (algo como "metades sucessivas"), que se tornou conhecido pelo trabalho de Jamieson e Talwalkar (2016). Em português, podemos chamá-lo de **corte sucessivo**. O algoritmo é:

1. Comece com *n* candidatos e um orçamento pequeno *r* (por exemplo, 1 época).
2. Treine **todos** com esse orçamento e avalie.
3. **Mantenha apenas a fração 1/η melhor** (com η = 3, a terça parte melhor).
4. **Multiplique o orçamento por η** para os que ficaram.
5. Repita até restar **um** candidato.

Veja um exemplo com n = 27, r = 1 e η = 3:

| Rodada | Candidatos | Épocas cada | Épocas gastas na rodada |
|---|---|---|---|
| 1 | 27 | 1 | 27 |
| 2 | 9 | 3 | 27 |
| 3 | 3 | 9 | 27 |
| 4 | 1 | 27 | 27 |

Dá para notar uma beleza: **cada rodada custa a mesma coisa** (27 épocas). O total é 108 épocas. Para comparar, treinar os 27 candidatos até 27 épocas cada custaria **729 épocas**, ou seja, mais de seis vezes mais.

### Implementando do zero

Vamos implementar o Successive Halving com um modelo real: o `SGDClassifier` do scikit-learn, que aprende por **gradiente descendente estocástico** (ajusta os pesos aos poucos, a cada volta pelos dados). O método `partial_fit` permite **treinar uma época por vez e retomar depois**, o que é perfeito para a multifidelidade: o recurso é o número de **épocas**.

Usaremos o conjunto **Digits** (UCI), com os pixels padronizados, e uma única separação treino/validação para simplificar. O espaço de busca tem três hiperparâmetros: `alpha` (regularização), `eta0` (passo de aprendizado, que mede o quanto os pesos mudam a cada ajuste) e `loss` (função de perda).

```python
import math
import numpy as np
from sklearn.datasets import load_digits
from sklearn.linear_model import SGDClassifier
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

def carregar_dados(semente=0):
    X, y = load_digits(return_X_y=True)
    Xtr, Xva, ytr, yva = train_test_split(X, y, test_size=0.3, stratify=y, random_state=semente)
    escala = StandardScaler().fit(Xtr)
    return escala.transform(Xtr), escala.transform(Xva), ytr, yva

class Candidato:
    """Uma configuração que pode ser treinada aos poucos (pausar e retomar)."""
    def __init__(self, rng, dados):
        self.hp = {"alpha": 10 ** rng.uniform(-8, 1), "eta0": 10 ** rng.uniform(-6, 1),
                   "loss": str(rng.choice(["hinge", "log_loss", "modified_huber"]))}
        self.modelo = SGDClassifier(loss=self.hp["loss"], alpha=self.hp["alpha"], learning_rate="constant",
                                    eta0=self.hp["eta0"], random_state=int(rng.integers(1e6)))
        self.dados, self.epocas, self.nota, self.curva = dados, 0, 0.0, []

    def treinar_ate(self, epocas):
        Xtr, Xva, ytr, yva = self.dados
        while self.epocas < epocas:
            self.modelo.partial_fit(Xtr, ytr, classes=np.arange(10))      # uma época
            self.epocas += 1
            self.nota = self.modelo.score(Xva, yva)                        # acurácia na validação
            self.curva.append(self.nota)
        return self.nota
```

Agora o algoritmo em si. Ele recebe uma lista de candidatos e aplica o corte sucessivo.

```python
def sucessivo(candidatos, r_min, eta=3, r_max=None, verbose=False):
    """Successive Halving: treina todos com r_min épocas, mantém o melhor 1/eta e multiplica o orçamento por eta."""
    r, gasto = r_min, 0
    while True:
        for c in candidatos:
            antes = c.epocas
            c.treinar_ate(int(r))
            gasto += c.epocas - antes                                      # só contamos as épocas NOVAS
        if verbose:
            print(f"  {len(candidatos):2d} candidatos com {int(r):2d} épocas | melhor acurácia = {max(c.nota for c in candidatos):.3f}")
        if len(candidatos) <= 1 or (r_max and r >= r_max):
            break
        candidatos = sorted(candidatos, key=lambda c: -c.nota)[:max(1, len(candidatos) // eta)]
        r *= eta
    return max(candidatos, key=lambda c: c.nota), gasto
```

```python
dados = carregar_dados()
rng = np.random.default_rng(0)
candidatos = [Candidato(rng, dados) for _ in range(81)]

print("Successive Halving com 81 candidatos (η = 3):")
vencedor, gasto = sucessivo(candidatos, r_min=1, eta=3, r_max=81, verbose=True)
print(f"\nÉpocas de treino gastas: {gasto}")
print(f"Treinar os 81 candidatos por 81 épocas custaria: {81 * 81}")
print(f"Vencedor: {vencedor.hp['loss']}, alpha = {vencedor.hp['alpha']:.2e}, eta0 = {vencedor.hp['eta0']:.2e}")
```
```saída
Successive Halving com 81 candidatos (η = 3):
  81 candidatos com  1 épocas | melhor acurácia = 0.948
  27 candidatos com  3 épocas | melhor acurácia = 0.961
   9 candidatos com  9 épocas | melhor acurácia = 0.969
   3 candidatos com 27 épocas | melhor acurácia = 0.969
   1 candidatos com 81 épocas | melhor acurácia = 0.956

Épocas de treino gastas: 297
Treinar os 81 candidatos por 81 épocas custaria: 6561
Vencedor: modified_huber, alpha = 1.39e-04, eta0 = 3.57e-03
```

Veja a eficiência: o vencedor emerge com 297 épocas, e não com as 6.561 que treinar todos os 81 candidatos exigiria. Cada rodada mostra menos candidatos e mais épocas, como na peneira.

Repare também em um detalhe: a melhor acurácia da última rodada (0,956) é **menor** que a de rodadas anteriores (0,969). Como o SGD com passo constante oscila de uma época para outra, a nota de um candidato **não cresce de forma regular** com o treino. Esse ruído é uma limitação real de qualquer método que decide com base em notas parciais.

## 6.4 Quando o corte precoce funciona (e quando não)

Para entender a aposta do corte precoce, observe **curvas de aprendizado reais**, isto é, como a acurácia evolui com as épocas, para 40 configurações do nosso problema.

![f6_curvas](Figura 6.3 — À esquerda, as curvas completas de 40 configurações (as 3 melhores no fim, em verde). À direita, o que um corte em 3 épocas enxerga.)

Dois fatos merecem atenção:

1. Algumas configurações são **claramente ruins desde as primeiras épocas** (curvas que ficam baixas ou que oscilam muito). Cortá-las cedo é seguro e economiza muito.
2. Entre as boas, as curvas **se cruzam**: uma configuração que começa devagar pode ultrapassar outra no fim. Um corte muito agressivo pode eliminar uma campeã "de largada lenta".

Podemos medir isso. O bloco abaixo treina as mesmas 40 configurações da figura e compara o **posto final** (1 = melhor) das três campeãs com o posto que elas tinham **após 3 épocas**.

```python
rng = np.random.default_rng(4)
dados = carregar_dados(0)
configs = [Candidato(rng, dados) for _ in range(40)]
for c in configs:
    c.treinar_ate(81)

final = np.array([c.curva[-1] for c in configs])
apos3 = np.array([c.curva[2] for c in configs])
posto_final = (-final).argsort().argsort() + 1          # 1 = melhor
posto_apos3 = (-apos3).argsort().argsort() + 1

print("As 3 melhores no final (epoch 81) e o posto delas após 3 épocas:")
for i in np.argsort(-final)[:3]:
    print(f"  configuração {i:2d}: posto final = {posto_final[i]} | posto após 3 épocas = {posto_apos3[i]:2d} de 40")
corte = len(configs) // 3
print(f"Se cortássemos para as {corte} melhores após 3 épocas, "
      f"{sum(posto_apos3[i] <= corte for i in np.argsort(-final)[:3])} das 3 campeãs sobreviveriam.")
```
```saída
As 3 melhores no final (epoch 81) e o posto delas após 3 épocas:
  configuração 30: posto final = 1 | posto após 3 épocas =  5 de 40
  configuração 14: posto final = 2 | posto após 3 épocas = 10 de 40
  configuração 35: posto final = 3 | posto após 3 épocas = 20 de 40
Se cortássemos para as 13 melhores após 3 épocas, 2 das 3 campeãs sobreviveriam.
```

Dois terços das campeãs sobreviveriam ao corte; a terceira, que estava no posto 20 de 40 após 3 épocas, seria eliminada. É o risco do corte precoce, medido, e não apenas imaginado.

É por isso que a escolha do **orçamento inicial** *r* e do fator **η** importa. Orçamentos iniciais muito pequenos cortam campeãs lentas; muito grandes perdem a economia.

## 6.5 No scikit-learn: busca com *halving*

O scikit-learn tem a ideia pronta em `HalvingGridSearchCV` e `HalvingRandomSearchCV`. Aqui, o "recurso" é, por padrão, o **número de exemplos de treino**: as primeiras rodadas usam poucos dados, e as seguintes, mais. Essas classes são marcadas como **experimentais**: é preciso habilitá-las explicitamente.

```python
import numpy as np
from sklearn.experimental import enable_halving_search_cv    # habilita as classes experimentais
from sklearn.model_selection import GridSearchCV, HalvingGridSearchCV, StratifiedKFold
from sklearn.datasets import load_digits
from sklearn.svm import SVC

X, y = load_digits(return_X_y=True); X = X / 16.0
cv = StratifiedKFold(5, shuffle=True, random_state=0)
grade = {"C": np.logspace(-1, 3, 6), "gamma": np.logspace(-5, -1, 6)}      # 36 combinações

completa = GridSearchCV(SVC(), grade, cv=cv).fit(X, y)
halving = HalvingGridSearchCV(SVC(), grade, cv=cv, factor=3, random_state=0).fit(X, y)

n_treinos = len(completa.cv_results_["params"]) * 5
custo_completa = n_treinos * int(len(X) * 0.8)
custo_halving = sum(c * r * 5 * 0.8 for c, r in zip(halving.n_candidates_, halving.n_resources_))

print(f"Grade completa : {n_treinos} treinos | melhor acurácia = {completa.best_score_:.3f}")
print(f"Halving        : candidatos por rodada {halving.n_candidates_} | exemplos por rodada {halving.n_resources_}")
print(f"                 melhor acurácia (na última rodada) = {halving.best_score_:.3f}")
print(f"Custo aproximado (exemplos processados): grade = {custo_completa:,.0f} | halving = {custo_halving:,.0f}")
print(f"Economia: {100 * (1 - custo_halving / custo_completa):.0f}%")
```
```saída
Grade completa : 180 treinos | melhor acurácia = 0.989
Halving        : candidatos por rodada [36, 12, 4] | exemplos por rodada [100, 300, 900]
                 melhor acurácia (na última rodada) = 0.987
Custo aproximado (exemplos processados): grade = 258,660 | halving = 43,200
Economia: 83%
```

A busca *halving* chega a configurações de qualidade parecida usando uma fração do custo, porque descarta cedo os candidatos fracos, quando só 'viu' poucos exemplos.

:::atencao Atenção
A nota final de uma busca *halving* vem da **última rodada**, que usa mais dados, mas só para poucos candidatos. Ela não é diretamente comparável à nota de uma grade completa. Compare modelos finais em um teste separado.
:::

## 6.6 Hyperband: não apostar tudo em um corte

O Successive Halving tem um dilema escondido. Para um orçamento total fixo, devemos testar **muitas configurações com pouco treino** (apostando que cortes precoces são confiáveis) ou **poucas configurações com muito treino** (apostando que o começo das curvas engana)? Não sabemos a resposta de antemão.

O **Hyperband** (Li *et al.*, 2018) resolve com uma ideia simples: **não escolha, faça os dois**. Ele roda **vários torneios** de Successive Halving, cada um com uma aposta diferente, do mais agressivo ao mais conservador, e fica com o melhor resultado entre todos. Os autores formularam o problema como uma busca em que um recurso (épocas, dados, atributos) é alocado a configurações sorteadas, e mostraram ganhos de velocidade em problemas com redes profundas e métodos de kernel.

![f6_brackets](Figura 6.4 — Os torneios (brackets) do Hyperband com R = 81 e η = 3. O primeiro testa 81 configurações com 1 época; o último testa 5 configurações com 81 épocas.)

Dois parâmetros definem o Hyperband:

- **R:** o máximo de recurso (épocas) que uma configuração pode receber.
- **η:** o fator de corte (mantém 1/η a cada rodada).

Cada torneio *s* começa com um número *n* de configurações e um recurso inicial *r*. Quanto maior o *s*, mais candidatos e menos treino inicial.

```python
def hyperband(rng, dados, R=81, eta=3):
    s_max = int(math.log(R) / math.log(eta) + 1e-9)
    B = (s_max + 1) * R
    melhor, gasto, n_config = None, 0, 0
    for s in range(s_max, -1, -1):
        n = int(math.ceil(B / R * eta ** s / (s + 1)))        # nº de configurações do torneio
        r = R * eta ** (-s)                                    # recurso inicial
        candidatos = [Candidato(rng, dados) for _ in range(n)]
        n_config += n
        vencedor, g = sucessivo(candidatos, r, eta, R)
        gasto += g
        if melhor is None or vencedor.nota > melhor.nota:
            melhor = vencedor
    return melhor, gasto, n_config

def busca_aleatoria(rng, dados, orcamento, R=81):
    """Linha de base: treina cada configuração até R épocas, até acabar o orçamento."""
    melhor, gasto = 0.0, 0
    while gasto + R <= orcamento:
        c = Candidato(rng, dados)
        c.treinar_ate(R)
        gasto += R
        melhor = max(melhor, c.nota)
    return melhor, gasto
```

### Uma comparação justa

Compararemos Successive Halving, Hyperband e busca aleatória com o **mesmo orçamento** (mesmo número de épocas), repetindo com 12 sementes. Isso leva alguns minutos de processamento.

```python
resultados = []
for s in range(12):
    d = carregar_dados(0)
    sh, gasto_sh = sucessivo([Candidato(np.random.default_rng(2000 + s * 1000 + i), d) for i in range(81)], 1, 3, 81)
    aleat_sh, _ = busca_aleatoria(np.random.default_rng(3000 + s), d, gasto_sh)
    hb, gasto_hb, n_cfg = hyperband(np.random.default_rng(s), d)
    aleat_hb, _ = busca_aleatoria(np.random.default_rng(1000 + s), d, gasto_hb)
    resultados.append((sh.nota, aleat_sh, hb.nota, aleat_hb, gasto_sh, gasto_hb, n_cfg))

r = np.array(resultados)
print(f"Orçamento de {int(r[0,4])} épocas:")
print(f"  Successive Halving (81 configurações): {r[:,0].mean():.3f} (±{r[:,0].std():.3f})")
print(f"  Aleatória (só {int(r[0,4] // 81)} configurações)         : {r[:,1].mean():.3f} (±{r[:,1].std():.3f})")
print(f"Orçamento de {int(r[0,5])} épocas:")
print(f"  Hyperband ({int(r[0,6])} configurações)      : {r[:,2].mean():.3f} (±{r[:,2].std():.3f})")
print(f"  Aleatória (só {int(r[0,5] // 81)} configurações)      : {r[:,3].mean():.3f} (±{r[:,3].std():.3f})")
```
```saída
Orçamento de 297 épocas:
  Successive Halving (81 configurações): 0.963 (±0.005)
  Aleatória (só 3 configurações)         : 0.955 (±0.012)
Orçamento de 1581 épocas:
  Hyperband (143 configurações)      : 0.969 (±0.002)
  Aleatória (só 19 configurações)      : 0.965 (±0.007)
```

![f6_comparacao](Figura 6.5 — Acurácia média de validação (12 sementes) para busca aleatória e métodos multifidelidade, com o mesmo orçamento de épocas. As barras de erro mostram o desvio padrão.)

O que os números mostram:

- **Successive Halving contra aleatória.** Com o mesmo orçamento de 297 épocas, o corte sucessivo avalia 81 configurações, enquanto a busca aleatória só consegue treinar 3 até o fim. O resultado: 0,963 contra 0,955, com variação bem menor entre as sementes (a aleatória oscila mais, porque três sorteios dependem muito da sorte).
- **Hyperband contra aleatória.** Com 1.581 épocas, o Hyperband explora 143 configurações; a aleatória treina 19. A diferença é menor, 0,969 contra 0,965, mas o Hyperband é muito mais **estável** (desvio padrão de cerca de 0,002 contra 0,007).

Ou seja, o ganho em **acurácia média** é **modesto** neste problema, porque o espaço tem muitas configurações boas. O benefício mais claro aparece em dois pontos: o **orçamento pequeno** (o Halving) e a **estabilidade** (menos dependência de sorte). Em problemas em que cada treino é muito caro (redes neurais profundas, por exemplo), economizar épocas pesa mais ainda.

## 6.7 BOHB: multifidelidade com inteligência

O Hyperband sorteia os candidatos **ao acaso**. Uma melhoria natural é gerar candidatos **de forma inteligente**, aproveitando o que se aprendeu. É exatamente a ideia do **BOHB** (*Bayesian Optimization and Hyperband*), de Falkner, Klein e Hutter (2018).

![f6_bohb](Figura 6.6 — O BOHB combina a organização em torneios do Hyperband com um modelo bayesiano (TPE) que sugere os candidatos.)

O BOHB:

- usa o **Hyperband** para decidir quanto orçamento cada candidato recebe e quando cortar;
- usa um modelo do tipo **TPE** (Capítulo 5) para sugerir novos candidatos, treinado com os resultados observados em cada nível de fidelidade.

Os autores reportam que o BOHB combina **bom desempenho logo no início** (o Hyperband) com **convergência rápida para boas configurações** (a otimização bayesiana), superando ambos em uma série de problemas, de máquinas de vetores de suporte a redes neurais profundas. No Capítulo 10, você verá que ferramentas de AutoML embutem ideias desse tipo.

## 6.8 Podas no Optuna

O Optuna implementa a multifidelidade por meio de **podadores** (*pruners*). A ideia é permitir que uma tentativa **seja interrompida cedo**, se estiver indo mal em comparação com as outras (Akiba *et al.*, 2019).

Dentro da função-objetivo, a cada época você faz duas coisas:

1. `trial.report(nota, epoca)`: informa a nota parcial;
2. `if trial.should_prune(): raise optuna.TrialPruned()`: pergunta ao podador se a tentativa deve parar.

Dois podadores populares são o `MedianPruner` (interrompe tentativas cuja nota parcial está abaixo da **mediana** das outras na mesma época) e o `HyperbandPruner` (aplica a lógica do Hyperband).

```python
import numpy as np
import optuna

optuna.logging.set_verbosity(optuna.logging.WARNING)
from sklearn.datasets import load_digits
from sklearn.linear_model import SGDClassifier
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

X, y = load_digits(return_X_y=True)
Xtr, Xva, ytr, yva = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)
esc = StandardScaler().fit(Xtr); Xtr, Xva = esc.transform(Xtr), esc.transform(Xva)

EPOCAS = 60
def objetivo(trial):
    modelo = SGDClassifier(loss=trial.suggest_categorical("loss", ["hinge", "log_loss", "modified_huber"]),
                           alpha=trial.suggest_float("alpha", 1e-8, 1e1, log=True),
                           eta0=trial.suggest_float("eta0", 1e-6, 1e1, log=True),
                           learning_rate="constant", random_state=0)
    for epoca in range(EPOCAS):
        modelo.partial_fit(Xtr, ytr, classes=np.arange(10))
        nota = modelo.score(Xva, yva)
        trial.report(nota, epoca)                      # nota parcial
        if trial.should_prune():                       # o podador manda parar?
            raise optuna.TrialPruned()
    return nota

for nome, podador in [("sem poda", optuna.pruners.NopPruner()), ("MedianPruner", optuna.pruners.MedianPruner(n_startup_trials=5, n_warmup_steps=3))]:
    estudo = optuna.create_study(direction="maximize", sampler=optuna.samplers.TPESampler(seed=0), pruner=podador)
    estudo.optimize(objetivo, n_trials=40)
    podadas = sum(t.state == optuna.trial.TrialState.PRUNED for t in estudo.trials)
    epocas = sum(len(t.intermediate_values) for t in estudo.trials)
    print(f"{nome:13s}: tentativas podadas = {podadas:2d}/40 | épocas treinadas = {epocas:4d} | melhor acurácia = {estudo.best_value:.3f}")
```
```saída
sem poda     : tentativas podadas =  0/40 | épocas treinadas = 2400 | melhor acurácia = 0.972
MedianPruner : tentativas podadas = 20/40 | épocas treinadas = 1297 | melhor acurácia = 0.969
```

O `MedianPruner` interrompe parte das tentativas, **economizando épocas** e chegando a uma nota parecida. Em tarefas caras (como redes neurais profundas), essa economia vira horas ou dias.

## 6.9 Armadilhas e boas práticas

1. **O ranking pode mudar.** Candidatos de "largada lenta" podem ser eliminados cedo. Use um orçamento inicial razoável e, se possível, um fator η menor (como 2) para cortes mais suaves.
2. **Fidelidade baixa demais não discrimina.** Se com 1 época todos parecem iguais, o corte é um sorteio.
3. **A fidelidade precisa ser monotônica o bastante.** Mais recurso deve, em geral, dar uma estimativa melhor. Verifique isso nas curvas de aprendizado.
4. **Não compare notas de fidelidades diferentes.** Compare apenas candidatos avaliados com o mesmo orçamento.
5. **Compare sempre com a busca aleatória** no mesmo orçamento, como fizemos. O ganho depende do problema.
6. **Guarde o estado do modelo** (checkpoints) para retomar o treino sem recomeçar, como o `partial_fit` permite.
7. **Avalie o vencedor em um teste final** treinado com orçamento completo.

## Resumo do capítulo

:::memorize Cartões de memorização
- **Multifidelidade:** avaliar muitos candidatos barato e os promissores caro.
- **Fidelidade:** épocas, dados, atributos, resolução ou partes da validação.
- **Aposta central:** o ranking em baixa fidelidade se parece com o de alta.
- **Successive Halving:** treina todos pouco, mantém 1/η melhor, multiplica o orçamento por η.
- **Hyperband:** vários torneios com apostas diferentes; não depende de escolher o corte certo.
- **BOHB:** Hyperband + TPE (candidatos inteligentes).
- **Podadores (Optuna):** `report` e `should_prune` interrompem tentativas ruins.
- **Risco:** curvas que se cruzam fazem o corte precoce eliminar campeãs lentas.
:::
