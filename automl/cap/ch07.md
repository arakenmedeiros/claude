## 7.1 A natureza como otimizadora

Durante milhares de anos, agricultores e criadores melhoraram plantas e animais sem saber nada de genética. O método era simples. A cada safra, eles **escolhiam as melhores plantas**, usavam suas sementes para a safra seguinte e, de vez em quando, uma variação inesperada aparecia e, se fosse boa, era preservada. Geração após geração, o milho ficou mais produtivo, e os cães, mais adequados a cada tarefa.

Esse processo tem três ingredientes:

1. **Variação:** os indivíduos são diferentes entre si.
2. **Seleção:** os melhores têm mais chance de deixar descendentes.
3. **Hereditariedade:** os filhos se parecem com os pais, e misturam características deles.

É a lógica da **evolução**. E ela funciona como **método de busca**: quando um problema tem muitas soluções possíveis e não sabemos a fórmula do melhor ponto, podemos **simular a evolução** em um computador. Os métodos baseados nessa ideia são chamados de **computação evolutiva**.

![f7_natureza](Figura 7.1 — Uma simulação real: uma população de soluções (pontos) evolui e se concentra nas regiões de maior aptidão (verde mais escuro).)

Na figura acima, cada ponto é uma solução candidata em uma "paisagem" com dois morros. Aos poucos, a população deixa de se espalhar e passa a se concentrar nas regiões mais altas.

## 7.2 O vocabulário dos algoritmos genéticos

Os **algoritmos genéticos** (GA, de *genetic algorithms*) usam termos emprestados da biologia. Vamos traduzi-los para o nosso problema, que é montar um **pipeline de aprendizado de máquina**.

| Termo | Significado em biologia | Significado para nós |
|---|---|---|
| **Indivíduo** | Um organismo | Um pipeline completo (escala, redução, modelo e hiperparâmetros) |
| **Genoma** | O DNA | A descrição do pipeline: lista de escolhas |
| **Gene** | Um trecho do DNA | Uma escolha (tipo de escala, valor de C...) |
| **População** | O conjunto dos organismos | Um grupo de pipelines (por exemplo, 14) |
| **Aptidão** (*fitness*) | Quão bem o organismo sobrevive | A nota de validação cruzada do pipeline |
| **Geração** | Um ciclo de reprodução | Uma rodada de seleção, cruzamento e mutação |
| **Seleção** | Os mais aptos reproduzem mais | Os pipelines de maior nota têm mais chance de ser "pais" |
| **Cruzamento** | Mistura de genes de dois pais | Combinar escolhas de dois pipelines |
| **Mutação** | Alteração aleatória de um gene | Mudar uma escolha ao acaso |
| **Elitismo** | — | Copiar os melhores direto para a próxima geração |

O ciclo de um algoritmo genético é este:

![f7_ciclo](Figura 7.2 — O ciclo do algoritmo genético. A cada geração, a população é avaliada, os melhores são selecionados, e filhos são criados por cruzamento e mutação.)

Os dois operadores de variação merecem um olhar mais atento.

![f7_operadores](Figura 7.3 — O cruzamento combina genes de dois pais; a mutação altera um gene ao acaso.)

- O **cruzamento** combina boas ideias: se o Pai A tem uma boa escala e o Pai B um bom modelo, o filho pode herdar as duas coisas.
- A **mutação** introduz novidade: sem ela, a população perderia diversidade e ficaria presa em um tipo de solução.

:::memorize Memorize
**Seleção** concentra a busca nas boas soluções (aproveitar). **Mutação** mantém a diversidade (explorar). O mesmo dilema do Capítulo 5, resolvido com a ideia da evolução.
:::

## 7.3 Um algoritmo genético do zero

Vamos construir um GA que **evolui pipelines** de classificação. É uma versão minúscula do que o TPOT faz, mas com todas as peças.

**O problema.** Para tornar a busca mais interessante, usaremos um conjunto **difícil de propósito**: 300 imagens do conjunto **Digits** (UCI), às quais acrescentamos **200 colunas de ruído** (números aleatórios sem informação). Assim, a escolha de escala e de redução de dimensionalidade realmente importa.

**O genoma.** Cada indivíduo é um dicionário com: o tipo de **escala** (nenhuma, padrão ou min-máx), o número de componentes do **PCA** (0 = sem PCA), o **modelo** (k-vizinhos, SVM, regressão logística ou floresta) e os hiperparâmetros do modelo escolhido.

```python
import copy
import numpy as np
from sklearn.datasets import load_digits
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler, MinMaxScaler
from sklearn.decomposition import PCA
from sklearn.neighbors import KNeighborsClassifier
from sklearn.svm import SVC
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import cross_val_score, StratifiedKFold

# Dados: 300 imagens de Digits + 200 colunas de ruído
X0, y0 = load_digits(return_X_y=True)
X0 = X0 / 16.0
rng_dados = np.random.default_rng(0)
idx = rng_dados.choice(len(y0), 300, replace=False)
X = np.hstack([X0[idx], rng_dados.normal(size=(300, 200))])
y = y0[idx]
print("Formato dos dados:", X.shape, "(64 colunas úteis + 200 de ruído)")

def sortear_modelo(rng, modelo):
    """Sorteia os hiperparâmetros do modelo escolhido."""
    if modelo == "knn":       return {"k": int(rng.integers(1, 30))}
    if modelo == "svm":       return {"C": float(10 ** rng.uniform(-2, 3)), "gamma": float(10 ** rng.uniform(-5, 0))}
    if modelo == "logistica": return {"C": float(10 ** rng.uniform(-3, 3))}
    return {"arvores": int(rng.integers(20, 150)), "prof": int(rng.integers(3, 20))}

def sortear_individuo(rng):
    g = {"escala": str(rng.choice(["nenhuma", "padrao", "minmax"])),
         "pca": int(rng.choice([0, 0, 10, 20, 30, 40])),
         "modelo": str(rng.choice(["knn", "svm", "logistica", "floresta"]))}
    g.update(sortear_modelo(rng, g["modelo"]))
    return g
```

Agora transformamos o genoma em um pipeline do scikit-learn e definimos a **aptidão**: a nota de validação cruzada. Guardamos as notas já calculadas em um dicionário (*cache*), para não avaliar duas vezes o mesmo pipeline.

```python
def construir(g):
    """Traduz o genoma em um pipeline do scikit-learn."""
    passos = []
    if g["escala"] == "padrao": passos.append(StandardScaler())
    if g["escala"] == "minmax": passos.append(MinMaxScaler())
    if g["pca"] > 0:            passos.append(PCA(g["pca"], random_state=0))
    m = g["modelo"]
    if m == "knn":        passos.append(KNeighborsClassifier(g["k"]))
    elif m == "svm":      passos.append(SVC(C=g["C"], gamma=g["gamma"]))
    elif m == "logistica": passos.append(LogisticRegression(C=g["C"], max_iter=300))
    else:                 passos.append(RandomForestClassifier(g["arvores"], max_depth=g["prof"], random_state=0, n_jobs=-1))
    return make_pipeline(*passos)

def aptidao(g, X, y, cache):
    chave = str(sorted(g.items()))
    if chave not in cache:
        cache[chave] = float(cross_val_score(construir(g), X, y, cv=StratifiedKFold(3, shuffle=True, random_state=0)).mean())
    return cache[chave]
```

Os **operadores genéticos** são o cruzamento (mistura de dois pais) e a mutação (mudanças aleatórias).

```python
def cruzar(a, b, rng):
    filho = {}
    for k in ("escala", "pca"):                                 # cada gene vem de um dos pais
        filho[k] = a[k] if rng.random() < 0.5 else b[k]
    pai = a if rng.random() < 0.5 else b                        # o modelo (com seus hiperparâmetros) vem de um pai
    filho["modelo"] = pai["modelo"]
    filho.update({k: v for k, v in pai.items() if k not in ("escala", "pca", "modelo")})
    return filho

def mutar(g, rng, p=0.3):
    g = copy.deepcopy(g)
    if rng.random() < p: g["escala"] = str(rng.choice(["nenhuma", "padrao", "minmax"]))
    if rng.random() < p: g["pca"] = int(rng.choice([0, 0, 10, 20, 30, 40]))
    if rng.random() < p * 0.7:                                  # às vezes troca o modelo inteiro
        g["modelo"] = str(rng.choice(["knn", "svm", "logistica", "floresta"]))
        for k in [k for k in g if k not in ("escala", "pca", "modelo")]: del g[k]
        g.update(sortear_modelo(rng, g["modelo"]))
    else:                                                       # ou ajusta levemente os hiperparâmetros
        for k, v in list(g.items()):
            if k in ("escala", "pca", "modelo") or rng.random() >= 0.6: continue
            if k in ("C", "gamma"): g[k] = float(np.clip(v * 10 ** rng.normal(0, 0.4), 1e-5 if k == "gamma" else 1e-3, 1 if k == "gamma" else 1e3))
            elif k == "k":          g[k] = int(np.clip(v + rng.integers(-3, 4), 1, 40))
            elif k == "arvores":    g[k] = int(np.clip(v + rng.integers(-20, 21), 10, 200))
            elif k == "prof":       g[k] = int(np.clip(v + rng.integers(-3, 4), 2, 25))
    return g
```

Por fim, o laço evolutivo. A **seleção por torneio** sorteia 3 indivíduos e escolhe o melhor deles: os bons têm mais chance, mas os fracos ainda podem ser pais. O **elitismo** copia os 2 melhores direto para a geração seguinte.

```python
def evoluir(X, y, semente, pop=14, geracoes=5, elite=2):
    rng = np.random.default_rng(semente)
    cache, populacao, historico, todos = {}, [sortear_individuo(rng) for _ in range(pop)], [], []
    for ger in range(geracoes + 1):
        notas = np.array([aptidao(g, X, y, cache) for g in populacao])
        todos += list(zip(populacao, notas))
        historico.append((len(cache), float(notas.max()), float(notas.mean())))
        if ger == geracoes:
            break
        ordem = np.argsort(-notas)
        nova = [copy.deepcopy(populacao[i]) for i in ordem[:elite]]                 # elitismo
        torneio = lambda: populacao[max(rng.choice(pop, 3, replace=False), key=lambda i: notas[i])]
        while len(nova) < pop:
            nova.append(mutar(cruzar(torneio(), torneio(), rng), rng))
        populacao = nova
    return historico, todos

historico, todos = evoluir(X, y, semente=0)
```

```python
print("geração | pipelines avaliados | melhor nota | nota média da população")
for ger, (n, melhor, media) in enumerate(historico):
    print(f"{ger:7d} | {n:19d} | {melhor:11.3f} | {media:.3f}")
```
```saída
geração | pipelines avaliados | melhor nota | nota média da população
      0 |                  14 |       0.900 | 0.624
      1 |                  24 |       0.930 | 0.832
      2 |                  36 |       0.930 | 0.740
      3 |                  47 |       0.930 | 0.697
      4 |                  57 |       0.937 | 0.750
      5 |                  68 |       0.937 | 0.727
```

Observe duas coisas. A **melhor nota** sobe aos poucos (de 0,900 para 0,937) e, depois, estaciona. A **nota média da população** dá um salto logo na primeira geração (de 0,62 para 0,83), pois os piores pipelines são substituídos, e depois **oscila** entre 0,70 e 0,75. Esse é o efeito da seleção: a população inteira melhora logo de início, e não apenas o campeão. A oscilação posterior vem das mutações, como veremos abaixo.

:::atencao Atenção
A nota média pode oscilar entre gerações, pois a mutação cria filhos ruins. Isso é normal e até desejável: a mutação é a "pesquisa" do algoritmo. Por isso o elitismo preserva os melhores.
:::

## 7.4 Evolução contra busca aleatória

Resta a pergunta de sempre: **vale a pena?** Vamos comparar o algoritmo genético com a busca aleatória, dando a **ambos o mesmo número de pipelines avaliados**, em 5 sementes diferentes. Isso leva alguns minutos de processamento.

```python
def busca_aleatoria(X, y, semente, n_avaliacoes):
    rng = np.random.default_rng(10_000 + semente)
    cache, melhor = {}, 0.0
    for _ in range(n_avaliacoes):
        melhor = max(melhor, aptidao(sortear_individuo(rng), X, y, cache))
    return melhor

ga, al = [], []
for s in range(5):
    hist, _ = evoluir(X, y, semente=s)
    n_aval = hist[-1][0]
    ga.append(hist[-1][1]); al.append(busca_aleatoria(X, y, s, n_aval))
    print(f"semente {s}: {n_aval} pipelines avaliados | genético = {ga[-1]:.3f} | aleatória = {al[-1]:.3f}")

print(f"\nMédia: genético = {np.mean(ga):.3f} | aleatória = {np.mean(al):.3f}")
print(f"O genético venceu em {sum(g > a for g, a in zip(ga, al))} de 5 sementes (empates: {sum(g == a for g, a in zip(ga, al))}).")
```

Neste problema difícil, o algoritmo genético termina **à frente em média**, e vence em 4 das 5 sementes. Mas note a diferença modesta e a variação entre sementes: com apenas 5 repetições, não dá para dizer que ele é superior em geral. O que há de mais robusto é a **tendência**: o GA reaproveita boas combinações (cruzamento) e testa variações próximas delas (mutação), enquanto a aleatória nunca "aprende" com o que viu.

## 7.5 Programação genética e pipelines em árvore

O nosso genoma era uma **lista fixa** de escolhas. Mas um pipeline real pode ter formas muito variadas: duas etapas de pré-processamento, ou cinco; seleção de atributos antes ou depois; vários modelos empilhados. Uma lista fixa não representa isso bem.

A **programação genética** (GP) resolve isso representando cada solução como uma **árvore**. Cada **nó** é uma operação, e os filhos de um nó são as entradas dela.

![f7_arvore](Figura 7.5 — Pipelines como árvores. O cruzamento troca subárvores inteiras; a mutação substitui nós ou ramos.)

Nesse formato:

- O **cruzamento** escolhe um ramo de cada pai e **troca as subárvores**. Pedaços inteiros do tratamento dos dados mudam de dono.
- A **mutação** pode trocar o tipo de um nó, mudar um hiperparâmetro, inserir ou remover um nó.
- Pipelines de **tamanhos e formas diferentes** convivem na mesma população.

Foi exatamente essa a ideia do **TPOT** (*Tree-based Pipeline Optimization Tool*). Olson e colaboradores (2016) implementaram, em Python, uma ferramenta que usa programação genética para evoluir pipelines do scikit-learn, incluindo pré-processadores, seletores de atributos e modelos (Olson *et al.*, 2016; Olson; Moore, 2016). No trabalho apresentado na oficina de AutoML do ICML, a ferramenta foi avaliada em 150 tarefas de classificação supervisionada (Olson; Moore, 2016).

## 7.6 Dois objetivos ao mesmo tempo

Há um problema clássico em programação genética: a evolução tende a produzir pipelines **cada vez maiores e mais complicados**, porque acrescentar etapas costuma aumentar levemente a nota. Mas um pipeline complicado é difícil de explicar, lento e arriscado.

A solução natural é pedir **dois objetivos** ao mesmo tempo: **maximizar a acurácia** e **minimizar a complexidade**. É a **otimização multiobjetivo**.

Com dois objetivos, geralmente não existe um "melhor" absoluto. Um pipeline pode ser mais preciso, mas mais complexo; outro, mais simples, mas um pouco menos preciso. Dizemos que um pipeline **domina** outro quando é **melhor ou igual em ambos os objetivos e estritamente melhor em pelo menos um**. O conjunto dos pipelines que **ninguém domina** é a **fronteira de Pareto**: são as melhores concessões possíveis entre os dois objetivos.

**Analogia:** você quer um carro rápido e econômico. Nenhum carro é o melhor nos dois. Mas há uma "fronteira" de carros em que, para ganhar em um aspecto, você precisa perder no outro. Os carros que estão fora da fronteira são sempre piores que algum carro dentro dela.

O algoritmo **NSGA-II** (Deb *et al.*, 2002) é um algoritmo genético multiobjetivo muito usado. Ele introduz uma forma rápida de ordenar os indivíduos em camadas de dominância (a "ordenação rápida por não dominância") e valoriza a diversidade ao longo da fronteira. Uma variante do TPOT usa a seleção do NSGA-II para tratar o número de operadores do pipeline como segundo objetivo, produzindo pipelines compactos sem sacrificar a acurácia (Olson *et al.*, 2016).

Vamos calcular uma fronteira de Pareto de verdade. Reaproveitamos todos os pipelines avaliados pelo nosso GA (semente 0) e tomamos como segundo objetivo o **número de atributos usados pelo modelo**: o PCA reduz de 264 colunas para 10 a 40 componentes, e uma floresta ou SVM sem PCA usa todas as 264.

```python
import numpy as np

# Cada indivíduo avaliado: (genoma, nota). Objetivo 1: nota (maximizar). Objetivo 2: nº de atributos (minimizar).
avaliados = {}
for g, nota in todos:
    avaliados[str(sorted(g.items()))] = (g, float(nota))
pontos = [(g["pca"] if g["pca"] > 0 else X.shape[1], nota, g) for g, nota in avaliados.values()]

def domina(a, b):
    """a domina b: não é pior em nenhum objetivo e é melhor em pelo menos um."""
    return a[0] <= b[0] and a[1] >= b[1] and (a[0] < b[0] or a[1] > b[1])

fronteira = [p for p in pontos if not any(domina(q, p) for q in pontos)]
fronteira.sort(key=lambda p: p[0])
print(f"Pipelines distintos avaliados: {len(pontos)} | na fronteira de Pareto: {len(fronteira)}")
print("\natributos | acurácia | pipeline")
for n_atr, nota, g in fronteira:
    ajustes = {k: round(v, 3) if isinstance(v, float) else v for k, v in g.items() if k not in ("escala", "pca", "modelo")}
    descricao = f"escala={g['escala']}, PCA={g['pca']}, {g['modelo']} {ajustes}"
    print(f"{n_atr:9d} | {nota:8.3f} | {descricao}")
```
```saída

atributos | acurácia | pipeline
       10 |    0.903 | escala=minmax, PCA=10, svm {'C': 725.389, 'gamma': 0.031}
       20 |    0.930 | escala=minmax, PCA=20, svm {'C': 1000.0, 'gamma': 0.027}
       30 |    0.937 | escala=minmax, PCA=30, svm {'C': 327.15, 'gamma': 0.042}
       30 |    0.937 | escala=minmax, PCA=30, svm {'C': 327.15, 'gamma': 0.046}
```

![f7_pareto](Figura 7.6 — A fronteira de Pareto (em vermelho) mostra as melhores concessões entre acurácia e simplicidade. Pontos cinza estão dominados.)

A fronteira dá **opções** a quem decide: o pipeline mais preciso, o mais enxuto e algumas concessões no meio. Uma pessoa pode escolher o ponto que melhor equilibra acerto e simplicidade para o seu contexto. Essa é a vantagem dos métodos multiobjetivo: em vez de esconder a decisão em uma média, eles **mostram o dilema**.

## 7.7 O TPOT na prática

O TPOT usa exatamente a estrutura que estudamos: população de pipelines em árvore, avaliação por validação cruzada, seleção multiobjetivo, cruzamento e mutação. Ao terminar, ele **exporta o melhor pipeline como código Python do scikit-learn**, que você pode ler, editar e reutilizar. Isso é um grande ponto a favor da transparência.

![f7_tpot](Figura 7.7 — O fluxo do TPOT: de uma população de pipelines evoluída por validação cruzada e seleção multiobjetivo até o código Python do melhor pipeline.)

:::atencao Atenção
O código abaixo **não foi executado** durante a elaboração deste livro: não foi possível instalar o TPOT no ambiente em que o livro foi preparado. Ele mostra a estrutura de uso no estilo da versão clássica da biblioteca. As interfaces de bibliotecas de AutoML mudam entre versões; consulte a documentação atual do TPOT antes de usar e adapte os nomes dos argumentos.
:::

```python
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from tpot import TPOTClassifier

X, y = load_digits(return_X_y=True)
X_treino, X_teste, y_treino, y_teste = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)

tpot = TPOTClassifier(generations=5,        # nº de gerações
                      population_size=20,   # nº de pipelines por geração
                      cv=5,                 # validação cruzada
                      random_state=0,
                      n_jobs=-1,
                      verbosity=2)
tpot.fit(X_treino, y_treino)                # evolui os pipelines (pode levar de minutos a horas)
print("Acurácia no teste:", tpot.score(X_teste, y_teste))
tpot.export("melhor_pipeline.py")           # grava o código Python do melhor pipeline
```

Mesmo sem executá-lo, você já sabe o que acontece dentro dele, porque construímos uma versão minúscula do mesmo mecanismo na Seção 7.3.

## 7.8 Vantagens e limites dos métodos evolutivos

**Vantagens:**

- **Flexibilidade.** Lidam com espaços de busca estranhos: estruturas variáveis, categorias, condicionais, objetivos múltiplos.
- **Paralelismo natural.** Os indivíduos de uma geração podem ser avaliados ao mesmo tempo.
- **Diversidade.** Uma população mantém várias soluções vivas, o que reduz o risco de ficar preso em uma só.
- **Transparência.** O resultado pode ser um pipeline legível, exportado como código.

**Limites:**

- **Custo.** Cada geração avalia dezenas de pipelines. Em dados grandes, o custo cresce depressa.
- **Aleatoriedade.** Duas execuções podem dar resultados diferentes. Fixe sementes e repita.
- **Muitos parâmetros do próprio método.** Tamanho da população, número de gerações, taxas de mutação e de cruzamento. Escolhê-los é, em si, um problema de hiperparâmetros.
- **Tendência à complexidade.** Sem controle (como o segundo objetivo), os pipelines crescem.
- **Overfitting da busca.** Como em todo AutoML, testar muitos pipelines infla a nota do melhor (Capítulos 2 e 4). Use teste final intocado.

| Família | Ideia central | Pontos fortes | Cuidados |
|---|---|---|---|
| Aleatória / grade | Sorteio ou varredura | Simples; paralela; linha de base | Não aprende com o histórico |
| Bayesiana (GP, TPE, SMAC) | Modelo substituto + aquisição | Eficiente com poucas avaliações caras | Sequencial; sofre com dimensões altas (GP) |
| Multifidelidade (Halving, Hyperband) | Cortar cedo candidatos fracos | Economiza treino | O ranking pode mudar com o treino |
| Evolutiva (GA, GP, TPOT) | População, seleção, cruzamento, mutação | Estruturas variáveis; multiobjetivo; paralela | Custo; aleatoriedade; complexidade |

:::memorize Memorize
Nenhuma família vence sempre. A escolha depende do **espaço de busca** (simples ou estruturado), do **custo de cada avaliação** e do **orçamento**. E a **busca aleatória** continua sendo a linha de base de comparação.
:::

## 7.9 Boas práticas

1. **Defina o orçamento:** população, número de gerações e tempo máximo.
2. **Fixe sementes** e repita a evolução, relatando média e variação.
3. **Compare com a busca aleatória** no mesmo número de avaliações.
4. **Use elitismo** para não perder os melhores.
5. **Controle a complexidade** (segundo objetivo ou limite de tamanho).
6. **Use o cache** de avaliações, para não repetir pipelines idênticos.
7. **Avalie o resultado final** em um teste intocado e **leia o pipeline exportado**: entenda o que ele faz antes de usá-lo.

## Resumo do capítulo

:::memorize Cartões de memorização
- **Computação evolutiva:** busca por simulação da evolução (variação + seleção + hereditariedade).
- **Algoritmo genético:** população de indivíduos; aptidão = nota de validação; seleção, cruzamento, mutação, elitismo.
- **Cruzamento** combina boas ideias; **mutação** mantém diversidade.
- **Programação genética:** soluções como árvores; cruzamento troca subárvores.
- **TPOT:** evolui pipelines do scikit-learn por programação genética e exporta código Python.
- **Multiobjetivo:** acurácia × complexidade; **fronteira de Pareto** = melhores concessões.
- **NSGA-II:** GA multiobjetivo com ordenação por não dominância.
- **Nenhuma família vence sempre:** compare com a busca aleatória.
:::
