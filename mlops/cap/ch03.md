## 3.1 Lixo entra, lixo sai

Existe um ditado antigo na computação: ***garbage in, garbage out***. Em português: se entra lixo, sai lixo. Em ML, ele vale em dobro. Um modelo é tão bom quanto os dados com que aprendeu **e** os dados que recebe em produção.

Sambasivan e colegas (2021) estudaram profissionais de IA em projetos de alto risco e chamaram de **cascatas de dados** (*data cascades*) os problemas que nascem cedo nos dados, passam despercebidos e causam danos graves lá na frente. Quase todos os profissionais entrevistados relataram ter sofrido ao menos uma cascata. O estudo conclui que o trabalho com dados é muitas vezes pouco valorizado, embora seja decisivo.

Whang e colegas (2023) discutem os desafios de coleta e qualidade de dados sob a perspectiva de uma "IA centrada em dados", que coloca os dados, e não só o algoritmo, no centro do trabalho.

:::cotidiano No seu dia a dia
Pense numa **receita com ingredientes vencidos**. Não importa se o cozinheiro é excelente: o prato sai ruim, e talvez perigoso. Cuidar dos ingredientes (dados) vem antes de cuidar da panela (algoritmo).
:::

## 3.2 As dimensões da qualidade dos dados

Wang e Strong (1996) perguntaram aos usuários de dados o que "qualidade" significava para eles. A resposta foi além da simples exatidão. Hoje as equipes usam um conjunto de dimensões parecido com este:

| Dimensão | Pergunta | Exemplo de problema |
|---|---|---|
| **Completude** | Faltam valores? | Renda vazia em 30% dos clientes |
| **Validade** | O valor está no formato e no intervalo permitidos? | Idade = −5 ou 250 |
| **Unicidade** | Há registros duplicados? | O mesmo cliente aparece duas vezes |
| **Consistência** | Os dados concordam entre si? | Data de saída anterior à data de entrada |
| **Atualidade** | Os dados estão em dia? | Tabela atualizada pela última vez há 6 meses |
| **Exatidão** | O valor corresponde à realidade? | Endereço antigo |
| **Representatividade** | Os dados cobrem os casos reais? | Só clientes de uma cidade |

![f3_qualidade](Figura 3.1 — As dimensões da qualidade dos dados, vistas como um painel de instrumentos. Cada medidor deve ser verificado de forma automática.)

### 3.2.1 Medindo a qualidade com pandas

Vamos criar uma tabela de clientes com defeitos conhecidos e medi-los. Usaremos dados simulados, para saber exatamente quais problemas existem.

```python
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
n = 1000
df = pd.DataFrame({
    "id_cliente": np.arange(n),
    "idade": rng.integers(18, 80, n).astype(float),
    "renda": rng.lognormal(8.0, 0.5, n).round(2),
    "cidade": rng.choice(["Natal", "Recife", "Fortaleza"], n),
})
# defeitos injetados de propósito
df.loc[rng.choice(n, 120, replace=False), "renda"] = np.nan      # ausentes
df.loc[rng.choice(n, 15, replace=False), "idade"] = -1           # inválidos
df = pd.concat([df, df.sample(25, random_state=1)], ignore_index=True)  # duplicados

relatorio = {
    "linhas": len(df),
    "% ausentes em renda": round(df["renda"].isna().mean() * 100, 1),
    "idades inválidas (<0 ou >120)": int((~df["idade"].between(0, 120)).sum()),
    "linhas duplicadas": int(df.duplicated().sum()),
    "ids repetidos": int(df["id_cliente"].duplicated().sum()),
}
for k, v in relatorio.items():
    print(f"{k:32s}: {v}")
```

O relatório mostra, em segundos, quatro problemas. Em um projeto real, **essa verificação roda sozinha** toda vez que chegam dados novos.

## 3.3 Validação automática de dados

Validar dados é como o **controle de passaporte** de um aeroporto: ninguém entra sem documentos válidos. Breck e colegas (2019) descrevem, no contexto do TFX, um sistema de validação de dados com três ideias centrais:

1. **Esquema** (*schema*): descreve o que é esperado de cada coluna (tipo, intervalo, valores permitidos, proporção de ausentes).
2. **Detecção de anomalias nos dados**: compara novos lotes com o esquema e avisa sobre desvios.
3. **Desvio treino–serviço** (*training-serving skew*): detecta se os dados vistos em produção diferem dos dados usados no treino.

Schelter e colegas (2018) trazem uma ideia parecida para dados em larga escala: escrever **"testes unitários para dados"**, ou seja, regras declarativas verificadas automaticamente.

### 3.3.1 Um validador simples

Ferramentas como Great Expectations, Pandera e o TensorFlow Data Validation fazem isso de forma completa. Para entender a lógica, vamos escrever um validador mínimo:

```python
import numpy as np
import pandas as pd

ESQUEMA = {
    "idade":  {"tipo": "numerico", "min": 18, "max": 100, "max_ausentes": 0.0},
    "renda":  {"tipo": "numerico", "min": 0, "max": 1e6, "max_ausentes": 0.05},
    "cidade": {"tipo": "categorico", "permitidos": {"Natal", "Recife", "Fortaleza"},
               "max_ausentes": 0.0},
}

def validar(df, esquema):
    erros = []
    for col, regra in esquema.items():
        if col not in df.columns:
            erros.append(f"coluna ausente: {col}")
            continue
        serie = df[col]
        frac_nulos = serie.isna().mean()
        if frac_nulos > regra["max_ausentes"]:
            erros.append(f"{col}: {frac_nulos:.1%} de ausentes (máximo {regra['max_ausentes']:.0%})")
        valida = serie.dropna()
        if regra["tipo"] == "numerico":
            fora = ((valida < regra["min"]) | (valida > regra["max"])).sum()
            if fora:
                erros.append(f"{col}: {fora} valores fora de [{regra['min']}, {regra['max']}]")
        else:
            inesperados = set(valida.unique()) - regra["permitidos"]
            if inesperados:
                erros.append(f"{col}: categorias inesperadas {sorted(inesperados)}")
    return erros

lote = pd.DataFrame({
    "idade": [25, 40, -1, 130, 33],
    "renda": [3000, np.nan, 4500, 2800, np.nan],
    "cidade": ["Natal", "Recife", "Salvador", "Natal", "Fortaleza"],
})
problemas = validar(lote, ESQUEMA)
print("Lote aprovado!" if not problemas else "Lote REPROVADO:")
for p in problemas:
    print(" -", p)
```

:::dica Dica
Trate a validação como um **portão** (*gate*). Se o lote reprova, o pipeline **para** e avisa alguém, em vez de treinar com lixo. Isso evita as cascatas de dados.
:::

![f3_validacao](Figura 3.2 — Portões de validação no pipeline de dados: lotes que não passam são desviados para quarentena e geram alerta.)

## 3.4 Vazamento de dados: o inimigo invisível

O **vazamento de dados** (*data leakage*) acontece quando o modelo "vê", durante o treino, uma informação que **não estaria disponível** na hora de prever. Os resultados ficam lindos no teste e péssimos na vida real. Kaufman e colegas (2012) formalizam o problema e mostram como detectá-lo e evitá-lo.

:::cotidiano No seu dia a dia
É como um aluno que **vê a prova antes** de fazê-la. A nota é ótima, mas não prova que ele sabe a matéria.
:::

Os tipos mais comuns:

- **Vazamento de alvo:** um atributo é uma consequência do rótulo. Exemplo: prever inadimplência usando "valor cobrado em cobrança judicial".
- **Contaminação treino–teste:** informação do teste entra no treino (por exemplo, normalizar tudo antes de dividir; veja o Capítulo 4).
- **Vazamento temporal:** usar dados do futuro para prever o passado.
- **Duplicatas:** o mesmo registro aparece no treino e no teste.

### 3.4.1 Detectando um vazamento

Uma pista clássica: **resultado bom demais**. Vamos criar um atributo que vaza o alvo e ver o efeito:

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split

X, y = load_breast_cancer(return_X_y=True)
rng = np.random.default_rng(0)

# atributo "vazado": quase uma cópia do alvo, com um pouco de ruído
vazado = (y + rng.normal(0, 0.15, len(y))).reshape(-1, 1)
X_vaza = np.hstack([X, vazado])

def acuracia(entrada):
    Xtr, Xte, ytr, yte = train_test_split(entrada, y, test_size=0.3, random_state=0, stratify=y)
    return RandomForestClassifier(n_estimators=100, random_state=0).fit(Xtr, ytr).score(Xte, yte)

print("Sem vazamento:", round(acuracia(X), 3))
print("Com vazamento:", round(acuracia(X_vaza), 3))
```

A acurácia sobe para praticamente 100%. Em produção, a coluna vazada **não existe** na hora da previsão, e o desempenho desaba. A pergunta de ouro para cada atributo é:

:::memorize A pergunta do vazamento
"Na **hora exata** em que o modelo for usado, eu terei **esta informação**?"
:::

## 3.5 Rótulos errados também contam

Em muitos problemas, os rótulos (as "respostas corretas") vêm de pessoas, e pessoas erram. Northcutt, Athalye e Mueller (2021) mostraram que até conjuntos de dados famosos usados como padrão de comparação têm erros de rotulagem em seus conjuntos de teste, o que pode até mudar a classificação de modelos.

### 3.5.1 Quanto o ruído atrapalha?

Vamos simular: embaralhar uma fração dos rótulos de **treino** e medir a acurácia em um teste **limpo**.

```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

for ruido in [0.0, 0.1, 0.2, 0.4]:
    rng = np.random.default_rng(1)
    y_ruim = ytr.copy()
    idx = rng.choice(len(ytr), int(ruido * len(ytr)), replace=False)
    y_ruim[idx] = rng.integers(0, 10, len(idx))
    acc = RandomForestClassifier(n_estimators=100, random_state=0).fit(Xtr, y_ruim).score(Xte, yte)
    print(f"ruído de rótulos = {ruido:4.0%} -> acurácia no teste limpo = {acc:.3f}")
```

![f3_rotulos](Figura 3.3 — Efeito do ruído aleatório nos rótulos de treino sobre a acurácia em dados de teste limpos (experimento do texto, 1.797 imagens de dígitos).)

Observe que a floresta aleatória é bastante **robusta a ruído aleatório moderado**: a acurácia quase não muda com 10% ou 20% de rótulos trocados e só cai de forma visível com 40%. Mas cuidado: erros **sistemáticos** (por exemplo, um rotulador que sempre confunde duas classes) são muito mais danosos do que erros ao acaso. Por isso, em MLOps, **rótulos são tratados como dados de primeira classe**: revisados, amostrados e monitorados.

## 3.6 Como dividir os dados

Dividir os dados em **treino**, **validação** e **teste** é um ato de honestidade científica.

- **Treino:** onde o modelo aprende.
- **Validação:** onde se comparam modelos e se ajustam hiperparâmetros.
- **Teste:** usado **uma vez**, no final, para estimar o desempenho real.

| Estratégia | Quando usar | Cuidado |
|---|---|---|
| Aleatória | Dados independentes e sem ordem | Não use com séries temporais |
| Estratificada | Classes desbalanceadas | Mantém a proporção das classes |
| Temporal | Dados com tempo (vendas, fraude) | Treina no passado e testa no futuro |
| Por grupo | Várias linhas por pessoa/cliente | Evita o mesmo indivíduo nos dois lados |

```python
import numpy as np
import pandas as pd
from sklearn.model_selection import GroupShuffleSplit

# Cada cliente aparece várias vezes (várias compras).
df = pd.DataFrame({
    "cliente": np.repeat(np.arange(50), 6),
    "valor": np.random.default_rng(0).normal(100, 20, 300),
})
gss = GroupShuffleSplit(n_splits=1, test_size=0.2, random_state=0)
tr, te = next(gss.split(df, groups=df["cliente"]))
clientes_comuns = set(df.iloc[tr]["cliente"]) & set(df.iloc[te]["cliente"])
print("Clientes presentes nos dois lados:", len(clientes_comuns))
```

Com a divisão por grupo, **nenhum cliente** aparece nos dois conjuntos, evitando que o modelo "decore" pessoas.

## 3.7 Versionando dados

Você versiona seu código com **Git**: cada mudança deixa um registro. Mas e os dados? Arquivos grandes não cabem bem no Git, e ainda assim precisamos saber **qual versão dos dados** gerou **qual modelo**.

### 3.7.1 A ideia do hash

Um **hash** é uma "impressão digital" de um conteúdo. Se um único byte mudar, o hash muda por completo. Usamos hashes como identificadores de versão.

```python
import hashlib
import json
import numpy as np
import pandas as pd

def hash_dataframe(df):
    """Impressão digital estável do conteúdo de uma tabela."""
    csv_bytes = df.to_csv(index=False).encode("utf-8")
    return hashlib.sha256(csv_bytes).hexdigest()

df = pd.DataFrame({"x": [1, 2, 3], "y": [10.0, 20.0, 30.0]})
v1 = hash_dataframe(df)

df2 = df.copy()
df2.loc[1, "y"] = 20.1              # mudança mínima
v2 = hash_dataframe(df2)

print("versão 1:", v1[:16], "...")
print("versão 2:", v2[:16], "...")
print("Iguais?", v1 == v2)

manifesto = {"arquivo": "clientes.csv", "sha256": v1, "linhas": len(df),
             "colunas": list(df.columns)}
print(json.dumps(manifesto, indent=2))
```

Guardar esse **manifesto** junto do modelo já resolve o essencial: dá para provar com qual dado o modelo foi treinado.

### 3.7.2 Como o DVC funciona

O **DVC** (*Data Version Control*) é uma ferramenta que usa essa ideia. O funcionamento, em linhas gerais:

1. Os dados grandes ficam em um **armazenamento remoto** (disco, nuvem).
2. No Git, fica apenas um **arquivo pequeno** com o hash e o caminho do dado.
3. Ao trocar de versão no Git, o DVC traz de volta os dados correspondentes.

![f3_versionamento](Figura 3.4 — Versionamento de dados no estilo DVC: o Git guarda ponteiros leves; os arquivos pesados ficam em armazenamento remoto.)

Comandos típicos (execute no terminal; não são código Python):

```bash
git init && dvc init                       # inicia os dois repositórios
dvc add data/raw/clientes.csv              # cria data/raw/clientes.csv.dvc
git add data/raw/clientes.csv.dvc data/raw/.gitignore
git commit -m "Dados v1"
dvc remote add -d armazem s3://meu-bucket/dados   # define o armazenamento remoto
dvc push                                   # envia os dados para o armazenamento
dvc checkout                               # volta os dados da versão atual do Git
```

:::atencao Atenção
Os comandos acima são ilustrativos e dependem de instalar o DVC e de configurar o armazenamento. Eles não foram executados na elaboração deste livro. Consulte a documentação oficial da ferramenta para seu ambiente.
:::

### 3.7.3 Dados que mudam com o tempo

Há três estratégias comuns:

- **Instantâneos** (*snapshots*): guardar uma cópia completa a cada versão. Simples, mas ocupa espaço.
- **Particionamento por data:** guardar `dados/2026-10-01/`, `dados/2026-10-02/` etc.
- **Viagem no tempo** (*time travel*): formatos de tabela que guardam o histórico e permitem consultar o dado "como era" em certa data.

## 3.8 Documentando os dados

Dados sem documentação são como um remédio sem bula. Gebru e colegas (2021) propuseram as ***datasheets for datasets***: uma "ficha técnica" que acompanha o conjunto de dados e responde perguntas como:

- **Motivação:** por que o conjunto foi criado? Por quem?
- **Composição:** o que há nele? Quantos exemplos? Há dados pessoais?
- **Coleta:** como foi coletado? Houve consentimento?
- **Pré-processamento:** o que foi limpo ou removido?
- **Usos:** para que serve? Para que **não** deve ser usado?
- **Distribuição e manutenção:** quem mantém? Há licença?

Veja um modelo simples em Python, para guardar ao lado do dado:

```python
import json

datasheet = {
    "nome": "Câncer de mama (Diagnóstico de Wisconsin)",
    "origem": "Repositório UCI Machine Learning (embutido no scikit-learn)",
    "exemplos": 569,
    "atributos": 30,
    "alvo": "diagnóstico: maligno (0) ou benigno (1)",
    "uso_indicado": "estudo e ensino de classificação binária",
    "uso_nao_indicado": "apoio real a diagnóstico clínico sem validação médica",
    "limitacoes": ["amostra pequena", "uma única instituição", "sem dados temporais"],
    "licenca": "consultar a página do conjunto de dados no repositório UCI",
}
print(json.dumps(datasheet, indent=2, ensure_ascii=False))
```

## 3.9 Dados pessoais e privacidade desde o início

Se os dados descrevem pessoas, há obrigações legais (no Brasil, a LGPD, Lei n.º 13.709/2018) e éticas. Duas práticas básicas:

- **Minimização:** colete e guarde apenas o que for necessário.
- **Pseudonimização:** troque identificadores diretos (CPF, e-mail) por códigos que não permitem identificar a pessoa sem uma informação adicional guardada separadamente.

```python
import hashlib
import hmac

SEGREDO = b"guarde-esta-chave-fora-do-codigo"   # em produção: gerenciador de segredos

def pseudonimizar(identificador: str) -> str:
    return hmac.new(SEGREDO, identificador.encode(), hashlib.sha256).hexdigest()[:16]

print(pseudonimizar("maria@exemplo.com"))
print(pseudonimizar("maria@exemplo.com") == pseudonimizar("maria@exemplo.com"))
```

Note que o mesmo e-mail sempre gera o mesmo código (permite juntar tabelas), mas ninguém consegue reverter o código sem a chave. O Capítulo 10 trata de privacidade com mais profundidade, incluindo a privacidade diferencial (DWORK; ROTH, 2014).

## 3.10 Onde encontrar dados reais

Para praticar, use repositórios públicos:

- **UCI Machine Learning Repository** (DUA; GRAFF, 2019): centenas de conjuntos clássicos. O pacote `ucimlrepo` facilita o download.
- **Kaggle:** competições e conjuntos de dados da comunidade; exige conta.
- **OpenML** (VANSCHOREN et al., 2013): plataforma aberta de conjuntos e experimentos; o scikit-learn acessa via `fetch_openml`.

:::saibamais Saiba mais
Os conjuntos *Iris*, *Wine*, *Breast Cancer Wisconsin* e *Digits* já vêm embutidos no scikit-learn, e são originários do repositório UCI. Por isso, usamo-los ao longo do livro: não exigem download e garantem os mesmos resultados para todos.
:::

## 3.11 Resumo do capítulo

:::memorize O que levar deste capítulo
- **Garbage in, garbage out**: cuide dos dados antes do algoritmo.
- Dimensões de qualidade: **completude, validade, unicidade, consistência, atualidade, exatidão e representatividade**.
- **Valide automaticamente**: esquema, intervalos e categorias. Reprove o lote ruim antes de treinar.
- **Vazamento de dados** dá resultado bom demais. Pergunte: "terei essa informação na hora de prever?"
- **Rótulos errados** prejudicam o modelo; trate-os como dados importantes.
- Divida os dados com cuidado: estratificada, temporal ou por grupo, conforme o caso.
- **Hash** identifica versões de dados; o **DVC** guarda ponteiros no Git e os dados em armazenamento remoto.
- Documente com **datasheets** e proteja dados pessoais desde o início.
:::
