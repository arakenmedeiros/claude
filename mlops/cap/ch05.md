## 5.1 O caderno de laboratório do cientista

Imagine um cozinheiro que testa 40 versões de uma receita, mas **não anota nada**. Na semana seguinte, o chefe pergunta: "Qual versão ficou melhor? Quanto de açúcar usamos?". Ninguém sabe.

É o que acontece quando se treinam modelos sem registro. Um dia alguém diz: "aquele modelo de terça-feira era melhor, volte para ele". Mas qual era? Com quais parâmetros? Com quais dados?

O **rastreamento de experimentos** (*experiment tracking*) é o **caderno de laboratório** do ML. Cada tentativa deixa um registro completo.

![f5_caderno](Figura 5.1 — Sem rastreamento, as tentativas se perdem. Com rastreamento, cada execução guarda parâmetros, métricas, artefatos e a origem do código e dos dados.)

Zaharia e colegas (2018) apresentaram o **MLflow**, uma plataforma de código aberto criada justamente para organizar o ciclo de vida de ML. No artigo, eles motivam a ferramenta com dificuldades comuns: acompanhar experimentos, reproduzir código e compartilhar e implantar modelos.

## 5.2 O vocabulário do rastreamento

| Termo | O que é | Exemplo |
|---|---|---|
| **Experimento** | Grupo de execuções para um mesmo objetivo | "detecção de cancelamento" |
| **Execução** (*run*) | Uma tentativa de treino, do começo ao fim | `rf_200_arvores` |
| **Parâmetro** | Valor de entrada, fixo durante a execução | `n_estimators = 200` |
| **Métrica** | Número que mede o resultado, pode variar no tempo | `f1 = 0,96` |
| **Artefato** | Arquivo produzido: modelo, gráfico, relatório | `matriz_confusao.png` |
| **Tag** | Rótulo livre para organizar | `autor = Ana` |
| **Modelo registrado** | Modelo catalogado, com versões | `detector_cancer v3` |

## 5.3 Primeiros passos com o MLflow

O MLflow tem alguns componentes principais:

- **Tracking:** registra e consulta execuções.
- **Models:** um formato padrão para empacotar modelos.
- **Model Registry:** catálogo de modelos, com versões e apelidos.
- **Projects:** formato para empacotar código reprodutível (não usaremos aqui).

Para registrar informações, precisamos dizer *onde* guardar. O jeito mais simples é um banco de dados local SQLite.

```python
import math
import mlflow

mlflow.set_tracking_uri("sqlite:///mlflow.db")   # banco local, um único arquivo
mlflow.set_experiment("primeiros_passos")

with mlflow.start_run(run_name="minha_primeira_execucao"):
    mlflow.log_param("taxa_aprendizado", 0.1)
    mlflow.log_param("origem_dos_dados", "simulado")
    for epoca in range(1, 6):
        perda = math.exp(-0.5 * epoca)                 # perda caindo com o tempo
        mlflow.log_metric("perda", perda, step=epoca)  # métrica com passo
    mlflow.set_tag("autor", "estudante")

execucoes = mlflow.search_runs()
print(execucoes[["run_id", "params.taxa_aprendizado", "metrics.perda"]].to_string(index=False))
```

O trecho `with mlflow.start_run()` abre uma execução, e tudo o que for registrado dentro dele fica associado a ela. Ao sair do bloco, a execução é encerrada.

:::dica Dica
Para **ver** os registros em uma interface web, rode no terminal, na pasta do projeto: `mlflow ui --backend-store-uri sqlite:///mlflow.db`. Depois abra o endereço que o programa mostrar (normalmente `http://127.0.0.1:5000`). Esse comando só funciona com o MLflow instalado.
:::

## 5.4 Registrando um experimento de verdade

Vamos comparar três configurações de uma floresta aleatória. Para cada uma, registramos:

- os **parâmetros** (hiperparâmetros e semente);
- as **métricas** (F1 e acurácia);
- a **impressão digital dos dados** (hash do Capítulo 3), para saber com qual dado foi treinado;
- um **artefato** gráfico (matriz de confusão);
- o **modelo**, com sua **assinatura**.

A **assinatura** (*signature*) descreve os nomes e tipos de entrada e saída esperados. É um contrato: se alguém enviar dados no formato errado, o erro aparece cedo.

```python
import hashlib
import warnings
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt
import mlflow
import mlflow.sklearn
import pandas as pd
from mlflow.models import infer_signature
from sklearn.datasets import load_breast_cancer
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import ConfusionMatrixDisplay, accuracy_score, f1_score
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

warnings.filterwarnings("ignore")
mlflow.set_tracking_uri("sqlite:///mlflow.db")
mlflow.set_experiment("cancer_rf")

dados = load_breast_cancer(as_frame=True)
X, y = dados.data, dados.target
hash_dados = hashlib.sha256(pd.concat([X, y], axis=1).to_csv(index=False).encode()).hexdigest()[:12]
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)

for n_arvores in [5, 50, 300]:
    with mlflow.start_run(run_name=f"rf_{n_arvores}"):
        pipe = make_pipeline(StandardScaler(),
                             RandomForestClassifier(n_estimators=n_arvores, random_state=0))
        pipe.fit(Xtr, ytr)
        previsto = pipe.predict(Xte)

        mlflow.log_params({"n_estimators": n_arvores, "semente": 0, "tamanho_teste": 0.25})
        mlflow.log_metrics({"f1": f1_score(yte, previsto), "acuracia": accuracy_score(yte, previsto)})
        mlflow.set_tags({"hash_dados": hash_dados, "base": "UCI WDBC"})

        fig, ax = plt.subplots(figsize=(3.6, 3.2))
        ConfusionMatrixDisplay.from_predictions(yte, previsto, ax=ax)
        mlflow.log_figure(fig, "matriz_confusao.png")
        plt.close(fig)

        assinatura = infer_signature(Xte, previsto)
        mlflow.sklearn.log_model(pipe, name="modelo", signature=assinatura,
                                 skops_trusted_types=["sklearn.tree._tree.Tree"])

res = mlflow.search_runs(order_by=["metrics.f1 DESC"])
print(res[["tags.mlflow.runName", "params.n_estimators", "metrics.f1", "metrics.acuracia"]]
      .round(4).to_string(index=False))
```

![f5_comparacao](Figura 5.2 — Comparação das execuções do experimento. Com tudo registrado, escolher o melhor modelo vira uma consulta, e não uma memória.)

:::atencao Atenção: diferença pequena não é prova
Neste exemplo, a floresta com **5 árvores** teve F1 ligeiramente maior que as de 50 e 300 árvores. Com apenas 143 exemplos de teste, diferenças dessa ordem podem ser **ruído**. Registrar tudo permite ver isso; decidir com rigor exige as técnicas estatísticas do Capítulo 6.
:::

### 5.4.1 Cuidado com o formato do modelo salvo

O MLflow salva modelos do scikit-learn, por padrão, em um formato seguro chamado **skops**. Ao carregar, ele exige que você declare quais tipos de objeto são confiáveis (como `sklearn.tree._tree.Tree`, usado nas árvores). Isso evita executar código malicioso escondido em um arquivo de modelo.

:::atencao Atenção
Formatos como `pickle` e `cloudpickle` podem executar código arbitrário ao serem abertos. Prefira formatos seguros e **só carregue modelos de fontes que você controla**. Versões diferentes do MLflow podem ter padrões diferentes: confira a documentação da versão que usar.
:::

### 5.4.2 O que mais vale registrar

Quanto mais contexto, melhor a rastreabilidade. Além do que fizemos, considere registrar:

- o **commit do Git** do código (o MLflow costuma capturar automaticamente quando há repositório);
- o arquivo **requirements.txt** ou a lista de pacotes;
- a **duração** do treino e o **consumo de memória**;
- métricas por **subgrupo** de dados (para justiça e robustez, Capítulos 6 e 10);
- **comentários** sobre a motivação do experimento.

### 5.4.3 Registro automático (*autologging*)

O MLflow consegue registrar parâmetros, métricas e o modelo **automaticamente** para as bibliotecas mais usadas. É prático para começar:

```python
import warnings
import mlflow
from sklearn.datasets import load_wine
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import train_test_split

warnings.filterwarnings("ignore")
mlflow.set_tracking_uri("sqlite:///mlflow.db")
mlflow.set_experiment("autolog_demo")
mlflow.sklearn.autolog(log_models=False)     # registra parâmetros e métricas de treino

X, y = load_wine(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
with mlflow.start_run():
    LogisticRegression(max_iter=5000, C=0.5).fit(Xtr, ytr)

execucao = mlflow.search_runs().iloc[0]
print("Parâmetro C registrado sozinho:", execucao["params.C"])
```

O *autologging* é conveniente, mas **não substitui** o registro consciente das decisões importantes (hash dos dados, semente, métricas de negócio).

## 5.5 Do experimento ao produto: o registro de modelos

Escolher o melhor modelo não basta. É preciso um **catálogo oficial** de modelos aprovados, com versões. É o **registro de modelos** (*model registry*).

Pense em uma **biblioteca**. Cada livro tem edições. Há uma "edição vigente" que todos devem consultar. O registro funciona assim:

- **Modelo registrado:** o "título" (por exemplo, `detector_cancer`).
- **Versão:** a "edição" (v1, v2, v3...).
- **Apelido** (*alias*): um nome móvel que aponta para uma versão, como `champion` (a que está em produção) e `challenger` (a candidata).

![f5_registro](Figura 5.3 — Registro de modelos: versões numeradas e apelidos que apontam para elas. Para trocar o modelo em produção basta mover o apelido `champion`.)

A grande vantagem dos apelidos: o código de produção carrega sempre `models:/detector_cancer@champion`. Para atualizar ou reverter o modelo, **ninguém precisa mexer no código de produção**: basta mover o apelido.

```python
import warnings
import mlflow
import mlflow.sklearn
from mlflow import MlflowClient
from mlflow.models import infer_signature
from sklearn.datasets import load_breast_cancer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import f1_score
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

warnings.filterwarnings("ignore")
mlflow.set_tracking_uri("sqlite:///mlflow.db")
mlflow.set_experiment("registro_demo")
NOME = "detector_cancer"

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, stratify=y, random_state=0)

def treinar_e_registrar(C):
    with mlflow.start_run(run_name=f"logreg_C{C}"):
        pipe = make_pipeline(StandardScaler(), LogisticRegression(C=C, max_iter=2000)).fit(Xtr, ytr)
        f1 = f1_score(yte, pipe.predict(Xte))
        mlflow.log_params({"C": C})
        mlflow.log_metric("f1", f1)
        info = mlflow.sklearn.log_model(pipe, name="modelo",
                                        signature=infer_signature(Xte, pipe.predict(Xte)))
    versao = mlflow.register_model(info.model_uri, NOME)    # cria v1, v2, ...
    return versao.version, f1

cliente = MlflowClient()
v1, f1_v1 = treinar_e_registrar(0.01)
cliente.set_registered_model_alias(NOME, "champion", v1)     # v1 vai para produção
v2, f1_v2 = treinar_e_registrar(1.0)
cliente.set_registered_model_alias(NOME, "challenger", v2)   # v2 é a candidata

print(f"v{v1}: F1 = {f1_v1:.4f} | v{v2}: F1 = {f1_v2:.4f}")
producao = mlflow.sklearn.load_model(f"models:/{NOME}@champion")
print("Previsões do champion:", producao.predict(Xte[:5]))
print("Champion é a versão:", cliente.get_model_version_by_alias(NOME, "champion").version)
```

:::saibamais Saiba mais
Versões antigas do MLflow usavam **estágios** (*Staging*, *Production*, *Archived*). Hoje a recomendação da própria ferramenta é usar **apelidos** e **tags**, mais flexíveis. Se você encontrar tutoriais com estágios, entenda que a ideia é a mesma: marcar qual versão está em cada fase.
:::

## 5.6 Promoção automática com portão de qualidade

Mover o apelido `champion` à mão é arriscado. Podemos criar uma **regra automática** (um "portão") que só promove a candidata se ela for melhor **e** passar nas verificações mínimas.

A regra tem de ser conservadora. Por exemplo:

1. A candidata deve superar a campeã em pelo menos uma **margem mínima** (para evitar trocar por diferenças de ruído).
2. A candidata deve respeitar um **piso** absoluto de qualidade.
3. O resultado deve ser **registrado** (quem promoveu, quando, por quê).

```python
def decidir_promocao(f1_campea, f1_candidata, margem=0.005, piso=0.90):
    """Retorna (promover?, motivo)."""
    if f1_candidata < piso:
        return False, f"reprovada: F1 {f1_candidata:.3f} abaixo do piso {piso:.2f}"
    if f1_candidata < f1_campea + margem:
        return False, f"reprovada: ganho {f1_candidata - f1_campea:+.3f} menor que a margem {margem}"
    return True, f"aprovada: ganho de {f1_candidata - f1_campea:+.3f} sobre a campeã"

casos = [(0.950, 0.980), (0.950, 0.952), (0.950, 0.850), (0.920, 0.961)]
for campea, candidata in casos:
    ok, motivo = decidir_promocao(campea, candidata)
    print(f"campeã={campea:.3f} candidata={candidata:.3f} -> {'PROMOVER' if ok else 'manter'} ({motivo})")
```

Em um pipeline real, essa função roda ao final do treino. Se aprovar, chama `set_registered_model_alias(..., "champion", nova_versao)`. Se reprovar, mantém o modelo atual e avisa a equipe.

:::dica Dica
Uma comparação justa exige **o mesmo conjunto de teste** para as duas versões. Guarde um conjunto de avaliação fixo e versionado (Capítulo 3). Para decisões importantes, compare também as **incertezas** (Capítulo 6), e não só os valores médios.
:::

## 5.7 Metadados de modelo: o que um "cartão de identidade" deve conter

Cada modelo registrado deve ter uma ficha mínima:

| Campo | Exemplo |
|---|---|
| Nome e versão | `detector_cancer` v2 |
| Objetivo e uso indicado | Triagem de apoio, não diagnóstico |
| Dados de treino | hash `a3f9...`, período, fonte |
| Código | commit `9d1c...` |
| Parâmetros | `C = 1.0`, semente 0 |
| Métricas | F1 = 0,97 (teste), subgrupos |
| Limitações conhecidas | Dados de uma só instituição |
| Responsável | Nome da equipe/pessoa |
| Data e aprovação | 2026-10-17, aprovado por... |

O Capítulo 10 aprofunda isso com os ***model cards*** (MITCHELL et al., 2019).

## 5.8 Além do MLflow

O MLflow é uma opção entre várias para rastrear experimentos e registrar modelos. Existem plataformas comerciais e de código aberto com ideias semelhantes (por exemplo, Weights & Biases, Neptune, Comet, DVC Experiments, ClearML e os serviços de nuvem). O que importa é o **princípio**: registrar de forma sistemática, comparável e reprodutível.

Em plataformas industriais, a mesma ideia aparece como "metadados de ML" integrados ao pipeline, como no TFX (BAYLOR et al., 2017), que guarda a linhagem de cada artefato produzido.

## 5.9 Resumo do capítulo

:::memorize O que levar deste capítulo
- **Rastrear experimentos** é manter um caderno de laboratório: parâmetros, métricas, artefatos, tags, dados e código.
- No MLflow: **experimento** agrupa **execuções**; cada execução tem **parâmetros**, **métricas**, **artefatos** e **tags**.
- A **assinatura** do modelo descreve as entradas e saídas esperadas.
- O **registro de modelos** guarda **versões** e **apelidos** (`champion`, `challenger`).
- O código de produção carrega o modelo pelo **apelido**; para trocar ou reverter, mova o apelido.
- Use um **portão de promoção** com margem mínima, piso de qualidade e registro da decisão.
- Prefira formatos de modelo **seguros** e carregue apenas modelos de origem confiável.
:::
