@@EX 1 | A ordem dos patches importa? | básico
Use `load_digits`, patches 4×4 (4 por imagem) e uma projeção PCA de 8 dimensões ajustada **apenas** nos patches do treino (1 300 imagens; as 497 restantes são de teste, com `np.random.default_rng(0).permutation`). Construa dois vetores de características por imagem: (a) a **média** dos embeddings dos patches (ignora a ordem) e (b) a **concatenação** dos embeddings na ordem de leitura (preserva a posição). Treine uma regressão logística em cada um e compare a acurácia de teste. Repita com patches 2×2 (16 patches).

*Pergunta:* o que o resultado diz sobre a necessidade de informação de posição? Por que o ViT soma vetores de posição em vez de concatenar?
@@SOL
```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.linear_model import LogisticRegression
from llmdidatico.multimodal import patches

dg = load_digits(); imagens, y = dg.images / 16, dg.target
idx = np.random.default_rng(0).permutation(len(y)); tr, te = idx[:1300], idx[1300:]

def caracteristicas(p, d=8):
    Ptr = np.concatenate([patches(imagens[i], p) for i in tr]); mu = Ptr.mean(0)
    _, _, Vt = np.linalg.svd(Ptr - mu, full_matrices=False); W = Vt[:d].T
    E = np.stack([(patches(im, p) - mu) @ W for im in imagens])      # (n, N, d)
    return E.mean(1), E.reshape(len(E), -1)

print(f"{'patch':>6} {'N':>4} {'média (sem ordem)':>18} {'concatenação (com ordem)':>25}")
for p in (4, 2):
    media, conc = caracteristicas(p)
    acc = []
    for F in (media, conc):
        clf = LogisticRegression(max_iter=2000).fit(F[tr], y[tr])
        acc.append(clf.score(F[te], y[te]))
    print(f"{p}x{p:<4} {(8 // p) ** 2:>4} {acc[0]:>18.3f} {acc[1]:>25.3f}")
```
@@NOTE Com patches 4×4, a regressão logística atinge 0,700 usando a **média** dos embeddings (sem ordem) e 0,964 com a **concatenação** (com ordem). Com patches 2×2, a média cai a 0,151 (perto do acaso, 0,10) e a concatenação sobe a 0,978. A média quase não carrega informação aqui porque os embeddings são centrados: ela resume, grosso modo, a quantidade de tinta e perde **onde** ela está, que é o que distingue os dígitos. Isso ilustra por que a informação de posição é indispensável. No ViT, a posição é **somada** (e não concatenada) para manter fixa a dimensão do modelo, deixando que a rede aprenda a usá-la; a atenção, sozinha, não percebe a ordem. O experimento é um brinquedo (classificador linear sobre características fixas), e não o ViT.
@@EX 2 | Temperatura e dimensão do embedding | intermediário
Treine o modelo contrastivo do capítulo (pares dígito↔descrição sintética, `treinar_contrastivo`, 40 épocas, lote 64) com $\tau\in\{0{,}05;\,0{,}5\}$ e dimensão do embedding $d\in\{2,4,8,16\}$, com 3 sementes cada. Reporte o recall@1 imagem→texto (critério: mesmo dígito) no teste como média e desvio-padrão entre sementes.

*Pergunta:* a partir de que dimensão o recall satura? A temperatura muda essa conclusão? Lembre que são dados sintéticos e fáceis.
@@SOL
```python
import numpy as np
from sklearn.datasets import load_digits
from llmdidatico.multimodal import descricao, vocabulario, bow, treinar_contrastivo, recall_em_k

dg = load_digits(); imagens, y = dg.images, dg.target
X = imagens.reshape(len(imagens), -1) / 16
idx = np.random.default_rng(0).permutation(len(y)); tr, te = idx[:1300], idx[1300:]
med = np.median(X.sum(1)); rt = np.random.default_rng(1)
leg = [descricao(y[i], imagens[i] / 16, rt, med) for i in range(len(y))]
T = bow(leg, vocabulario(leg)); Xi = X - 0.5

def emb(A, W):
    Z = A @ W; return Z / np.linalg.norm(Z, axis=1, keepdims=True)

print(f"{'tau':>5} {'d':>3} {'R@1 i->t (média ± dp, 3 sementes)':>36}")
for tau in (0.05, 0.5):
    for d in (2, 4, 8, 16):
        r = []
        for sem in range(3):
            Wi, Wt, _ = treinar_contrastivo(Xi[tr], T[tr], d=d, tau=tau, epocas=40, lote=64, lr=0.05, seed=sem)
            S = emb(Xi[te], Wi) @ emb(T[te], Wt).T
            r.append(recall_em_k(S, y[te], y[te], (1,))[1])
        print(f"{tau:>5} {d:>3} {np.mean(r):>25.3f} ± {np.std(r):.3f}")
```
@@NOTE Com $d=2$ o recall@1 é baixo e instável (0,309 ± 0,145 com $\tau=0{,}05$ e 0,335 ± 0,055 com $\tau=0{,}5$): dois eixos não separam dez dígitos. Com $d=4$ sobe para 0,761 e 0,807, com desvios ainda altos; com $d=8$ chega a 0,960 e 0,967, e com $d=16$ a 0,970 em ambas as temperaturas, de modo que o recall satura a partir de $d=8$. A temperatura quase não muda a conclusão nesses dados fáceis; as diferenças entre $\tau$ para $d=4$ são comparáveis aos desvios entre sementes (0,023 e 0,055), então não se deve concluir qual é melhor. Em dados reais e ruidosos, o efeito costuma ser maior.
@@EX 3 | Janela da STFT: tempo versus frequência | intermediário
Gere (fs = 8 000 Hz, 2 s) um sinal com dois tons próximos, 440 Hz e 470 Hz, ambos ligados a partir de $t=1{,}0$ s (silêncio antes, sem ruído). Para `n_fft` em $\{64, 128, 256, 512, 1024\}$ (salto = n_fft/4), calcule: (a) a resolução em frequência $f_s/n_{fft}$ e se os dois tons aparecem como **dois picos separados** no espectro médio dos quadros após $t=1{,}2$ s; (b) a **largura de transição no tempo**: número de segundos entre o primeiro quadro com energia acima de 10% e o primeiro acima de 90% da energia máxima do quadro.

*Pergunta:* qual `n_fft` distingue os dois tons? O que se perde ao aumentá-lo?
@@SOL
```python
import numpy as np
from llmdidatico.multimodal import stft

fs = 8000
t = np.arange(2 * fs) / fs
x = np.where(t >= 1.0, np.sin(2 * np.pi * 440 * t) + np.sin(2 * np.pi * 470 * t), 0.0)
print(f"{'n_fft':>6} {'resol. (Hz)':>12} {'picos separados':>16} {'transição (ms)':>15}")
for n_fft in (64, 128, 256, 512, 1024):
    salto = n_fft // 4
    Z = np.abs(stft(x, n_fft, salto)); freqs = np.fft.rfftfreq(n_fft, 1 / fs)
    centros = (np.arange(Z.shape[1]) * salto + n_fft / 2) / fs
    esp = Z[:, centros >= 1.2 + n_fft / fs].mean(1)
    sel = (freqs > 300) & (freqs < 620); e = esp[sel]; f = freqs[sel]
    picos = [f[i] for i in range(1, len(e) - 1) if e[i] > e[i - 1] and e[i] > e[i + 1] and e[i] > 0.5 * e.max()]
    separados = len(picos) >= 2 and (max(picos) - min(picos)) >= 20
    energia = Z.max(0); i10 = np.argmax(energia > 0.1 * energia.max()); i90 = np.argmax(energia > 0.9 * energia.max())
    print(f"{n_fft:>6} {fs / n_fft:>12.2f} {str(separados):>16} {(i90 - i10) * salto / fs * 1000:>15.1f}")
```
@@NOTE A resolução em frequência vai de 125 Hz ($n_{fft}=64$) a 7,81 Hz ($n_{fft}=1024$). Os dois tons, separados por 30 Hz, só aparecem como dois picos com $n_{fft}=512$ (resolução 15,62 Hz) e 1024; com 256 (31,25 Hz) a resolução é comparável à separação e os picos se fundem. A largura de transição no tempo **não** é monotônica nesta medição (4,0 ms com 64; 32,0 ms com 128; 40,0 ms com 256; 32,0 ms com 512; 64,0 ms com 1024), pois depende do passo de salto, que é quantizado, e do critério de 10% a 90%; mas o caso extremo, 1024 (a janela dura 128 ms), é o que mais borra o início do tom. O compromisso é: janelas longas separam frequências próximas e perdem precisão no tempo.

@@PROJ Busca imagem–texto com abstenção e avaliação por fatia | intermediário
**Contexto.** Você vai montar um pequeno sistema de busca "descrição → imagens" sobre dígitos sintéticos e avaliá-lo como se fosse um produto: por fatia, com robustez a ruído e com um mecanismo de abstenção. Todos os dados são sintéticos (sem pessoas).

**Tarefas.**

1. Treine o modelo contrastivo do capítulo ($\tau=0{,}1$, $d=16$, 60 épocas) com 1 000 pares; reserve 300 pares como **validação** (para calibrar o limiar) e os 497 restantes como teste.
2. Implemente a classificação por descrições de classe ("dígito sete") e a recuperação texto→imagem. Reporte recall@1 e recall@5 (critério: mesmo dígito) no teste, com IC 95% por bootstrap.
3. **Robustez:** some ruído gaussiano de desvio $\sigma\in\{0;\,0{,}1;\,0{,}3;\,0{,}5\}$ às imagens de teste (em escala 0 a 1) e reporte a acurácia por classe de descrição com IC.
4. **Abstenção:** defina como escore a similaridade máxima entre a imagem e as descrições de classe. Para limiares correspondentes aos percentis 0, 5, 10 e 20 do escore na validação, reporte a **cobertura** (fração aceita) e a **acurácia entre as aceitas**, em imagens do domínio e em 300 imagens de **ruído uniforme** (fração de ruído aceita).
5. Escreva um parágrafo: que limiar você escolheria para um produto, e que cuidados adicionais (revisão humana, monitoramento) seriam necessários?

**Entregáveis.** Código, tabelas e o parágrafo.
@@RUBRICA
- Modelo treinado e avaliado no teste com IC (3 pontos).
- Análise de robustez ao ruído (2 pontos).
- Curva de cobertura × acurácia e taxa de ruído aceito (3 pontos).
- Discussão crítica, reconhecendo que os dados e o modelo são sintéticos e lineares (2 pontos).
@@SOL
```python
import numpy as np
from sklearn.datasets import load_digits
from llmdidatico.multimodal import descricao, vocabulario, bow, treinar_contrastivo, recall_em_k, PALAVRAS
from llmdidatico import avaliacao as av

dg = load_digits(); imagens, y = dg.images, dg.target
X = imagens.reshape(len(imagens), -1) / 16
idx = np.random.default_rng(0).permutation(len(y)); trn, val, te = idx[:1000], idx[1000:1300], idx[1300:]
med = np.median(X.sum(1)); rt = np.random.default_rng(1)
leg = [descricao(y[i], imagens[i] / 16, rt, med) for i in range(len(y))]
voc = vocabulario(leg); T = bow(leg, voc); Xi = X - 0.5

def emb(A, W):
    Z = A @ W; return Z / np.linalg.norm(Z, axis=1, keepdims=True)

Wi, Wt, h = treinar_contrastivo(Xi[trn], T[trn], d=16, tau=0.1, epocas=60, lote=64, lr=0.05, seed=0)
Up = emb(bow([f"dígito {w}" for w in PALAVRAS], voc), Wt)

# 2. recuperação e classificação
S = emb(Xi[te], Wi) @ emb(T[te], Wt).T
r_i2t, r_t2i = recall_em_k(S, y[te], y[te], (1, 5)), recall_em_k(S.T, y[te], y[te], (1, 5))
print("recall@1/@5 imagem->texto:", round(r_i2t[1], 3), round(r_i2t[5], 3), "| texto->imagem:", round(r_t2i[1], 3), round(r_t2i[5], 3))
acertos = ((emb(Xi[te], Wi) @ Up.T).argmax(1) == y[te]).astype(float)
m, lo, hi = av.bootstrap_ic(acertos, n=1000, seed=0)
print(f"acurácia por descrições de classe: {m:.3f}  IC95% [{lo:.3f}; {hi:.3f}]")

# 3. robustez ao ruído
rg = np.random.default_rng(4)
print("\nsigma   acurácia   IC95%")
for sg in (0.0, 0.1, 0.3, 0.5):
    Xr = np.clip(X[te] + sg * rg.standard_normal(X[te].shape), 0, 1) - 0.5
    a = ((emb(Xr, Wi) @ Up.T).argmax(1) == y[te]).astype(float)
    m, lo, hi = av.bootstrap_ic(a, n=1000, seed=0)
    print(f"{sg:<7} {m:<10.3f} [{lo:.3f}; {hi:.3f}]")

# 4. abstenção
esc_val = (emb(Xi[val], Wi) @ Up.T).max(1)
esc_te = (emb(Xi[te], Wi) @ Up.T)
pred_te, s_te = esc_te.argmax(1), esc_te.max(1)
ruido = np.random.default_rng(9).uniform(0, 1, (300, 64)) - 0.5
s_ru = (emb(ruido, Wi) @ Up.T).max(1)
print("\npercentil  limiar  cobertura  acurácia nas aceitas  ruído aceito")
for q in (0, 5, 10, 20):
    lim = np.percentile(esc_val, q)
    ac = s_te >= lim
    print(f"{q:>9} {lim:>7.3f} {ac.mean():>10.3f} {(pred_te[ac] == y[te][ac]).mean():>20.3f} {(s_ru >= lim).mean():>13.3f}")
```
@@NOTE No teste, o recall@1 imagem→texto é 0,966 (recall@5: 0,982) e texto→imagem 0,996 (1,000); a acurácia por descrições de classe é 0,946 (IC 95% [0,926; 0,966]). Com ruído, a acurácia cai de 0,946 ($\sigma=0$) para 0,924 (0,1), 0,722 (0,3) e 0,475 (0,5): o modelo linear é frágil a ruído forte. Na abstenção, com o limiar do percentil 20 da validação (0,394), a cobertura é 0,865 e a acurácia nas aceitas sobe para 0,970, mas 55,7% do ruído uniforme ainda é aceito; com o percentil 0 (aceita quase tudo), 99,3% do ruído é aceito. Ou seja, o limiar melhora a acurácia entre as aceitas (de 0,946 para 0,970) ao custo de recusar 13,5% das imagens do domínio, e **não** resolve a entrada fora do domínio. Em dados reais, seria preciso um detector específico de fora do domínio, revisão humana dos casos recusados e monitoramento. Todos os dados são sintéticos e o modelo é linear: não generalize.
