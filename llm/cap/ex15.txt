MC: Na decodificação com lote pequeno, qual costuma ser o gargalo principal do acelerador?
= A leitura dos pesos e do cache da memória, pois cada token novo exige poucas operações por byte lido.
- A capacidade de cálculo, pois cada passo multiplica enormes matrizes de ativações e satura as unidades aritméticas.
- A velocidade da rede entre o usuário e o servidor, que impede novos passos.
- O tamanho do vocabulário, que decide a duração de cada operação e, portanto, a de cada passo.
- A quantidade de tokens do prompt original, mesmo depois de processado.
J: Com poucas sequências, a intensidade aritmética é baixa; o tempo do passo é dominado por ler a memória, e não por calcular.

MC: Por que o comprimento da saída costuma dominar a latência de uma resposta?
= Porque os tokens de saída são gerados um a um, cada um ocupando um passo de decodificação.
- Porque a saída é sempre mais longa que o prompt de entrada, e o custo cresce com o número de caracteres.
- Porque o preenchimento do prompt é sequencial e lento, enquanto a geração da saída ocorre em paralelo.
- Porque a saída precisa ser traduzida de números para texto no fim.
- Porque os tokens de saída ocupam mais bytes que os de entrada.
J: O prompt entra em paralelo no preenchimento; a saída exige um passo por token.

MC: Ao aumentar o tamanho do lote na decodificação (em um modelo ainda limitado por memória), o que tende a ocorrer?
= A vazão total aumenta, mas o tempo por token para cada pessoa tende a piorar.
- A vazão total cai, mas cada pessoa recebe tokens mais rápido, pois divide a memória com menos gente.
- Tanto a vazão total quanto a velocidade individual aumentam sempre.
- Nada muda, pois os pesos são lidos uma vez por pessoa, e não uma vez por passo para todos.
- Os pesos passam a ocupar menos memória.
J: Os pesos são lidos uma vez para todos, o que eleva a vazão; o cache de cada sequência adicional aumenta a leitura por passo.

MC: Quanto ocupam só os pesos de um modelo hipotético de 7 bilhões de parâmetros com 4 bits por parâmetro?
= Cerca de 3,5 GB.
- Cerca de 14 GB, que seria o valor com 16 bits por parâmetro e não com 4.
- Cerca de 28 GB, que seria o valor com 32 bits por parâmetro e não com 4.
- Cerca de 7 GB, que seria o valor com 8 bits por parâmetro e não com 4.
- Cerca de 0,35 GB.
J: $7\times10^9\times0{,}5$ byte $=3{,}5\times10^9$ bytes.

MC: Na quantização simétrica com $b$ bits, como se costuma escolher a escala $s$ de um tensor?
= $s=\max|w|/(2^{b-1}-1)$.
- $s=\min(w)/b$.
- $s=2^{b}\cdot\max|w|$, de modo que o maior peso vire sempre o inteiro máximo.
- $s=\text{média}(w)/\text{desvio}(w)$.
- $s=1/\max|w|$, qualquer que seja $b$, sem depender do número de bits.
J: A escala faz o maior valor absoluto corresponder ao maior inteiro representável.

MC: Por que alguns valores muito grandes (outliers) prejudicam a quantização com uma única escala por tensor?
= Porque a escala é determinada pelo máximo, e um valor grande reduz a resolução com que todos os demais são representados.
- Porque valores grandes não podem ser representados por inteiros.
- Porque os outliers aumentam o número de bits de cada parâmetro.
- Porque a quantização sempre arredonda para cima os valores positivos.
- Porque os outliers mudam o tamanho do vocabulário do modelo.
J: Com o máximo grande, o passo da quantização cresce, e os pesos pequenos viram poucos níveis.

MC: Qual o benefício de usar uma escala por coluna (ou por grupo), em vez de uma por tensor?
= Adaptar o passo aos valores locais, reduzindo o efeito de colunas atípicas, ao custo de mais escalas.
- Eliminar a necessidade de guardar qualquer escala, já que cada coluna passa a usar o mesmo passo unitário.
- Dobrar o número de bits efetivos de cada peso, sem aumentar o tamanho do modelo na memória.
- Evitar que o modelo precise de dados de teste depois.
- Tornar a quantização reversível, sem nenhum erro.
J: Escalas mais finas seguem melhor as variações de magnitude entre partes do tensor.

MC: Um modelo quantizado em 4 bits apresentou perplexidade média quase igual à original. Qual a conclusão prudente?
= Ainda é preciso avaliar na tarefa real e em casos difíceis, pois a média pode esconder degradações raras.
- O modelo está garantidamente equivalente ao original em todas as tarefas, pois a perplexidade resume a qualidade.
- A quantização não pode ter causado nenhum efeito, em nenhum caso, já que a perplexidade praticamente não mudou.
- A perplexidade média substitui qualquer outra avaliação.
- O modelo agora pode ser considerado seguro contra alucinações.
J: A perplexidade é uma média; a qualidade na tarefa e em subgrupos precisa ser verificada separadamente.

MC: O que a destilação de conhecimento (Hinton et al., 2015) usa como alvo para treinar o aluno?
= As saídas, em geral suavizadas por uma temperatura, produzidas por um modelo professor.
- Apenas os rótulos duros do conjunto original, sem nenhuma outra informação vinda de um professor.
- Os pesos do professor, copiados diretamente para o aluno antes de qualquer treino adicional.
- Somente os gradientes do aluno, sem professor.
- Um conjunto de regras escritas à mão.
J: As probabilidades suaves informam sobre a semelhança entre classes, o que enriquece o treino do aluno.

MC: Qual o efeito de usar uma temperatura $T>1$ ao calcular as probabilidades do professor na destilação?
= A distribuição fica mais suave, realçando as probabilidades das classes não vencedoras.
- A distribuição fica mais concentrada na classe mais provável, aproximando-se de um vetor one-hot.
- O professor passa a escolher sempre a mesma classe, independentemente do exemplo apresentado.
- O número de parâmetros do aluno diminui.
- A perda do aluno deixa de depender das saídas do professor.
J: Dividir os logits por $T$ achata o softmax, tornando visíveis as relações entre as classes.

MC: O que uma mistura de especialistas (MoE) reduz, em comparação com um modelo denso de mesmo número total de parâmetros?
= O cálculo por token, pois só alguns especialistas são ativados; a memória ainda precisa guardar todos.
- A memória necessária para guardar os parâmetros, na mesma proporção.
- O número total de parâmetros, que fica igual ao de um especialista.
- A necessidade de um roteador.
- O desbalanceamento de carga, que desaparece.
J: Os parâmetros ativos por token são uma fração do total, mas todos os especialistas precisam estar disponíveis.

MC: Qual problema típico surge no roteador de uma mistura de especialistas?
= O desbalanceamento de carga, com alguns especialistas recebendo muito mais tokens que outros.
- A impossibilidade de escolher mais de um especialista por token, o que força o uso de um só.
- O aumento do vocabulário a cada token.
- A perda da máscara causal na atenção, que deixa o modelo enxergar tokens futuros durante o treino.
- A necessidade de reiniciar o treino a cada token.
J: Um especialista sobrecarregado limita a velocidade do conjunto; o treino costuma incluir mecanismos para equilibrar a carga.

MC: Para que o cache de prefixo funcione, o que é necessário?
= Que o início do prompt seja idêntico entre as requisições, e por isso o texto estável vai antes do variável.
- Que o final do prompt seja idêntico, com o texto estável depois do variável.
- Que as perguntas tenham o mesmo significado, ainda que escritas de forma diferente.
- Que a temperatura seja igual a zero em todas as chamadas.
- Que o usuário use sempre o mesmo navegador.
J: O cache KV de um prefixo só é reaproveitável se os tokens do prefixo forem exatamente os mesmos.

MC: Qual a diferença essencial entre o cache de prefixo e o cache semântico de respostas?
= O de prefixo reaproveita cálculo e mantém o resultado idêntico; o semântico devolve uma resposta pronta a um pedido apenas parecido e pode errar.
- O de prefixo guarda respostas prontas, e o semântico guarda pesos do modelo.
- Os dois são idênticos, mudando apenas o nome.
- O semântico nunca altera a resposta, e o de prefixo sempre altera.
- O de prefixo só funciona fora de servidores de inferência.
J: O primeiro apenas evita recalcular; o segundo substitui o cálculo por uma resposta de outro pedido.

MC: Qual o principal risco do cache semântico de respostas?
= Reaproveitar uma resposta de um pedido parecido, mas que exige resposta diferente (outro plano, outro número, outro usuário).
- Aumentar sempre a latência de todos os pedidos.
- Impedir o uso de qualquer outro tipo de cache.
- Tornar o modelo menos preciso em todas as tarefas.
- Fazer o modelo esquecer o treinamento.
J: Embeddings capturam o assunto, mas distinguem mal detalhes como números, nomes e datas.

MC: O que acontece, em geral, ao reduzir o limiar de similaridade $\tau$ de um cache semântico?
= A taxa de acerto sobe, mas a fração de respostas reaproveitadas erradas também tende a subir.
- A taxa de acerto cai e a de erro também cai, pois o cache passa a aceitar menos pedidos como equivalentes.
- A taxa de erro cai a zero.
- Nada muda na taxa de acerto.
- O cache passa a ser exato, devolvendo respostas idênticas às que o modelo geraria a cada pedido.
J: Um limiar menor aceita pedidos menos parecidos como equivalentes.

MC: Por que o lote estático desperdiça capacidade quando os comprimentos de saída são muito variados?
= Porque o grupo só termina quando o pedido mais longo termina, e os espaços dos que acabaram antes ficam ociosos.
- Porque cada pedido do grupo precisa de um modelo diferente.
- Porque o lote estático sempre usa menos memória.
- Porque os pedidos curtos são recusados.
- Porque o lote estático impede o uso do cache KV.
J: Espaços vazios não podem ser reaproveitados até o grupo inteiro terminar.

MC: O que caracteriza o lote contínuo (continuous batching)?
= O lote é reavaliado a cada passo, e um novo pedido entra assim que outro termina.
- Os pedidos esperam um número fixo de segundos antes de cada grupo ser enviado ao acelerador, sempre completo.
- O modelo é treinado continuamente durante o atendimento.
- Todos os pedidos são concatenados em um único prompt gigante, processado de uma só vez pelo modelo.
- Os pedidos longos são sempre recusados.
J: Isso mantém o acelerador ocupado, aumentando a utilização e a vazão.

MC: Em uma fila M/M/1 com $\lambda=0{,}8$ pedido/s e $\mu=1$ pedido/s, qual o tempo médio no sistema $W=1/(\mu-\lambda)$?
= 5 segundos.
- 0,8 segundo, que é só a taxa de chegada λ, e não o tempo médio no sistema.
- 1,25 segundo, que é 1/λ, o intervalo médio entre chegadas, e não $W$.
- 4 segundos, valor que corresponde ao número médio de pedidos no sistema, e não ao tempo.
- 0,2 segundo.

MC: O que ocorre com a latência de um sistema de filas quando a utilização $\rho$ se aproxima de 1?
= Ela cresce muito rapidamente, e a fila pode crescer sem limite se $\rho\ge1$.
- Ela diminui, pois o sistema fica mais eficiente quando os aceleradores trabalham quase sem folga.
- Ela permanece constante, qualquer que seja a carga, desde que o hardware seja o mesmo.
- Ela se torna exatamente igual ao tempo de atendimento.
- Ela passa a depender apenas do tamanho do vocabulário.
J: Perto da capacidade, pequenas variações de chegada geram filas longas.

MC: O que a decodificação especulativa (Leviathan et al., 2023) preserva?
= A distribuição de saída do modelo grande, mudando apenas o tempo gasto.
- Apenas a média da qualidade, aceitando que as amostras individuais sejam diferentes das do modelo grande.
- O vocabulário do modelo pequeno, que substitui o do grande durante toda a geração dos tokens.
- A temperatura, que passa a ser fixa em zero.
- O cache KV, que deixa de ser necessário.
J: A regra de aceitação e a amostragem do resíduo garantem que as amostras venham da distribuição do alvo.

MC: Em um roteador entre um modelo barato e um caro, o que decide se um pedido é escalonado?

DISC[P]: Implemente `quantizar_grupos(W, bits, grupo)` que quantize uma matriz em grupos de valores consecutivos (escala simétrica por grupo) e devolva a matriz reconstruída. Meça o erro relativo para grupos de 256, 64 e 16 em pesos sintéticos com alguns valores atípicos.
CODE:
import numpy as np

def quantizar_grupos(W, bits=4, grupo=64):
    qmax = 2 ** (bits - 1) - 1
    Wg = W.reshape(-1, grupo)
    s = np.abs(Wg).max(axis=1, keepdims=True) / qmax
    s = np.where(s == 0, 1.0, s)
    q = np.clip(np.round(Wg / s), -qmax, qmax)
    return (q * s).reshape(W.shape)

rng = np.random.default_rng(0)
W = rng.normal(0, 0.02, (128, 256))
W[:, ::50] *= 25
erros = {}
for g in (256, 64, 16):
    Wq = quantizar_grupos(W, 4, g)
    erros[g] = np.sqrt(np.mean((W - Wq) ** 2)) / np.sqrt(np.mean(W ** 2))
    print(g, round(float(erros[g]), 4))
assert erros[16] < erros[64] < erros[256]
ENDCODE

DISC[P]: Simule uma fila M/M/1 com `numpy` (chegadas de Poisson, serviços exponenciais) para $\mu=1$ e $\lambda\in\{0{,}5; 0{,}8\}$ e compare o tempo médio no sistema com $1/(\mu-\lambda)$.
CODE:
import numpy as np

def simular_mm1(lam, mu, n=100000, seed=0):
    rng = np.random.default_rng(seed)
    chegada = np.cumsum(rng.exponential(1 / lam, n))
    servico = rng.exponential(1 / mu, n)
    saida = np.empty(n)
    anterior = 0.0
    for i in range(n):
        inicio = max(chegada[i], anterior)
        anterior = inicio + servico[i]
        saida[i] = anterior
    lat = saida - chegada
    return lat[n // 20:].mean()

for lam in (0.5, 0.8):
    sim = simular_mm1(lam, 1.0)
    teo = 1 / (1.0 - lam)
    print(lam, round(float(sim), 2), round(teo, 2))
    assert abs(sim - teo) / teo < 0.15
ENDCODE

import numpy as np

def tokens_esperados(alfa, gama):
    return (1 - alfa ** (gama + 1)) / (1 - alfa)

def ganho(alfa, gama, c):
    return tokens_esperados(alfa, gama) / (gama * c + 1)

def melhor_gama(alfa, c, gamas=range(1, 33)):
    return max(gamas, key=lambda g: ganho(alfa, g, c))

for a in (0.5, 0.8, 0.95):
    g = melhor_gama(a, 0.05)
    print(a, g, round(ganho(a, g, 0.05), 2))
assert melhor_gama(0.5, 0.05) < melhor_gama(0.95, 0.05)

DISC[P]: Implemente `psi(ref, atual, categorias)` com suavização para proporções zero e use-o para comparar duas amostras de rótulos, uma sem deriva e outra com uma categoria três vezes mais frequente.
CODE:
import numpy as np

def psi(ref, atual, categorias, piso=1e-4):
    ref, atual = np.asarray(ref), np.asarray(atual)
    e = np.array([max(np.mean(ref == c), piso) for c in categorias])
    a = np.array([max(np.mean(atual == c), piso) for c in categorias])
    return float(np.sum((a - e) * np.log(a / e)))

cats = ["a", "b", "c", "d"]
rng = np.random.default_rng(0)
ref = rng.choice(cats, 2000)
sem = rng.choice(cats, 2000)
com = rng.choice(cats, 2000, p=[0.5, 0.5 / 3, 0.5 / 3, 0.5 / 3])    # 'a' passa de 25% a 50% (o dobro)
print(round(psi(ref, sem, cats), 4), round(psi(ref, com, cats), 4))
assert psi(ref, sem, cats) < 0.02 < psi(ref, com, cats)
ENDCODE
