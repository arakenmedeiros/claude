MC: O que é um embedding de texto, no sentido deste capítulo?
= Um vetor de números que representa um trecho de texto, de modo que textos usados em contextos parecidos fiquem próximos.
- Uma tradução automática do texto para outro idioma.
- Uma lista das palavras mais frequentes de um documento.
- Um resumo escrito pelo modelo de linguagem.
- Um código de barras que identifica o arquivo.
J: O embedding é um vetor cuja proximidade reflete semelhança de uso, e não identidade de significado.

MC: Qual a diferença entre uma representação esparsa e uma densa?
= A esparsa tem uma dimensão por palavra, quase toda zerada; a densa tem poucas dimensões aprendidas, sem zeros.
- A esparsa é sempre mais precisa em qualquer tarefa; a densa nunca reconhece sinônimos nem paráfrases, por mais que seja treinada.
- A esparsa usa números negativos; a densa usa só positivos.
- A esparsa guarda apenas imagens; a densa guarda apenas texto.
- Não há diferença; são nomes de duas marcas.
J: Contagens e TF-IDF são esparsos (626 dimensões na base, 97% de zeros); a LSA e os codificadores neurais são densos.

MC: Como a análise semântica latente (LSA) obtém vetores densos?
= Aplica uma decomposição em valores singulares à matriz de TF-IDF e mantém poucas dimensões.
- Treina uma rede neural que gera texto palavra por palavra, usando o documento inteiro como contexto de cada previsão.
- Traduz cada documento para vetores de imagem.
- Ordena os documentos pelo tamanho do arquivo.
- Pede a um usuário que classifique cada documento.
J: A SVD truncada agrupa palavras que aparecem nos mesmos documentos, aproximando textos com vocabulários diferentes.

MC: O que o cosseno entre dois vetores mede?
= O ângulo entre eles, isto é, a semelhança de direção, independentemente do comprimento.
- A diferença entre as somas de suas coordenadas.
- A distância entre as pontas dos vetores no espaço, que cresce quando o comprimento dos vetores aumenta.
- O número de palavras em comum, sempre.
- O tamanho do documento maior entre os dois, medido pelo número de palavras que ele contém.
J: O cosseno divide o produto interno pelo produto das normas, eliminando o efeito do comprimento.

MC: Por que o produto interno pode favorecer um documento longo em vetores não normalizados?
= Porque o valor cresce com a norma do vetor, e um texto longo tende a ter contagens maiores.
- Porque o produto interno ignora as palavras da consulta.
- Porque documentos longos têm menos palavras.
- Porque o produto interno só funciona com números negativos.
- Porque documentos longos são sempre mais relevantes.
J: Sem normalizar, a magnitude entra no valor; no experimento, o documento artificial longo ficou no topo.

MC: Se todos os vetores têm norma 1, o que se pode afirmar sobre as três medidas de similaridade?
= Produto interno, cosseno e distância euclidiana produzem a mesma ordem de documentos.
- O produto interno passa a ser sempre zero, porque os vetores unitários ficam ortogonais entre si.
- A distância euclidiana passa a ser sempre 1.
- O cosseno deixa de poder ser calculado, pois o denominador da fórmula passa a valer zero nesse caso.
- As três medidas ficam em ordem inversa umas das outras.
J: Com norma 1, a distância ao quadrado vale 2 menos 2 vezes o cosseno, e o produto interno é o cosseno.

MC: Qual é o erro silencioso mais típico ao usar embeddings em produção?
= Indexar com um modelo ou medida e consultar com outro, produzindo comparações sem sentido.
- Guardar os vetores em arquivo no disco, em vez de mantê-los apenas na memória durante a execução.
- Calcular o cosseno com NumPy em vez de usar uma biblioteca especializada de busca vetorial.

- Usar mais de uma consulta de teste.
J: Espaços de modelos diferentes não são comparáveis; a mistura não gera erro, só resultados ruins.

MC: O que significa hit@3 igual a 0,913 em um conjunto de consultas?
= Em 91,3% das consultas, ao menos um documento relevante aparece entre os três primeiros.
- Em 91,3% das consultas, os três primeiros documentos são todos relevantes, sem nenhuma exceção entre eles.
- O sistema demora 0,913 segundo para responder.
- Em 91,3% dos documentos, há três consultas.
- O terceiro colocado é relevante em todas as consultas do conjunto, e os dois primeiros podem não ser.
J: O hit@k é binário por consulta: há ou não há algum relevante nos k primeiros.

MC: Em que o recall@k difere do hit@k?
= O recall@k mede a fração dos relevantes achados nos k primeiros; o hit@k só verifica se há algum.
- O recall@k considera só o primeiro colocado da lista, ignorando os demais documentos recuperados pelo sistema.
- O recall@k é sempre igual ao hit@k.
- O hit@k usa a ordem alfabética dos documentos.
- O recall@k mede o tempo de resposta do sistema, enquanto o hit@k mede a memória ocupada pelo índice vetorial.
J: Com vários relevantes, recuperar um de dois dá recall de 0,5 e hit igual a 1.

MC: O que o MRR (rank recíproco médio) recompensa?
= Colocar o primeiro documento relevante o mais perto possível do topo da lista.
- Recuperar todos os relevantes, onde quer que estejam.
- Recuperar todos os relevantes, onde quer que estejam na lista, sem se importar com a posição de cada um.
- Usar o menor número possível de dimensões nos vetores, reduzindo a memória ocupada pelo índice.
- Ter documentos curtos.
J: Para cada consulta vale 1 dividido pela posição do primeiro relevante; depois se faz a média.

MC: Por que o nDCG usa um desconto logarítmico pela posição?
= Para valorizar mais os relevantes nas primeiras posições do que os que aparecem no fim da lista.
- Para eliminar os documentos relevantes que aparecem no fim da lista, deixando apenas os primeiros colocados.
- Para tornar a métrica igual ao recall@k, ignorando a ordem em que os documentos aparecem na lista.
- Para ordenar os documentos alfabeticamente.
- Para medir a memória do índice.
J: Cada relevante contribui com 1/log2(posição+1), e o total é dividido pelo valor do ranking ideal.

MC: O que o bootstrap sobre as consultas permite estimar?

- A velocidade do índice vetorial.
- A quantidade de memória da coleção.
- O número de palavras do vocabulário.
- O melhor valor de k para o RRF, sem dados.
J: Os quantis das médias reamostradas formam o intervalo de confiança; com 46 consultas, ele é largo.

MC: Por que comparar dois métodos pela diferença pareada, com reamostragem das mesmas consultas?
= Porque as consultas são as mesmas nos dois métodos, e a diferença por consulta captura essa dependência.
- Porque assim o intervalo fica sempre mais estreito, qualquer que seja o resultado e o número de consultas usado.
- Porque dispensa o uso de consultas de teste.
- Porque elimina a necessidade de calcular as métricas de cada método separadamente em cada consulta.
- Porque garante que o método novo é melhor.
J: Reamostrar a diferença por consulta respeita o pareamento; se o intervalo inclui zero, não há evidência de diferença.

MC: O que significa dizer que o BM25 "satura" a frequência dos termos?
= Que a contribuição de um termo cresce cada vez menos a cada nova ocorrência no documento.
- Que o termo deixa de ser considerado depois de aparecer uma vez no documento, ignorando as demais ocorrências.
- Que documentos curtos recebem pontuação zero.
- Que a pontuação diminui à medida que o termo aparece mais vezes.
- Que o BM25 exige vetores de norma 1 e, por isso, só pode ser aplicado a representações densas.
J: A fração f(k1+1)/(f+k1(...)) tem limite quando f cresce.

MC: Em qual situação a busca lexical tende a falhar?
= Quando a consulta usa palavras diferentes das do documento, como em uma paráfrase.
- Quando a consulta repete exatamente as palavras do documento, o que torna a pontuação lexical alta demais.
- Quando o documento tem um título.
- Quando há muitos documentos curtos na coleção, pois a busca lexical só funciona com textos longos.
- Quando a consulta contém um número.
J: Sem palavras em comum, a pontuação é zero, mesmo que o sentido coincida.

MC: O que o RRF calcula para cada documento?
= A soma, sobre os métodos, de 1 dividido por (k mais a posição do documento no ranking do método).
- A média das pontuações brutas dos métodos, depois de normalizadas para a mesma escala entre zero e um.
- O maior cosseno entre todos os métodos.
- O número de palavras em comum com a consulta, dividido pelo total de palavras do documento recuperado.
- A diferença entre a primeira e a última posição.
J: Só usa posições, e portanto dispensa calibrar escalas de pontuação diferentes.

MC: Qual o efeito de usar um k pequeno no RRF?
= O topo dos rankings pesa muito mais do que as posições seguintes.
- Todas as posições passam a valer exatamente o mesmo, de modo que a ordem dos rankings deixa de importar.
- Os documentos do fim da lista passam a valer mais.
- O RRF deixa de poder ser calculado, porque o denominador da fórmula se anula quando k é pequeno.
- A fusão passa a depender de escalas de pontuação.
J: Com k pequeno, 1/(k+1) é bem maior que 1/(k+2); com k grande, o desconto é suave.

DISC[C]: Descreva a diferença entre bi-encoder e cross-encoder e explique por que se usam em dois estágios.
R: O bi-encoder codifica consulta e documento separadamente; os vetores dos documentos são pré-calculados e a busca é rápida, mas a comparação final é só um cosseno. DISC[C]: Por que não se indexa, em geral, um documento longo como um único vetor? Que decisões envolve a segmentação em pedaços?

DISC[P]: Implemente `knn_cosseno(q, D, k)` em NumPy, que devolva os índices dos k documentos de maior cosseno com a consulta, em ordem decrescente. Teste com quatro vetores.

import numpy as np

def knn_cosseno(q, D, k):
    q = np.asarray(q, float); D = np.asarray(D, float)
    nq = np.linalg.norm(q); nD = np.linalg.norm(D, axis=1)
    cos = (D @ q) / np.where(nD * nq == 0, 1.0, nD * nq)
    return list(np.argsort(-cos, kind="stable")[:k])

CODE:
def rrf(rankings, k=60):
    pont = {}
    for rk in rankings:
        for pos, d in enumerate(rk, 1):
            pont[d] = pont.get(d, 0.0) + 1.0 / (k + pos)
    return sorted(pont, key=lambda d: (-pont[d], d)), pont

def dividir(texto, tamanho, sobreposicao=0):
    if sobreposicao >= tamanho:
        raise ValueError("a sobreposição deve ser menor que o tamanho")
    palavras = texto.split()
    passo = tamanho - sobreposicao
    janelas = []
    for i in range(0, len(palavras), passo):
        janelas.append(" ".join(palavras[i:i + tamanho]))
        if i + tamanho >= len(palavras):
            break
    return janelas

import hashlib

def sha(t):
    return hashlib.sha256(t.encode("utf-8")).hexdigest()

def a_reindexar(registro, documentos):
    novos = [d for d in documentos if d not in registro]
    alterados = [d for d, t in documentos.items() if d in registro and registro[d] != sha(t)]
    removidos = [d for d in registro if d not in documentos]
    return novos, alterados, removidos
