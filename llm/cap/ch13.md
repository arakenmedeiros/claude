## 13.5 O que é uma modalidade

Uma **modalidade** é um tipo de dado com sua própria estrutura e forma de percepção: texto (sequência de símbolos), imagem (grade de pixels), áudio (variação de pressão no tempo), vídeo (sequência de imagens com som), tabela, mapa. Um modelo é **unimodal** quando lida com uma só, e **multimodal** quando lê ou produz mais de uma (por exemplo, recebe imagem e pergunta em texto e responde em texto).

Por baixo, todas são **arrays de números**. O que muda é a forma do array e o tipo de regularidade que ele contém:

| Modalidade | Array típico | Estrutura a aproveitar |
|---|---|---|
| Texto | sequência de ids de tokens | ordem, gramática, significado |
| Imagem | altura × largura × canais | vizinhança espacial, bordas, formas |
| Áudio | amostras ao longo do tempo | periodicidade, frequências |
| Vídeo | quadros × altura × largura × canais | movimento, continuidade temporal |
| Documento digitalizado | imagem de página (ou texto + coordenadas) | layout, tabelas, ordem de leitura |

A estratégia geral dos modelos atuais é **converter cada modalidade em uma sequência de vetores** (embeddings) e deixar um Transformer (Capítulo 5) operar sobre elas. As seções seguintes mostram como.

:::intuicao Intuição: um tradutor para cada idioma, um idioma comum
Imagine uma reunião com pessoas que falam idiomas diferentes. Cada uma tem um intérprete que traduz para um idioma comum da sala. Na IA multimodal, o "intérprete" é o **codificador** de cada modalidade, e o "idioma comum" é o **espaço de embeddings**. Se o intérprete traduz mal, a conversa inteira sai prejudicada, por melhor que seja o resto do sistema.
:::

## 13.6 Imagem como números

Uma imagem digital é uma grade de **pixels**. Em tons de cinza, cada pixel é um número (a intensidade); em cores, são **três números por pixel**, um para cada **canal** (vermelho, verde e azul, RGB). Uma imagem de $H$ pixels de altura e $L$ de largura vira um array de formato $(H, L)$ em cinza, ou $(H, L, 3)$ em cores. Vamos olhar uma imagem real e pequena: os dígitos escritos à mão do conjunto `load_digits` do scikit-learn (Pedregosa et al., 2011), com 8×8 pixels e intensidades de 0 a 16.

```python
import numpy as np
from sklearn.datasets import load_digits

dg = load_digits()
imagens, rotulos = dg.images, dg.target
print("conjunto:", imagens.shape, "| tipo:", imagens.dtype)
print("pixel mínimo e máximo:", imagens.min(), imagens.max())
print("rótulo da imagem 0:", rotulos[0])
print(imagens[0].astype(int))
```

```python+
cinza = imagens[0] / 16                                          # normaliza para [0, 1]
rgb = np.stack([cinza, 0.5 * cinza, 0.2 * cinza], axis=-1)       # três canais (R, G, B): tingimos de laranja
print("formato RGB (altura, largura, canais):", rgb.shape)
print("pixel (2, 3) nos canais R, G, B:", rgb[2, 3].round(3))
luminancia = rgb @ np.array([0.299, 0.587, 0.114])               # pesos usuais para converter RGB em cinza
print("formato após converter para cinza:", luminancia.shape)
for h, l in [(8, 8), (224, 224), (1024, 768)]:
    print(f"imagem {h}x{l} em RGB: {h * l * 3} números")
```

Dois pontos práticos. Primeiro, o **tamanho cresce depressa**: uma foto de celular tem milhões de números, muito mais que uma frase. Segundo, **o pixel isolado quase não diz nada**: o que importa são os padrões entre vizinhos (bordas, curvas). Redes convolucionais exploravam essa vizinhança por filtros; o ViT (próxima seção) a explora de outro modo.

## 13.7 Patches e embeddings de imagem: a ideia do ViT

Um Transformer lê uma **sequência** de vetores. Como transformar uma grade em sequência? Dosovitskiy et al. (2021) propuseram, no **Vision Transformer (ViT)**, dividir a imagem em **patches** (blocos) quadrados de lado $p$, "achatar" cada bloco em um vetor, projetá-lo linearmente para a dimensão do modelo e somar uma informação de **posição**. A frase-título do artigo resume: "uma imagem vale 16×16 palavras", pois os blocos fazem o papel de tokens.

Para uma imagem $H\times L$ com patches $p\times p$:

$$N=\frac{H}{p}\cdot\frac{L}{p},\qquad \mathbf{z}_k=\mathbf{W}\,\mathrm{vec}(\text{patch}_k)+\mathbf{pos}_k,\quad k=1,\dots,N.$$

Aqui $\mathrm{vec}(\cdot)$ achata o bloco em um vetor de $p^2$ números (por canal), $\mathbf{W}$ é a matriz de projeção e $\mathbf{pos}_k$ é o vetor de posição do bloco $k$. Costuma-se acrescentar também um token especial de classificação, cujo estado final resume a imagem. No ViT real, $\mathbf{W}$ é **aprendida** junto com o resto da rede; aqui, para enxergar o mecanismo sem treinar uma rede, usaremos como $\mathbf{W}$ as direções principais (PCA) dos patches.

```python+
from llmdidatico.multimodal import patches, posicao_senoidal

rng = np.random.default_rng(0)
idx = rng.permutation(len(rotulos)); tr, te = idx[:1300], idx[1300:]       # divisão treino/teste usada no capítulo
img = imagens[0] / 16
P = patches(img, 4)
print("patches 4x4:", P.shape, "(N patches, p*p valores)  |  patches 2x2:", patches(img, 2).shape)

Ptr = np.concatenate([patches(imagens[i] / 16, 4) for i in tr])           # todos os patches do treino
mu = Ptr.mean(0)
_, s, Vt = np.linalg.svd(Ptr - mu, full_matrices=False)
d = 8
W = Vt[:d].T                                                              # projeção 16 -> 8 (PCA)
print(f"variância dos patches explicada por {d} componentes: {(s[:d]**2).sum() / (s**2).sum():.3f}")

E = (P - mu) @ W                                                          # embeddings de patch (4, 8)
pos = posicao_senoidal(len(P), d)
cls = rng.normal(0, 0.1, (1, d))                                          # token de classificação (aqui, fixo)
seq = np.vstack([cls, E + pos])
print("sequência entregue ao Transformer:", seq.shape, "(1 token especial + 4 patches)")

def atencao_media(X):                                                     # autoatenção sem parâmetros, saída média
    A = X @ X.T / np.sqrt(X.shape[1]); A = np.exp(A - A.max(1, keepdims=True)); A /= A.sum(1, keepdims=True)
    return (A @ X).mean(0)
ordem = np.array([3, 1, 0, 2])                                            # embaralha os patches
Eb = (P[ordem] - mu) @ W
print("sem posição, diferença após embaralhar:", np.abs(atencao_media(E) - atencao_media(Eb)).max().round(6))
print("com posição, diferença após embaralhar:", np.abs(atencao_media(E + pos) - atencao_media(Eb + pos)).max().round(6))
```

O último teste explica por que a posição é indispensável: a atenção **sem posição não percebe a ordem** (embaralhar os patches não muda a saída), e uma imagem com os blocos trocados de lugar seria "a mesma" para o modelo. Somar $\mathbf{pos}_k$ devolve a informação de "onde" cada bloco estava. No ViT original, as posições são vetores aprendidos; aqui usamos a forma senoidal do Transformer original (Vaswani et al., 2017) por não exigir treino.

![f13_patches]([D:figs_cap13.py] Um dígito dividido em patches 4×4 (esquerda), os quatro embeddings de 8 dimensões após a projeção PCA (centro) e a mesma sequência com a posição somada (direita). Dados reais do `load_digits`; projeção por PCA, e não aprendida como no ViT.)

:::cuidado Cuidado com esta interpretação
O tamanho do patch é um compromisso. Patches grandes geram poucos tokens (barato), mas perdem detalhe fino; patches pequenos preservam detalhe, mas multiplicam os tokens, e o custo da atenção cresce com o quadrado do número deles. Esse número de tokens é também o que se paga em serviços (Seção 13.14).
:::

## 13.8 Aprendizado contrastivo imagem–texto: a ideia do CLIP

### 13.8.1 A ideia

Como fazer imagem e texto "morarem" no mesmo espaço de embeddings, de modo que a foto de um cachorro fique perto da frase "um cachorro correndo"? Radford et al. (2021) treinaram o **CLIP** com um grande número de pares imagem–legenda coletados da internet. Há **dois codificadores** (um para imagens e outro para textos). Em cada lote de $n$ pares, o treino empurra para **perto** os embeddings do par correto e para **longe** os dos $n^2-n$ pares incorretos. Não há rótulos de classe: a legenda é a supervisão.

### 13.8.2 A perda contrastiva simétrica (InfoNCE com temperatura)

Sejam $\mathbf{u}_i$ e $\mathbf{t}_j$ os embeddings normalizados (norma 1) da imagem $i$ e do texto $j$ no lote. A matriz de similaridades escalada pela **temperatura** $\tau>0$ é

$$S_{ij}=\frac{\mathbf{u}_i^{\top}\mathbf{t}_j}{\tau}.$$

Para cada imagem $i$, queremos que o texto $i$ tenha a maior pontuação entre os $n$ textos; isso é uma classificação com softmax sobre a linha $i$. Para cada texto $j$, o mesmo vale sobre a coluna $j$. A perda simétrica é a média das duas entropias cruzadas:

$$\mathcal{L}=\frac{1}{2n}\sum_{i=1}^{n}\Big[-\log\frac{e^{S_{ii}}}{\sum_{j}e^{S_{ij}}}\Big]+\frac{1}{2n}\sum_{j=1}^{n}\Big[-\log\frac{e^{S_{jj}}}{\sum_{i}e^{S_{ij}}}\Big].$$

Se os embeddings fossem aleatórios, cada softmax seria quase uniforme e a perda valeria cerca de $\ln n$. A temperatura controla a **nitidez**: $\tau$ pequeno amplifica diferenças entre similaridades (distribuição afiada, punindo com força os "quase acertos" negativos mais parecidos), e $\tau$ grande achata o softmax. No CLIP original a temperatura é um parâmetro aprendido; aqui a trataremos como hiperparâmetro para estudar seu efeito.

:::saibamais Saiba mais: o gradiente da perda
Seja $\mathbf{P}^{\text{lin}}=\text{softmax}_{\text{linhas}}(S)$ e $\mathbf{P}^{\text{col}}=\text{softmax}_{\text{colunas}}(S)$. Para a entropia cruzada com softmax, o gradiente em relação aos logits é "probabilidade menos alvo", de modo que
$$\frac{\partial\mathcal{L}}{\partial S}=\frac{1}{2n}\Big[(\mathbf{P}^{\text{lin}}-\mathbf{I})+(\mathbf{P}^{\text{col}}-\mathbf{I})\Big].$$
Como $S=\mathbf{U}\mathbf{T}^{\top}/\tau$, temos $\partial\mathcal{L}/\partial\mathbf{U}=\frac{1}{\tau}\frac{\partial\mathcal{L}}{\partial S}\mathbf{T}$ e $\partial\mathcal{L}/\partial\mathbf{T}=\frac{1}{\tau}\big(\frac{\partial\mathcal{L}}{\partial S}\big)^{\top}\mathbf{U}$. Resta atravessar a normalização $\mathbf{u}=\mathbf{z}/\lVert\mathbf{z}\rVert$: o gradiente em relação a $\mathbf{z}$ é $(\mathbf{g}-\mathbf{u}(\mathbf{u}^{\top}\mathbf{g}))/\lVert\mathbf{z}\rVert$, onde $\mathbf{g}=\partial\mathcal{L}/\partial\mathbf{u}$ (a parte radial é removida, pois a perda só depende da direção). Com codificadores lineares $\mathbf{Z}_{\text{img}}=\mathbf{X}_{\text{img}}\mathbf{W}_{\text{img}}$, o gradiente dos pesos é $\mathbf{X}^{\top}\,\partial\mathcal{L}/\partial\mathbf{Z}$. É exatamente isso que o código do módulo `llmdidatico.multimodal` implementa, e verificamos o resultado contra diferenças finitas.
:::

### 13.8.3 Pares sintéticos e codificadores lineares

Montamos pares **imagem de dígito ↔ descrição textual**. A descrição diz o dígito e dois atributos calculados da própria imagem (quantidade de "tinta" e lado onde está o centro de massa), com três modelos de frase, por exemplo "dígito sete, traço leve, à esquerda". O codificador de imagem é linear sobre os 64 pixels; o de texto é linear sobre um **saco de palavras** (contagem de cada palavra do vocabulário). Ambos produzem vetores de 16 dimensões. O treino usa o gradiente manual descrito acima.

```python+
from llmdidatico.multimodal import (descricao, vocabulario, bow, infonce_simetrica,
                                    treinar_contrastivo, recall_em_k, PALAVRAS)

X = imagens.reshape(len(imagens), -1) / 16                     # 64 pixels por imagem, em [0, 1]
med = np.median(X.sum(1))
rng_t = np.random.default_rng(1)
legendas = [descricao(rotulos[i], imagens[i] / 16, rng_t, med) for i in range(len(rotulos))]
voc = vocabulario(legendas)
T = bow(legendas, voc)
chaves = np.array([f"{rotulos[i]}|" + ",".join(c.split(",")[1:]) for i, c in enumerate(legendas)])   # chave exata: dígito + atributos
print("exemplos de legendas:", legendas[:3])
print("tamanho do vocabulário:", len(voc), "| legendas distintas:", len(set(legendas)))

# verificação do gradiente por diferenças finitas
g = np.random.default_rng(0); A = g.normal(size=(5, 4)); B = g.normal(size=(5, 4))
L0, dA, dB, _ = infonce_simetrica(A, B, 0.3)
A2 = A.copy(); A2[2, 1] += 1e-6
print("gradiente analítico:", round(dA[2, 1], 6), "| numérico:", round((infonce_simetrica(A2, B, 0.3)[0] - L0) / 1e-6, 6))
print("perda esperada com embeddings ao acaso (ln 64):", round(float(np.log(64)), 3))
```
