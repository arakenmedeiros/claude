## 1.5 O que é um modelo de linguagem

### 1.5.1 Uma tarefa simples: prever o que vem depois

Complete a frase: "Hoje à noite vou estudar para a ______".

Você provavelmente pensou em "prova". Talvez em "aula" ou "reunião". Dificilmente pensou em "geladeira". Sem perceber, você atribuiu **graus de expectativa** às palavras possíveis. Isso é, em essência, o que faz um **modelo de linguagem**.

:::intuicao Intuição
Um modelo de linguagem é uma máquina de **expectativas sobre texto**. Dado o que já foi escrito, ele diz o quanto cada continuação possível é plausível. Escrever uma frase inteira é repetir esse passo muitas vezes: prever, escolher, acrescentar, prever de novo.
:::

Dois termos precisam ser definidos agora.

- **Token:** a unidade de texto que o modelo manipula. Pode ser uma palavra, um pedaço de palavra ou até um caractere. O Capítulo 3 explica como o texto é dividido em tokens. Por ora, pense em "palavra ou pedaço de palavra".
- **Modelo de linguagem:** um modelo que atribui uma probabilidade a sequências de tokens, ou, de forma equivalente, que estima a probabilidade do próximo token dado o contexto anterior.

Escrevemos isso como $P(w_t \mid w_1, \ldots, w_{t-1})$. Lê-se: "a probabilidade de o token $w_t$ aparecer na posição $t$, **dado** que os tokens anteriores foram $w_1, \ldots, w_{t-1}$".

### 1.5.2 A regra da cadeia e a probabilidade de uma frase

Podemos calcular a probabilidade de uma frase inteira multiplicando as probabilidades de cada passo. Essa é a **regra da cadeia** da probabilidade.

$$ P(w_1, w_2, \ldots, w_n) = \prod_{t=1}^{n} P(w_t \mid w_1, \ldots, w_{t-1}) $$

O símbolo $\prod$ significa "produto": multiplique todos os termos de $t=1$ até $t=n$.

:::passo Passo a passo: calculando a probabilidade de uma frase
Considere a frase "o estudante lê o livro" e **suponha** (valores hipotéticos, só para ilustrar) que um modelo atribua:

1. $P(\text{o}) = 0{,}30$
2. $P(\text{estudante} \mid \text{o}) = 0{,}40$
3. $P(\text{lê} \mid \text{o estudante}) = 0{,}25$
4. $P(\text{o} \mid \text{o estudante lê}) = 0{,}50$

Multiplicando: $0{,}30 \times 0{,}40 \times 0{,}25 \times 0{,}50 = 0{,}015$. A probabilidade da frase é 1,5%.
:::

Há um problema prático: multiplicar muitos números pequenos produz um número minúsculo, que o computador não representa bem. A solução é trabalhar com **logaritmos**, que transformam produtos em somas.

$$ \ln P(w_1, \ldots, w_n) = \sum_{t=1}^{n} \ln P(w_t \mid w_1, \ldots, w_{t-1}) $$

No exemplo, $\ln 0{,}015 \approx -4{,}20$. Dividindo pelo número de tokens ($n=4$ considerando os quatro passos calculados), obtemos $-1{,}05$ por token. Elevando $e$ ao oposto desse valor, chegamos a $e^{1{,}05} \approx 2{,}86$. Esse número, a **perplexidade**, pode ser lido como "o modelo estava, em média, tão incerto quanto se escolhesse entre cerca de 2,9 opções igualmente prováveis a cada passo". Voltaremos à perplexidade nos Capítulos 5 e 16.

:::cuidado Cuidado com esta interpretação
Uma probabilidade alta para uma frase **não** significa que ela seja verdadeira. Significa que ela é **plausível** segundo os padrões do texto com que o modelo aprendeu. "A capital da Austrália é Sydney" pode receber probabilidade considerável, porque é um erro comum em textos. Plausibilidade e verdade são coisas diferentes.
:::

### 1.5.3 Do modelo de n-gramas ao "grande" modelo de linguagem

Como estimar essas probabilidades? A ideia mais antiga é **contar**. Num grande conjunto de textos (um **corpus**), contamos quantas vezes cada sequência aparece. Um **n-grama** é uma sequência de $n$ tokens consecutivos. Um modelo de bigramas ($n=2$) estima

$$ P(w_t \mid w_{t-1}) \approx \frac{\mathrm{contagem}(w_{t-1}, w_t)}{\mathrm{contagem}(w_{t-1})} $$

isto é, olha só para o token anterior. Um modelo de trigramas olha para dois tokens anteriores, e assim por diante. Claude Shannon (1948) já gerava "texto" aproximado dessa forma ao descrever a teoria da informação.

Vamos ver isso funcionando, com um corpus **sintético** em português, escrito por regras para este livro (frases curtas sobre a vida acadêmica). Ele é pequeno de propósito: queremos enxergar o mecanismo.

```python
from llmdidatico import corpus, modelos

frases = corpus.frases_lm(n=3000, seed=0)       # lista de frases, cada uma uma lista de tokens
treino, teste = frases[:2400], frases[2400:]
print("Exemplo:", " ".join(frases[0]))
print("Tamanho do vocabulário:", len({t for f in frases for t in f}))

lm = modelos.NgramaLM(n=3, k=0.05).ajustar(treino)   # trigramas com suavização aditiva
contexto = ["o", "estudante"]
dist = lm.distribuicao(contexto)                  # probabilidade de cada token do vocabulário
top = sorted(zip(lm.vocab, dist), key=lambda x: -x[1])[:5]
print(f"Próximo token após '{' '.join(contexto)}':")
for tok, p in top:
    print(f"  {tok:<12s} {p:.3f}")
print("Soma das probabilidades:", round(float(dist.sum()), 6))
```

Observe três coisas na saída. Primeiro, o modelo devolve uma **distribuição** sobre todo o vocabulário, e não uma única palavra. Segundo, as probabilidades somam 1. Terceiro, os verbos mais prováveis após "o estudante" são os que **aparecem** naquele corpus, e só eles. O modelo não "sabe" o que é um estudante: ele resume regularidades de contagem.

Contar tem limites. Quanto maior $n$, mais combinações possíveis existem, e a maioria nunca aparece nos dados. Para um vocabulário de 50 mil tokens, haveria $50\,000^3 = 1{,}25 \times 10^{14}$ trigramas possíveis. Nenhum corpus os cobre. Esse problema é chamado de **esparsidade** dos dados.

Os modelos neurais resolvem a esparsidade de outro modo. Em vez de tabelar contagens, aprendem **representações numéricas** (os *embeddings*, Capítulo 3) em que palavras parecidas ficam próximas. Assim, o que se aprende sobre "estudante" ajuda a prever frases sobre "aluno". Bengio e colaboradores (2003) propuseram essa ideia para linguagem, e ela se tornou a base do que veio depois.

### 1.5.4 O que torna um modelo "grande"?

Um **grande modelo de linguagem** (*large language model*, LLM) é um modelo de linguagem neural, tipicamente baseado na arquitetura Transformer (Capítulo 4), treinado com enorme quantidade de texto e com muitos parâmetros: de centenas de milhões a centenas de bilhões. Não existe um limiar oficial que separe "pequeno" de "grande". O termo é relativo e mudou com o tempo (Zhao et al., 2023).

Três ingredientes crescem juntos:

1. **Parâmetros:** os "botões" do modelo.
2. **Dados:** a quantidade de texto usada no treinamento.
3. **Computação:** o poder de cálculo gasto para treinar.

Kaplan et al. (2020) mostraram, para modelos de linguagem Transformer, que a perda de treinamento diminui de forma previsível, seguindo leis de potência, quando se aumenta cada um desses fatores. Hoffmann et al. (2022) refinaram essa conclusão e argumentaram que, para um dado orçamento de computação, parâmetros e dados deveriam crescer em proporção equilibrada. Retomaremos esses resultados no Capítulo 5, com as devidas ressalvas.

:::saibamais Saiba mais: "emergência" de capacidades
Há relatos de que certas capacidades "surgem" de repente quando o modelo cresce (Wei et al., 2022). Schaeffer, Miranda e Koyejo (2023) argumentam que parte desse efeito decorre da escolha de métricas descontínuas, e que, com métricas contínuas, a melhora tende a ser gradual. O debate segue aberto. Neste livro, tratamos "emergência" como hipótese a ser examinada caso a caso, e não como fato geral.
:::

## 1.6 IA, aprendizado de máquina, aprendizado profundo e PLN

Esses termos são usados como se fossem sinônimos. Não são. Eles se encaixam como bonecas russas, com uma sobreposição importante.

- **Inteligência Artificial (IA):** o campo que busca construir sistemas que realizam tarefas associadas à inteligência. Inclui desde regras manuais até redes neurais.
- **Aprendizado de máquina (AM):** parte da IA em que o sistema **aprende** padrões a partir de dados, em vez de seguir regras escritas à mão (Hastie; Tibshirani; Friedman, 2009).
- **Aprendizado profundo (AP):** parte do AM que usa redes neurais com muitas camadas (Goodfellow; Bengio; Courville, 2016).
- **Processamento de Linguagem Natural (PLN):** o campo dedicado a fazer computadores lidarem com linguagem humana. Usa técnicas de várias famílias: regras linguísticas, estatística, aprendizado profundo (Jurafsky; Martin, 2024).

Os grandes modelos de linguagem vivem na **interseção** entre aprendizado profundo e PLN.

![f01_aninhados]([C] Relações entre IA, aprendizado de máquina, aprendizado profundo e PLN. Os LLMs ficam na interseção entre aprendizado profundo e PLN. O desenho é conceitual: os tamanhos não representam proporções reais.)

:::cotidiano No seu dia a dia
O corretor ortográfico do celular é PLN (e hoje, muitas vezes, aprendizado profundo). O filtro de spam do e-mail é aprendizado de máquina (e talvez nem seja profundo). Um robô aspirador que desvia de móveis é IA. Nem tudo que é IA aprende; nem tudo que aprende é profundo.
:::

### 1.6.1 Onde os LLMs se diferenciam dos modelos anteriores de PLN

Antes dos LLMs, o caminho comum era treinar **um modelo por tarefa**: um para classificar sentimentos, outro para traduzir, outro para extrair nomes. Cada um exigia dados rotulados para aquela tarefa.

Os LLMs mudaram esse quadro em dois pontos. Primeiro, o **pré-treinamento** com texto sem rótulos fornece uma base geral de linguagem. Segundo, muitas tarefas podem ser descritas **em linguagem natural**, no próprio texto de entrada (o *prompt*), sem treinar nada novo. Brown et al. (2020) chamaram de **aprendizagem em contexto** o fenômeno em que o modelo se adapta à tarefa a partir de instruções e exemplos no prompt.

Essa flexibilidade tem preço: o comportamento é menos previsível, mais difícil de verificar e mais caro de executar. Em muitos problemas, um modelo pequeno e especializado ainda é a melhor escolha. Aprender a decidir isso é um dos objetivos do livro.

## 1.7 Uma breve história dos modelos de linguagem

Conhecer a história ajuda a perceber que os LLMs não surgiram do nada. Cada passo respondeu a uma limitação do anterior.

![f01_historia]([C] Linha do tempo de marcos citados neste livro. Os anos referem-se às publicações indicadas nas referências do capítulo; a escala é qualitativa e a seleção é nossa, não uma lista completa.)

- **1948 — Shannon.** A teoria da informação apresenta a ideia de aproximar a língua por sequências estatísticas (Shannon, 1948).
- **2003 — modelo neural probabilístico.** Bengio et al. aprendem embeddings de palavras e a previsão do próximo token juntos (Bengio et al., 2003).
- **2013 — word2vec.** Embeddings treinados de modo eficiente em grandes corpora mostram que direções no espaço vetorial capturam relações entre palavras (Mikolov et al., 2013).
- **2014–2015 — sequência a sequência e atenção.** Redes recorrentes passam a mapear uma sequência em outra (Sutskever; Vinyals; Le, 2014), e o mecanismo de atenção permite consultar partes relevantes da entrada (Bahdanau; Cho; Bengio, 2015).
- **2017 — Transformer.** Vaswani et al. propõem uma arquitetura baseada apenas em atenção, que treina em paralelo e escala bem (Vaswani et al., 2017).
- **2018 — representações pré-treinadas.** ELMo (Peters et al., 2018) e BERT (Devlin et al., 2019) mostram o poder de pré-treinar e depois adaptar.
- **2019–2020 — geração em escala.** GPT-2 (Radford et al., 2019) e GPT-3, com 175 bilhões de parâmetros (Brown et al., 2020), evidenciam a aprendizagem em contexto. Kaplan et al. (2020) descrevem leis de escala.
- **2022 — alinhamento com instruções.** Ouyang et al. (2022) usam preferências humanas para ajustar o modelo a seguir instruções, aproximando-o do formato de "assistente".

## 1.8 Modelo, aplicação, interface e sistema

Um erro frequente é usar "ChatGPT" como sinônimo de "LLM". O nome designa um **produto** (uma interface de conversação), e não um modelo. Para pensar com clareza, separamos quatro camadas.

![f01_camadas]([C] As quatro camadas: modelo, aplicação, interface de conversação e sistema completo. A mesma pergunta do usuário atravessa todas elas, e cada camada pode introduzir ganhos ou erros.)

| Camada | O que é | Exemplo |
|---|---|---|
| **Modelo** | Parâmetros treinados que transformam uma sequência de tokens em probabilidades do próximo token | Um modelo com pesos disponíveis, rodando localmente |
| **Aplicação** | Código que prepara a entrada, chama o modelo e trata a saída | Um programa que monta o prompt, valida o formato e trata erros |
| **Interface de conversação** | A forma de interação (janela de chat, voz, API) | Um chat web; um ponto de acesso (*endpoint*) de API |
| **Sistema completo** | Aplicação mais tudo ao redor: recuperação de documentos, ferramentas, filtros, registros, supervisão humana | Um assistente corporativo que consulta a base de políticas e registra as respostas |

Por que isso importa? Porque os problemas surgem em camadas diferentes e se resolvem de formas diferentes. Uma resposta errada pode vir do modelo (conhecimento ausente), da aplicação (prompt mal montado), da recuperação (documento errado) ou da interface (instrução do sistema oculta). Se você não separa as camadas, não sabe onde consertar.

O código a seguir ilustra a separação com um **modelo de brinquedo**: uma função determinística que apenas escolhe, dentro do texto recebido, a frase mais parecida com a pergunta. **Ela não é um LLM** e foi escrita só para tornar visíveis as camadas. A base consultada é a base fictícia da "Universidade Federal Aurora", escrita para o livro.

```python+
import re
from llmdidatico import DOCS, modelos

def modelo_brinquedo(prompt: str) -> str:
    """MODELO (de brinquedo): devolve a frase do contexto mais parecida com a pergunta."""
    ctx, _, pergunta = prompt.partition("\nPERGUNTA: ")
    frases = [f.strip() for f in re.split(r"(?<=[.!?])\s+", ctx.replace("CONTEXTO:", "")) if f.strip()]
    if not frases:
        return "Não encontrei informação para responder."
    q = set(modelos.tokenizar_sem_stop(pergunta))
    pontos = [len(q & set(modelos.tokenizar_sem_stop(f))) for f in frases]
    return frases[pontos.index(max(pontos))]

def aplicacao(pergunta: str, contexto: str = "") -> str:
    """APLICAÇÃO: monta o prompt, chama o modelo e valida a saída."""
    prompt = f"CONTEXTO: {contexto}\nPERGUNTA: {pergunta}"
    resposta = modelo_brinquedo(prompt)
    return resposta if len(resposta) < 400 else resposta[:400]

def sistema(pergunta: str) -> dict:
    """SISTEMA: acrescenta recuperação de documentos e registro da evidência."""
    bm = modelos.BM25([modelos.tokenizar_sem_stop(d[3]) for d in DOCS])
    s = bm.pontuar(modelos.tokenizar_sem_stop(pergunta))
    melhor = int(s.argmax())
    resposta = aplicacao(pergunta, DOCS[melhor][3])
    return {"resposta": resposta, "fonte": DOCS[melhor][0] + " — " + DOCS[melhor][2]}

pergunta = "Qual o valor da multa por atraso na devolução de livros?"
print("1) só o modelo, sem contexto  :", aplicacao(pergunta))
print("2) aplicação com contexto fixo:", aplicacao(pergunta, "A biblioteca abre às 7h."))
r = sistema(pergunta)
print("3) sistema com recuperação    :", r["resposta"])
print("   fonte registrada           :", r["fonte"])
```

A mesma pergunta tem três destinos. Sem contexto, o modelo de brinquedo nada tem a dizer. Com um contexto irrelevante, devolve uma frase irrelevante com a mesma "confiança" de sempre. Só no sistema, com **recuperação**, a resposta correta aparece, acompanhada da fonte. Esse padrão (recuperar e depois responder) é o tema do Capítulo 11.

:::lembrar O que vale a pena lembrar
- **Modelo** ≠ **produto**. Nomes de chatbots não são nomes de modelos.
- A qualidade final depende do **sistema**, e não apenas do modelo.
- Ao depurar, pergunte: o erro nasceu no modelo, na entrada, na recuperação ou na validação?
:::

### 1.9.1 Casos de uso por domínio

Ao longo do livro, usaremos cinco domínios nos exemplos e projetos. Todos os dados são **fictícios ou sintéticos**.

- **Educação:** perguntas sobre regulamentos acadêmicos (a base da universidade fictícia).
- **Saúde:** apenas textos públicos ou sintéticos, com ênfase em riscos de uso indevido; nenhum conselho clínico.
- **Jurídico e administração pública:** busca em normas, com citação obrigatória da fonte.
- **Atendimento ao cliente:** classificação de mensagens e respostas padronizadas.
- **Documentação técnica:** perguntas sobre manuais e procedimentos.

:::atencao Atenção
Em saúde, direito e finanças, um erro plausível pode causar dano real. Nesses domínios, o LLM deve **apoiar** profissionais, nunca substituí-los, e toda saída relevante precisa de verificação humana. O Capítulo 17 trata disso em profundidade.
:::

## 1.10 Capacidades, limitações e expectativas realistas

Vamos organizar o que se pode esperar, separando **evidência**, **hipótese** e **opinião**.

### 1.10.1 O que os LLMs costumam fazer bem

Há evidência ampla, em artigos e *benchmarks*, de bom desempenho em tarefas de linguagem: reescrever, resumir textos curtos, traduzir, classificar, seguir formatos. A qualidade varia com o modelo, o idioma e a tarefa. Para o português, há trabalhos específicos e modelos treinados em português (por exemplo, Souza; Nogueira; Lotufo, 2020 para o BERTimbau; Pires et al., 2023 para o Sabiá). Mesmo assim, o desempenho em português costuma ser menos estudado e menos medido que em inglês.

### 1.10.2 Onde eles falham

- **Respostas inventadas.** A literatura chama de *alucinação* a geração de conteúdo fluente que não é fiel à fonte ou aos fatos (Ji et al., 2023). Neste livro, usamos "resposta inventada" ou "não fundamentada", para evitar sugerir que o modelo "percebe" algo.
- **Sensibilidade ao formato.** Mudanças pequenas no prompt podem alterar bastante a resposta.
- **Raciocínio frágil.** Em contas e lógica de vários passos, erros aparecem, e a explicação escrita pelo modelo nem sempre reflete o que determinou a resposta (Capítulo 8).
- **Conhecimento datado.** O modelo "sabe" até a data de corte dos dados de treinamento, e depois dela não sabe.
- **Vieses.** O modelo reproduz padrões dos textos, incluindo estereótipos (Bender et al., 2021).
- **Custo e latência.** Modelos grandes consomem memória, energia e tempo.

![f01_expectativas]([C] Expectativas realistas: mais útil como componente verificável de um sistema do que como oráculo isolado. O esquema organiza ideias do texto; não é um resultado experimental.)

### 1.10.3 Três perguntas antes de adotar um LLM

1. **Existe uma solução mais simples?** Regras, busca por palavras-chave ou um classificador pequeno podem bastar.
2. **Como saberei que a resposta está certa?** Se não há como verificar, o risco é maior.
3. **Qual o custo de um erro?** Um erro em um rascunho de e-mail é barato. Em uma dosagem de remédio, não é.

:::cuidado Cuidado com esta interpretação
"O modelo acertou nos meus cinco testes" não prova que ele é confiável. Cinco exemplos são amostra pequena e geralmente escolhida por quem testa. O Capítulo 16 ensina a medir com amostras maiores, intervalos de confiança e conjuntos de teste que o modelo não viu.
:::

## 1.11 Exemplos resolvidos

### Exemplo 1 — Perplexidade e ordem do n-grama

**Problema.** Treine modelos de unigramas, bigramas e trigramas no corpus sintético e compare a perplexidade em frases de teste. Qual deles descreve melhor o corpus? Por quê?

**Solução.** Usamos o mesmo corpus do início do capítulo. A perplexidade mede a "surpresa" média do modelo diante de frases que ele **não viu** no treino. Menor é melhor.

```python+
for n in (1, 2, 3):
    m = modelos.NgramaLM(n=n, k=0.05).ajustar(treino)
    print(f"n={n}: perplexidade no teste = {m.perplexidade(teste):.2f}")
```

**Interpretação.** O unigrama ignora o contexto e acerta pouco. O bigrama e o trigrama usam o contexto e reduzem muito a perplexidade. A diferença entre bigrama e trigrama é pequena porque, neste corpus, a frase tem estrutura simples. Em textos reais, o ganho de aumentar $n$ esbarra na esparsidade, e é por isso que modelos neurais assumiram o lugar dos n-gramas.

![f01_ppl]([D:figs_cap01.py] Perplexidade no conjunto de teste para n-gramas de ordem 1, 2 e 3, no corpus sintético do livro. Os valores são reproduzíveis com a semente indicada no código; o corpus é artificial e muito mais regular que a língua real.)

### Exemplo 2 — Calculando a probabilidade de uma frase

**Problema.** Qual a probabilidade, segundo o modelo de trigramas, da frase "a professora corrige a prova ."? E de uma frase fora do padrão, como "a prova corrige a professora ."?

```python+
f1 = "a professora corrige a prova .".split()
f2 = "a prova corrige a professora .".split()
m3 = modelos.NgramaLM(n=3, k=0.05).ajustar(treino)
import math
for f in (f1, f2):
    lp = m3.logprob_frase(f)
    print(" ".join(f), f"-> ln P = {lp:.2f}, P = {math.exp(lp):.2e}")
```

**Interpretação.** A primeira frase tem probabilidade muito maior que a segunda, que contém combinações que o corpus nunca apresentou. Observe que a segunda **não** recebe probabilidade zero: a suavização aditiva reserva uma pequena massa para o desconhecido. O modelo julga "estranheza estatística", e não "sentido".

### Exemplo 3 — Decidindo se vale usar um LLM

**Problema.** Uma universidade quer responder automaticamente à pergunta "qual o prazo para trancar a matrícula?". Compare três soluções.

| Solução | Vantagem | Risco | Quando escolher |
|---|---|---|---|
| Página de perguntas frequentes com busca por palavras | Simples, barata, previsível | Não entende perguntas reformuladas | Poucas perguntas, vocabulário estável |
| Sistema de recuperação + LLM com citação da fonte | Entende reformulações; cita o regulamento | Custo, latência, respostas ainda podem falhar | Muitas perguntas, regulamentos extensos |
| LLM sozinho, sem acesso ao regulamento | Fácil de montar | Inventa prazos; sem fonte | Não recomendado para este caso |

**Decisão.** Para um regulamento real e extenso, a segunda opção costuma equilibrar utilidade e controle, **desde que** haja avaliação (Capítulo 16) e supervisão (Capítulo 17). O ponto central é que a decisão se baseia em risco e verificabilidade, e não em modismo.

## 1.12 Atividade prática

**Objetivo.** Observar na prática a diferença entre plausibilidade e verdade, e registrar a observação de modo reprodutível.

**Passo a passo.**

1. Escolha uma interface de conversação ou um modelo local que você possa usar. Anote **qual** (nome, versão, data do teste). Isso é importante: os resultados dependem disso e mudam com o tempo.
2. Prepare cinco perguntas cujas respostas você consegue **verificar** em uma fonte confiável (por exemplo, datas, fórmulas, definições do seu curso).
3. Faça duas das perguntas de modo sugestivo, embutindo um erro (por exemplo: "Explique por que a Lei Geral de Proteção de Dados foi aprovada em 2008"). Observe se o modelo corrige a premissa ou segue o erro.
4. Para cada resposta, preencha uma tabela com: pergunta, resposta resumida, correta (sim/não/parcial), como você verificou.
5. Repita a pergunta mais difícil três vezes e compare as respostas.

**Entregável.** Uma tabela e um parágrafo de conclusão respondendo: "Em que casos a fluência escondeu um erro?".

:::fonte Reprodutibilidade em serviços externos
Serviços de conversação mudam de modelo, de instruções ocultas e de políticas sem aviso. Por isso, o seu experimento não é reproduzível por outra pessoa, nem por você mesmo meses depois, a menos que registre data, versão do serviço e parâmetros. Isso vale para todo experimento com serviços externos neste livro.
:::

## 1.13 Erros frequentes

- **Tratar "ChatGPT" como sinônimo de LLM.** É um produto; os modelos por trás mudam.
- **Achar que o modelo "sabe" ou "entende" como uma pessoa.** Descrevemos o que ele **faz** (estima probabilidades de tokens). Se isso equivale a "entender" é uma discussão filosófica que não precisamos resolver para construir sistemas.
- **Confiar na fluência.** Texto bem escrito não é texto verdadeiro.
- **Julgar por poucos exemplos.** Cinco acertos não provam nada.
- **Esquecer o custo de verificar.** Se verificar cada resposta custa tanto quanto produzi-la, o ganho some.
- **Ignorar a data de corte.** Perguntas sobre fatos recentes exigem fontes atualizadas.

## 1.14 Limitações e cuidados

- Os exemplos numéricos deste capítulo usam um **corpus sintético** e **n-gramas**. Eles ilustram o conceito de modelo de linguagem, mas **não** medem o desempenho de LLMs reais.
- O "modelo de brinquedo" da Seção 1.8 não é um LLM. Foi escrito apenas para separar camadas.
- A cronologia da Seção 1.7 é seletiva e simplifica uma história com muitos autores. Ela cita os trabalhos que consideramos mais úteis para o leitor; outros marcos importantes foram omitidos.
- Valores como número de parâmetros mudam e, em geral, não são divulgados para modelos comerciais. Nunca os trate como fatos sem fonte.

## 1.15 Síntese

:::lembrar O que vale a pena lembrar
- Um **modelo de linguagem** estima a probabilidade do próximo token dado o contexto; escrever é repetir esse passo.
- A probabilidade de uma frase é o **produto** das probabilidades de cada passo; na prática, somamos **logaritmos**.
- **Perplexidade** é a "incerteza média" do modelo; menor é melhor, mas não mede verdade.
- **N-gramas** contam; **modelos neurais** aprendem representações e superam a esparsidade.
- Um **LLM** é um modelo de linguagem neural, tipicamente Transformer, treinado em grande escala; "grande" é relativo.
- IA ⊃ aprendizado de máquina ⊃ aprendizado profundo; os LLMs estão na interseção com o PLN.
- Separe **modelo, aplicação, interface e sistema**; o erro pode estar em qualquer camada.
- Fluência **não** é correção. Verifique, meça e documente.
:::
