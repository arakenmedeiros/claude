## 2.2 Python em dez minutos

**Python** é uma linguagem de programação conhecida por ser legível. O código lembra o português escrito, só que em inglês.

### 2.2.1 Variáveis, listas e funções

Uma **variável** é um nome que guarda um valor. Uma **lista** guarda vários valores em ordem. Uma **função** é um trecho de código com nome, que recebe valores e devolve um resultado.

```python
idade = 34
nome = "Ana"
notas = [7.5, 8.0, 9.5]
media = sum(notas) / len(notas)
print(f"{nome} tem {idade} anos e média {media:.2f}")

def acuracia(acertos, total):
    return acertos / total

for n in notas:
    if n >= 8:
        print(n, "-> aprovada com folga")
    else:
        print(n, "-> atenção")

print("Acurácia:", acuracia(45, 50))
```

```saída
Ana tem 34 anos e média 8.33
7.5 -> atenção
8.0 -> aprovada com folga
9.5 -> aprovada com folga
Acurácia: 0.9
```

O que você viu:

- `=` **guarda** um valor em uma variável. Não é igualdade matemática.
- `[ ... ]` cria uma lista.
- `for ... in ...:` **repete** um bloco para cada item.
- `if ... else ...:` escolhe entre dois caminhos. O que está **recuado** (com espaços à esquerda) pertence ao bloco. Em Python, o recuo faz parte da sintaxe.
- `def nome(...)`: define uma função. `return` devolve o resultado.
- `#` inicia um **comentário**, ignorado pelo computador, escrito para humanos.
- Um número com ponto, como `8.33`, usa o **ponto** como separador decimal, e não a vírgula.

## 2.3 NumPy: o cálculo com vetores e matrizes

Dados de aprendizado de máquina são **tabelas de números**. A biblioteca NumPy (Harris et al., 2020) calcula com tabelas inteiras, de forma muito rápida.

- **Vetor**: uma lista de números. Exemplo: `[3, 5, 8, 2]`.
- **Matriz**: uma tabela de números, com linhas e colunas.
- **Formato** (*shape*): o tamanho da tabela. Uma matriz com 3 linhas e 3 colunas tem formato `(3, 3)`.

```python
import numpy as np

x = np.array([3, 5, 8, 2])
print("Vetor      :", x)
print("Dobro      :", x * 2)
print("Soma, média:", x.sum(), x.mean())

X = np.array([[34, 5.2, 12],
              [51, 8.1,  4],
              [27, 3.9, 20]])
print("Formato de X:", X.shape)          # (3 linhas, 3 colunas)
print("Primeira linha:", X[0])
print("Segunda coluna:", X[:, 1])
print("Média por coluna:", X.mean(axis=0).round(2))

y = np.array([1, 0, -1])                  # -1 = sem rótulo
print("Exemplos com rótulo:", (y != -1).sum())
print("Índices sem rótulo :", np.where(y == -1)[0])
```

```saída
Vetor      : [3 5 8 2]
Dobro      : [ 6 10 16  4]
Soma, média: 18 4.5
Formato de X: (3, 3)
Primeira linha: [34.   5.2 12. ]
Segunda coluna: [5.2 8.1 3.9]
Média por coluna: [37.33  5.73 12.  ]
Exemplos com rótulo: 2
Índices sem rótulo : [2]
```

Observe quatro ideias importantes.

- **Operações elemento a elemento.** `x * 2` dobra todos os valores, sem precisar de um laço.
- **Índices começam em zero.** `X[0]` é a **primeira** linha.
- **O símbolo `:`** significa "todos". `X[:, 1]` lê todas as linhas da coluna de índice 1.
- **Máscaras lógicas.** `y != -1` devolve um vetor de verdadeiro/falso. Somar esse vetor conta quantos são verdadeiros. Usaremos esse truque o tempo todo para separar exemplos rotulados dos sem rótulo.

## 2.5 Dados são pontos no espaço

Um cliente com 2 atributos (idade e renda) é um ponto em um plano. Com 3 atributos, é um ponto em um espaço 3D. Com 64 atributos, como uma imagem 8×8, é um ponto em um espaço de 64 dimensões. Não conseguimos desenhar, mas a matemática funciona do mesmo jeito.

![f2_pixels](Figura 2.3 — Uma imagem de dígito do conjunto Digits (UCI) vira um vetor de 64 números. Cada exemplo é uma linha da matriz X.)

Isso importa porque **exemplos parecidos ficam próximos** no espaço. Toda a intuição do aprendizado semissupervisionado se apoia nessa frase.

### 2.5.1 Medindo a distância entre dois pontos

Para dizer que dois pontos estão "perto" ou "longe", precisamos de uma **medida de distância**. Existem várias.

![f2_distancias](Figura 2.4 — Três maneiras de medir semelhança entre pontos: distância euclidiana (a "linha reta"), Manhattan (as "quadras") e cosseno (o ângulo entre vetores).)

**Distância euclidiana.** É a distância "em linha reta", a mais usada. Para dois pontos *a* e *b* com *d* atributos:

$$ d(a, b) = √( (a_1 − b_1)^2 + (a_2 − b_2)^2 + ... + (a_d − b_d)^2 ) $$

Em palavras: subtraia atributo por atributo, eleve ao quadrado, some tudo e tire a raiz quadrada.

*Exemplo:* de A = (1, 1) a B = (5, 4), as diferenças são 4 e 3. A distância é raiz de (16 + 9) = 5.

**Distância de Manhattan.** Soma as diferenças absolutas, como se você andasse pelas quadras de uma cidade. De A a B: 4 + 3 = 7.

**Similaridade do cosseno.** Mede o **ângulo** entre dois vetores, ignorando o comprimento. Vale 1 quando apontam na mesma direção e 0 quando são perpendiculares. É muito usada em texto.

```python
import numpy as np
A = np.array([1.0, 1.0]); B = np.array([5.0, 4.0])
eucl = np.sqrt(((A - B) ** 2).sum())
manh = np.abs(A - B).sum()
print("Euclidiana:", eucl)
print("Manhattan :", manh)

u, v, w = np.array([4.0, 1.0]), np.array([3.0, 3.0]), np.array([1.0, 4.0])
def cos(a, b): return a @ b / (np.linalg.norm(a) * np.linalg.norm(b))
print("cos(u, v) = %.3f" % cos(u, v))
print("cos(v, w) = %.3f" % cos(v, w))
print("cos(u, w) = %.3f" % cos(u, w))
```

```saída
Euclidiana: 5.0
Manhattan : 7.0
cos(u, v) = 0.857
cos(v, w) = 0.857
cos(u, w) = 0.471
```

O símbolo `@` faz o **produto escalar** (multiplicar posição a posição e somar), e `np.linalg.norm` calcula o **comprimento** de um vetor.

### 2.5.2 A armadilha da escala

Imagine descrever pessoas por altura (em metros, de 1,5 a 2,0) e renda (em reais, de 1.000 a 20.000). Ao calcular a distância euclidiana, a diferença de renda será **milhares de vezes maior** que a de altura. A altura vai ser praticamente ignorada.

![f2_escala](Figura 2.5 — No conjunto Breast Cancer, o raio médio varia de cerca de 6 a 28, e a área média, de 140 a 2.500. No mesmo gráfico, o raio parece constante. Depois de padronizar, os dois atributos têm o mesmo peso.)

A solução usual é a **padronização**: subtrair a média e dividir pelo desvio padrão, atributo por atributo. Assim, todos ficam com média 0 e desvio padrão 1.

$$ z = (x − μ) / σ $$

Aqui *x* é o valor original, *μ* (mu) é a média do atributo e *σ* (sigma) é o desvio padrão, uma medida de quanto os valores se espalham em torno da média.

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
cols = [0, 3]   # raio médio e área média
print("Antes : média", X[:, cols].mean(axis=0).round(1), "| desvio", X[:, cols].std(axis=0).round(1))
Z = StandardScaler().fit_transform(X[:, cols])
print("Depois: média", Z.mean(axis=0).round(1), "| desvio", Z.std(axis=0).round(1))
```

```saída
Antes : média [ 14.1 654.9] | desvio [  3.5 351.6]
Depois: média [-0. -0.] | desvio [1. 1.]
```

(O "-0." é um zero com sinal, que aparece por arredondamento do computador. Significa zero.)

:::atencao Atenção: métodos baseados em distância pedem padronização
Os métodos baseados em grafos, como o Label Spreading (Capítulo 8), calculam vizinhos por distância. Sem padronizar, o atributo de maior escala comanda tudo. **Padronize** antes, salvo se tiver um bom motivo para não fazê-lo.
:::

## 2.6 Probabilidade essencial

Probabilidade é a linguagem da **incerteza**. Vários métodos semissupervisionados são probabilísticos (Capítulo 6). Vamos ver o essencial.

### 2.6.1 O que é uma probabilidade

A **probabilidade** de um evento é um número entre 0 e 1 que mede o quão provável ele é. Zero significa impossível. Um significa certo. Se 20% dos e-mails são spam, a probabilidade de um e-mail sorteado ser spam é 0,20.

Escrevemos **P(spam) = 0,20**.

### 2.6.2 Probabilidade condicional

A probabilidade **condicional** responde: "qual a chance de A, **sabendo que** B aconteceu?". Escrevemos **P(A | B)**, lendo "probabilidade de A dado B".

Exemplo: **P(prêmio | spam) = 0,80** significa que 80% dos spams contêm a palavra "prêmio".

### 2.6.3 O teorema de Bayes

Muitas vezes temos P(B | A) e queremos P(A | B). O **teorema de Bayes** faz a ponte.

$$ P(A | B) = P(B | A) × P(A) / P(B) $$

Vamos usar números. Em 1.000 e-mails, 200 são spam. Entre os spams, 80% têm a palavra "prêmio". Entre os não spams, 5% têm.

![f2_bayes](Figura 2.6 — O teorema de Bayes com frequências naturais. Entre os 200 e-mails que contêm "prêmio", 160 são spam.)

Contando: 160 spams + 40 não spams têm a palavra, em um total de 200. Logo, **P(spam | prêmio) = 160/200 = 0,80**. Veja a mesma conta em código.

```python
# Teorema de Bayes: P(spam | "prêmio")
p_spam = 0.20
p_premio_dado_spam = 0.80
p_premio_dado_nao = 0.05
p_premio = p_premio_dado_spam * p_spam + p_premio_dado_nao * (1 - p_spam)
p_spam_dado_premio = p_premio_dado_spam * p_spam / p_premio
print("P(prêmio)        = %.2f" % p_premio)
print("P(spam | prêmio) = %.2f" % p_spam_dado_premio)
```

```saída
P(prêmio)        = 0.20
P(spam | prêmio) = 0.80
```

:::memorize Memorize
Bayes permite **atualizar uma crença** com novas evidências. Antes de ver a palavra, a chance de spam era 20%. Depois de vê-la, passou a 80%. Esse raciocínio é a base do classificador Naive Bayes, que reaparece no Capítulo 6.
:::

### 2.6.4 A curva normal

Muitos atributos do mundo real se espalham em torno de uma média, em forma de sino. Essa forma é a **distribuição normal** (ou gaussiana). Ela é descrita por dois números.

- a **média** μ: o centro do sino;
- o **desvio padrão** σ: a largura do sino.

![f2_gauss](Figura 2.7 — À esquerda, curvas normais com a mesma média e larguras diferentes. À direita, duas classes, cada uma com sua curva. A fronteira de decisão fica onde as curvas se cruzam.)

Uma ideia importante para o Capítulo 6: podemos **descrever cada classe por uma curva normal**. Para classificar um exemplo novo, perguntamos de qual curva ele "mais provavelmente veio". Os exemplos sem rótulo ajudam a **estimar melhor essas curvas**, porque revelam a forma geral dos dados.

## 2.7 A interface do scikit-learn

O **scikit-learn** (Pedregosa et al., 2011) é a biblioteca de aprendizado de máquina que usaremos em todo o livro. Seu grande mérito é a **consistência**: todos os modelos seguem o mesmo padrão.

![f2_api](Figura 2.8 — O padrão do scikit-learn: criar, ajustar (fit), prever (predict) e avaliar (score). Um Pipeline encadeia passos que seguem o mesmo contrato.)

Os métodos que você usará o tempo todo:

| Método | O que faz | Exemplo |
|---|---|---|
| fit(X, y) | Aprende com os dados de treino | modelo.fit(X_treino, y_treino) |
| predict(X) | Devolve as classes previstas | modelo.predict(X_novo) |
| predict_proba(X) | Devolve a probabilidade de cada classe | modelo.predict_proba(X_novo) |
| transform(X) | Transforma os dados (padronizar, por exemplo) | escala.transform(X) |
| score(X, y) | Devolve a acurácia | modelo.score(X_teste, y_teste) |

Nos métodos **semissupervisionados**, o `fit` recebe X com **todos** os exemplos e y com **-1** nos exemplos sem rótulo. É a única mudança.

### 2.7.1 Pipeline: encadeando passos

Um **pipeline** liga vários passos em um só objeto. É a melhor defesa contra o vazamento de informação, que veremos adiante.

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

X, y = load_breast_cancer(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)

modelo = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
modelo.fit(X_tr, y_tr)                       # aprende (padronização + regressão logística)
print("Acurácia no teste: %.1f%%" % (100 * modelo.score(X_te, y_te)))
print("Previsão dos 5 primeiros:", modelo.predict(X_te[:5]), "| reais:", y_te[:5])
```

```saída
Acurácia no teste: 95.9%
Previsão dos 5 primeiros: [0 1 0 1 0] | reais: [0 0 0 1 0]
```

Detalhes do código:

- **`load_breast_cancer`** carrega o conjunto *Breast Cancer Wisconsin (Diagnostic)* do repositório UCI: 569 exames com 30 medidas e dois rótulos, maligno (0) e benigno (1) (Wolberg; Mangasarian, 1990).
- **`train_test_split`** separa treino e teste. `test_size=0.3` reserva 30% para teste. `stratify=y` mantém a **mesma proporção de cada classe** nos dois conjuntos. `random_state=0` fixa o sorteio, para que o resultado seja **reprodutível**.
- **`LogisticRegression`** é um classificador linear. Apesar do nome, serve para **classificação**.
- **`make_pipeline(StandardScaler(), ...)`** padroniza os dados e depois classifica. No `fit`, a padronização aprende a média e o desvio **só do treino**.

## 2.8 Treino, validação e teste

Na seção 1.2.2 vimos o par treino e teste. Agora refinamos.

Se usarmos o teste para **escolher** parâmetros ou modelos, ele deixa de ser "secreto". Escolher o melhor entre dez modelos olhando para o teste é como estudar para a prova vendo as questões: a nota fica otimista. Por isso criamos uma terceira parte.

- **Treino:** o modelo aprende.
- **Validação:** usamos para **escolher** parâmetros e comparar modelos.
- **Teste:** usamos **uma única vez, no fim**, para dar a nota final.

![f2_split](Figura 2.9 — As partições dos dados. No caso semissupervisionado, o treino se divide em rotulados e sem rótulo.)

### 2.8.1 Validação cruzada

Em muitos problemas semissupervisionados, os rótulos são tão poucos que reservar uma validação grande é um luxo. A **validação cruzada** (*cross-validation*) aproveita melhor os dados (Kohavi, 1995).

Na validação cruzada com *k* dobras, dividimos os dados em *k* partes. Repetimos *k* vezes: em cada rodada, uma parte vira teste e as outras *k − 1* viram treino. A nota final é a **média** das *k* notas.

![f2_kfold](Figura 2.10 — Validação cruzada com 5 dobras. Cada exemplo é usado para teste uma vez e para treino quatro vezes.)

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

X, y = load_breast_cancer(return_X_y=True)
modelo = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
notas = cross_val_score(modelo, X, y, cv=cv)
print("Notas das 5 dobras:", (100 * notas).round(1))
print("Média: %.1f%% | desvio: %.1f" % (100 * notas.mean(), 100 * notas.std()))
```

```saída
Notas das 5 dobras: [ 95.6  97.4  98.2 100.   98.2]
Média: 97.9% | desvio: 1.4
```

A média dá a nota esperada. O **desvio padrão** mostra a estabilidade: se for grande, o resultado depende muito de quais exemplos caíram em cada parte.

### 2.8.2 Subajuste e sobreajuste

Dois problemas clássicos rondam qualquer modelo (Geman; Bienenstock; Doursat, 1992; Domingos, 2012).

- **Subajuste** (*underfitting*): o modelo é simples demais e não captura o padrão. Erra no treino **e** no teste.
- **Sobreajuste** (*overfitting*): o modelo é complexo demais e **decora** os detalhes, inclusive o ruído. Acerta no treino e erra no teste.

![f2_overfit](Figura 2.11 — Ajustando curvas a 14 pontos com ruído. A reta (esquerda) é simples demais. O polinômio de grau 11 (direita) passa por todos os pontos, mas oscila loucamente. O de grau 3 (centro) acompanha o padrão real.)

*Analogia:* um aluno que decora as respostas da lista de exercícios (sobreajuste) vai bem nesses exercícios e mal na prova. Um aluno que estudou só o primeiro capítulo (subajuste) vai mal em ambos.

O experimento abaixo mostra isso com árvores de decisão em Digits. A **profundidade** da árvore controla a complexidade.

```python
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = load_digits(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)
print("profundidade | acurácia treino | acurácia teste")
for d in [1, 3, 5, 10, None]:
    arv = DecisionTreeClassifier(max_depth=d, random_state=0).fit(X_tr, y_tr)
    print(f"{str(d):12s} | {100 * arv.score(X_tr, y_tr):14.1f}% | {100 * arv.score(X_te, y_te):13.1f}%")
```

```saída
profundidade | acurácia treino | acurácia teste
1            |           19.8% |          19.8%
3            |           47.2% |          47.6%
5            |           74.3% |          72.0%
10           |           97.6% |          84.8%
None         |          100.0% |          84.3%
```

Observe: com profundidade 1, a acurácia é baixa nos dois (subajuste). Com profundidade livre (`None`), o treino chega a 100%, mas o teste fica em 84%. A **diferença** entre treino e teste revela o sobreajuste.

:::atencao Atenção: sobreajuste é especialmente perigoso com poucos rótulos
Com 20 exemplos rotulados, é fácil o modelo decorar todos. A acurácia no próprio treino será ótima e enganosa. **Nunca** julgue um modelo semissupervisionado pelo desempenho nos exemplos rotulados do treino.
:::

## 2.9 Métricas: como medir o acerto

A acurácia é simples, mas pode enganar. Imagine um exame em que 99% dos pacientes são saudáveis. Um "modelo" que sempre responde "saudável" tem 99% de acurácia e **nunca acha um doente**. Por isso usamos outras métricas.

### 2.9.1 A matriz de confusão

A **matriz de confusão** cruza as classes reais com as previstas. Em uma classificação com duas classes, chamamos uma delas de "positiva" (aquela que queremos encontrar) e a outra de "negativa". Quatro casos podem ocorrer.

- **VP (verdadeiro positivo):** era positivo e o modelo previu positivo. Acerto.
- **VN (verdadeiro negativo):** era negativo e o modelo previu negativo. Acerto.
- **FP (falso positivo):** era negativo e o modelo previu positivo. Alarme falso.
- **FN (falso negativo):** era positivo e o modelo previu negativo. Caso perdido.

![f2_confusao](Figura 2.12 — Matriz de confusão de uma regressão logística no conjunto de teste do Breast Cancer (171 exames), tratando "benigno" como a classe positiva, e as métricas que dela decorrem.)

### 2.9.2 Precisão, revocação e F1

- **Acurácia:** de todos os exemplos, quantos acertamos? (VP + VN) / total.
- **Precisão:** das vezes em que previmos "positivo", quantas estavam certas? VP / (VP + FP). Mede a **confiabilidade** dos alarmes.
- **Revocação** (*recall*): de todos os positivos reais, quantos encontramos? VP / (VP + FN). Mede a **cobertura**.
- **F1:** a média harmônica de precisão e revocação. Só é alta quando **as duas** são altas.

$$ F1 = 2 × (precisão × revocação) / (precisão + revocação) $$

```python
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import confusion_matrix, classification_report

X, y = load_breast_cancer(return_X_y=True)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, stratify=y, random_state=0)
modelo = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(X_tr, y_tr)
pred = modelo.predict(X_te)
print(confusion_matrix(y_te, pred, labels=[1, 0]))
print(classification_report(y_te, pred, target_names=["maligno", "benigno"], digits=3))
```

```saída
[[103   4]
 [  3  61]]
              precision    recall  f1-score   support

     maligno      0.938     0.953     0.946        64
     benigno      0.972     0.963     0.967       107

    accuracy                          0.959       171
   macro avg      0.955     0.958     0.956       171
weighted avg      0.959     0.959     0.959       171

```

O relatório usa os termos em inglês: *precision* (precisão), *recall* (revocação) e *support* (número de exemplos reais da classe).

:::cotidiano No seu dia a dia
Um detector de incêndio com **alta revocação** quase nunca deixa de tocar em um incêndio real, mas pode tocar com a torrada queimada (baixa precisão). Um detector com **alta precisão** só toca quando há fogo de verdade, mas pode deixar de tocar em alguns incêndios. Qual é melhor? Depende do custo de cada erro.
:::

Em problemas com classes desbalanceadas, a acurácia sozinha engana. Prefira acompanhar precisão, revocação e F1, além da acurácia.

## 2.10 Cuidados especiais do aprendizado semissupervisionado

Agora que você tem as ferramentas, vamos ao ponto em que elas **mais** erram em projetos semissupervisionados.

### 2.10.1 Como "esconder" rótulos em um experimento

Para estudar métodos semissupervisionados com bases públicas, que vêm completamente rotuladas, **simulamos** a escassez: sorteamos alguns exemplos para manter o rótulo e trocamos o rótulo dos demais por -1. Vamos usar essa função em todo o livro.

```python
import numpy as np

def esconder_rotulos(y, n_rot, semente):
    """Mantém n_rot rótulos (igualmente divididos entre as classes) e põe -1 nos demais."""
    rng = np.random.RandomState(semente)
    classes = np.unique(y)
    idx = np.concatenate([rng.choice(np.where(y == c)[0], n_rot // len(classes), replace=False)
                          for c in classes])
    y_parcial = np.full(len(y), -1)
    y_parcial[idx] = y[idx]
    return y_parcial, idx
```

:::atencao Atenção: simular não é a realidade
Rotular exemplos **sorteados** é otimista. Em projetos reais, os exemplos rotulados raramente são uma amostra aleatória do total: tendem a ser os mais fáceis, os mais recentes ou os mais baratos de rotular. Isso pode distorcer o aprendizado. Voltaremos ao ponto no Capítulo 17.
:::

### 2.10.2 Regra de ouro: o teste fica de fora

No aprendizado semissupervisionado, os exemplos **sem rótulo do treino** entram no `fit`. É tentador incluir aí os exemplos de teste, "já que eles não têm rótulo mesmo". Em um **projeto indutivo** (queremos prever exemplos futuros), isso é **proibido**: o teste deve ser mantido totalmente à parte, para simular exemplos que ainda não existem.

Há uma exceção legítima: no **aprendizado transdutivo**, em que o objetivo é rotular justamente o conjunto sem rótulo que temos, o desempenho é medido sobre esses mesmos exemplos (Capítulo 3).

### 2.10.3 Vazamento de informação

**Vazamento** (*leakage*) acontece quando informação do conjunto de teste (ou da validação) **escapa** para o treino, direta ou indiretamente. O resultado é uma nota irreal. Exemplos comuns:

- padronizar os dados com a média de **todo** o conjunto, antes de separar treino e teste;
- escolher atributos olhando para **todos** os rótulos, antes de separar;
- usar o conjunto de teste para decidir parâmetros.

O experimento abaixo é impressionante. Criamos 2.000 atributos de **puro ruído** e rótulos **aleatórios**. Não há nada a aprender. A acurácia correta é 50%.

```python
import numpy as np
from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score, StratifiedKFold
from sklearn.pipeline import make_pipeline

rng = np.random.RandomState(0)
X = rng.normal(size=(60, 2000))          # 2.000 atributos de puro ruído
y = rng.randint(0, 2, size=60)           # rótulos aleatórios: não há nada a aprender
cv = StratifiedKFold(5, shuffle=True, random_state=0)

# ERRADO: escolhe os atributos olhando para TODOS os rótulos, antes de separar
X_vazado = SelectKBest(f_classif, k=20).fit_transform(X, y)
errado = cross_val_score(LogisticRegression(max_iter=1000), X_vazado, y, cv=cv).mean()

# CERTO: a seleção acontece dentro de cada dobra, só com o treino
certo = cross_val_score(make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression(max_iter=1000)), X, y, cv=cv).mean()
print("Acurácia com vazamento   : %.1f%%" % (100 * errado))
print("Acurácia sem vazamento   : %.1f%%" % (100 * certo))
print("Acurácia esperada ao acaso: 50.0%")
```

```saída
Acurácia com vazamento   : 88.3%
Acurácia sem vazamento   : 41.7%
Acurácia esperada ao acaso: 50.0%
```

Com vazamento, o "modelo" parece ótimo: **88%** de acurácia em dados que não têm nenhum padrão! Sem vazamento, o resultado é o esperado para o acaso (41,7%, que flutua ao redor de 50% com apenas 60 exemplos). A moral: **todo passo que olha para os rótulos ou para os dados deve estar dentro do pipeline**, aplicado somente ao treino de cada rodada.

:::memorize Memorize: três regras para não se enganar
1. **Separe o teste primeiro** e não o toque até o fim.
2. **Ajuste** (`fit`) padronização, seleção de atributos e modelo **somente com o treino**.
3. Use **pipelines** para garantir a regra 2.
:::

### 2.10.4 Reprodutibilidade

Muitos algoritmos sorteiam números. Para que seus resultados possam ser repetidos por outra pessoa, fixe sempre a **semente** (`random_state`). Nos nossos experimentos, a semente aparece sempre explícita.

E lembre-se: com **poucos rótulos**, os resultados variam muito de um sorteio para outro. Reporte **média e desvio padrão** de várias repetições, e não de uma só.
