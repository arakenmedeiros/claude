## 8.1 Do Q-learning à rede Q

No Capítulo 7, vimos que tabelas não escalam e que a aproximação de funções permite generalizar. Agora damos o passo decisivo: usar **redes neurais** como aproximador de **q**(s, a). O resultado é o **Deep Q-Network** (**DQN**), de Mnih e colegas (2015), considerado o marco inicial do **aprendizado por reforço profundo** (*deep reinforcement learning*).

A ideia é simples:

- A **entrada** da rede é o **estado** (por exemplo, os 4 números do CartPole ou os pixels de um jogo).
- A **saída** é um **valor Q para cada ação**.
- A ação escolhida é a de maior Q (com um pouco de exploração).

![f8_rede](Figura 8.1 — Rede Q para o CartPole: 4 números entram; dois valores Q (um por ação) saem.)

## 8.2 Redes neurais em dez minutos

### 8.2.1 O neurônio artificial

Um **neurônio artificial** faz três coisas:

1. **Multiplica** cada entrada por um **peso** (*w*).
2. **Soma** tudo e acrescenta um número chamado **viés** (*b*).
3. Passa o resultado por uma **função de ativação** *f*, que acrescenta curvas ao cálculo.

$$ saída = f( w_1 x_1 + w_2 x_2 + … + w_n x_n + b ) $$

A ativação mais comum hoje é a **ReLU**: devolve o número se for positivo e zero caso contrário, ou seja, max(0, x).

![f8_neuronio](Figura 8.2 — À esquerda, o neurônio artificial. À direita, três funções de ativação populares.)

### 8.2.2 Camadas e profundidade

Juntando muitos neurônios em **camadas**, obtemos uma **rede neural**. A saída de uma camada é a entrada da seguinte. Redes com várias camadas ocultas são **profundas**. Cada camada aprende a combinar o que a anterior descobriu, de características simples a conceitos complexos (LECUN; BENGIO; HINTON, 2015).

Uma rede com camadas suficientes pode aproximar praticamente qualquer função contínua. É por isso que redes neurais são aproximadores tão poderosos (GOODFELLOW; BENGIO; COURVILLE, 2016).

### 8.2.3 Como a rede aprende

O treinamento repete quatro ideias que você já conhece:

1. **Prever** com os pesos atuais.
2. Medir o **erro** (a **perda**): por exemplo, (alvo − previsão)².
3. Calcular o **gradiente** do erro em relação a cada peso. Isso é feito eficientemente pela **retropropagação** (*backpropagation*), que aplica a regra da cadeia da última camada para a primeira (RUMELHART; HINTON; WILLIAMS, 1986).
4. **Ajustar** os pesos um pouco, no sentido que reduz o erro (descida do gradiente). O otimizador **Adam** é o mais usado (KINGMA; BA, 2015).

:::cotidiano Treinar uma rede é como afinar uma orquestra
Cada peso é um botão de afinação. A perda mede o quanto a música está desafinada. O gradiente diz, para cada botão, em que direção girar para melhorar. Giramos todos um pouquinho, ouvimos de novo e repetimos milhares de vezes.
:::

## 8.3 Por que redes + Q-learning dão problema

Se treinássemos a rede Q com o Q-learning "ingênuo", encontraríamos dois problemas principais, que se somam ao triângulo mortal do Capítulo 7.

1. **Dados correlacionados.** Estados consecutivos de um episódio são muito parecidos. Treinar com eles em sequência é como estudar para uma prova lendo apenas o mesmo capítulo repetidas vezes: a rede "esquece" o resto.
2. **Alvo móvel.** O alvo y = r + γ max Q(s′, a′; θ) usa a **própria rede**. Cada vez que atualizamos θ, o alvo muda. É como perseguir o próprio rabo.

O DQN propõe dois remédios engenhosos.

## 8.4 Truque 1: repetição de experiência

Em vez de aprender com a transição que acabou de acontecer, o agente a **guarda** numa **memória de experiências** (*replay buffer*) e, a cada passo, **sorteia um lote aleatório** de transições antigas para treinar (LIN, 1992).

![f8_replay](Figura 8.3 — A memória de experiências embaralha o passado: o lote usado no treino é quase independente em vez de uma sequência correlacionada.)

Vantagens:

- **Quebra a correlação** entre amostras consecutivas.
- **Reaproveita** cada experiência muitas vezes, aumentando a eficiência dos dados.
- Torna o treino mais **estável** e parecido com o aprendizado supervisionado.

Em compensação, só funciona com métodos **off-policy** (o Q-learning é), pois os dados antigos vêm de políticas passadas.

## 8.5 Truque 2: a rede-alvo

O DQN mantém **duas redes** com a mesma arquitetura:

- a **rede online** (parâmetros θ), que é treinada a cada passo e decide as ações;
- a **rede-alvo** (parâmetros θ⁻), uma **cópia congelada** da online, usada **só para calcular o alvo** y. A cada C passos (por exemplo, 250 ou 1.000), copiamos θ para θ⁻.

$$ y = r + γ max_(a′) Q(s′, a′; θ⁻)        perda = ( y − Q(s, a; θ) )² $$

Com o alvo parado por um tempo, o problema vira um aprendizado supervisionado temporariamente estável. Em vez de perseguir o próprio rabo, a rede persegue um alvo que **muda devagar**.

![f8_dqn](Figura 8.4 — Visão geral do DQN: o agente age, guarda as transições, sorteia lotes da memória, calcula o alvo com a rede-alvo e atualiza a rede online.)

## 8.6 O algoritmo DQN, passo a passo

:::memorize O DQN em oito passos
1. Inicialize a rede online (θ) e a rede-alvo (θ⁻ = θ). Crie a memória vazia.
2. Observe o estado *s*.
3. Escolha a ação *a* por ε-gulosa, com ε decrescendo ao longo do treino.
4. Execute *a*; observe *r*, *s′* e se terminou.
5. Guarde (s, a, r, s′, terminou) na memória.
6. Sorteie um lote da memória.
7. Calcule o alvo y com a rede-alvo (y = r se terminou) e atualize θ para reduzir (y − Q(s, a; θ))².
8. A cada C passos, copie θ para θ⁻. Volte ao passo 2.
:::

Dois detalhes práticos importantes:

- **Perda de Huber** (`smooth_l1_loss`): quadrática para erros pequenos e linear para grandes. Evita que alguns erros enormes dominem o gradiente.
- **Recorte do gradiente** (*gradient clipping*): limita o tamanho do passo, outra proteção contra instabilidade.

## 8.7 O DQN que jogou Atari

O DQN original aprendeu a jogar **dezenas de jogos de Atari** a partir **apenas dos pixels** e da pontuação, usando **o mesmo algoritmo e os mesmos hiperparâmetros em todos os jogos** (MNIH et al., 2015). Os jogos vêm do *Arcade Learning Environment* (BELLEMARE et al., 2013). Em 29 dos 49 jogos testados, o DQN atingiu ao menos 75% do escore de um testador humano profissional.

![f8_cnn](Figura 8.5 — A rede do DQN para Atari: uma pilha de 4 imagens passa por 3 camadas convolucionais e uma camada totalmente conectada, produzindo um valor Q por ação.)

Detalhes de pré-processamento (resumidos):

- A imagem é convertida para **tons de cinza** e reduzida para **84 × 84**.
- Empilham-se **4 quadros consecutivos**, para o estado conter movimento (velocidade e direção).
- A cada ação, repete-se o movimento por **4 quadros** (*frame skip*).
- As recompensas são **recortadas** para −1, 0 e +1, para padronizar a escala entre jogos.

As **camadas convolucionais** são o tipo de camada usado em imagens: filtros pequenos "deslizam" sobre a imagem detectando padrões (bordas, formas) e compartilham pesos, o que reduz muito o número de parâmetros.

## 8.8 Extensões do DQN

Depois de 2015, vieram várias melhorias, quase todas **combináveis**.

### 8.8.1 Double DQN

O viés de maximização (Capítulo 6) também afeta o DQN, que superestima valores. O **Double DQN** usa a rede **online** para **escolher** a melhor ação em s′ e a rede-alvo para **avaliá-la** (VAN HASSELT; GUEZ; SILVER, 2016):

$$ y = r + γ Q( s′, argmax_(a′) Q(s′, a′; θ); θ⁻ ) $$

É uma mudança de uma linha de código, com ganho consistente.

### 8.8.2 Repetição de experiência priorizada

Nem toda transição ensina o mesmo. A **repetição priorizada** sorteia com maior probabilidade as transições com **maior erro TD** (as mais "surpreendentes"), aprendendo mais rápido (SCHAUL et al., 2016). Um fator de correção (peso de importância) evita viés.

### 8.8.3 Dueling

A arquitetura **dueling** separa a rede em dois ramos: o **valor do estado** V(s) e a **vantagem** A(s, a), quanto cada ação supera a média. Os dois se combinam em Q (WANG et al., 2016). Isso ajuda quando em muitos estados a escolha da ação importa pouco.

![f8_dueling](Figura 8.6 — Arquitetura dueling: um ramo estima o valor do estado, outro a vantagem de cada ação; a soma dá os valores Q.)

### 8.8.4 Alvos de múltiplos passos

Em vez de olhar um passo à frente, usa-se o **n-step** (Capítulo 6): somam-se n recompensas reais antes de estimar com a rede-alvo. Propaga recompensas mais rápido.

### 8.8.5 DQN distribucional

Em vez de aprender só a **média** do retorno, aprende-se a **distribuição inteira** (BELLEMARE; DABNEY; MUNOS, 2017). Isso fornece mais informação ao aprendizado, mesmo que a decisão use a média.

### 8.8.6 Redes com ruído (Noisy Nets)

Em vez da exploração ε-gulosa, acrescenta-se **ruído aprendido aos pesos** da rede. A rede aprende a **quanto explorar** em cada situação (FORTUNATO et al., 2018).

### 8.8.7 Rainbow

O **Rainbow** combina seis dessas ideias num só agente e supera cada uma isolada em Atari (HESSEL et al., 2018).

![f8_extensoes](Figura 8.7 — O Rainbow reúne o DQN e seis extensões.)

## 8.9 Hiperparâmetros e depuração

| Hiperparâmetro | Valores típicos | Efeito |
|---|---|---|
| Taxa de aprendizado | 10⁻⁴ a 10⁻³ | Muito alta: instável; muito baixa: lento |
| γ | 0,95 a 0,99 | Horizonte de planejamento |
| Tamanho da memória | 10⁴ a 10⁶ | Mais memória, mais diversidade |
| Lote | 32 a 256 | Estabilidade do gradiente |
| Troca da rede-alvo (C) | 250 a 10.000 passos | Maior: mais estável, mais lento |
| ε inicial → final | 1 → 0,01 a 0,1 | Exploração |

Dicas de depuração:

- **Verifique o ambiente** com um agente aleatório e um agente manual.
- **Monitore** o retorno por episódio, a perda e a média dos valores Q: valores Q **explodindo** indicam instabilidade.
- **Reduza** o problema: ache um ambiente mais simples em que o algoritmo funcione.
- **Várias sementes:** o desempenho varia muito (HENDERSON et al., 2018).

## 8.10 Mão na massa

### 8.10.1 DQN em PyTorch

Vamos implementar o DQN completo em uma função. O parâmetro `usar_replay` liga/desliga a memória, `usar_alvo` liga/desliga a rede-alvo e `duplo` ativa o Double DQN. (Veja o Apêndice G para PyTorch.)

```python
import random, time
from collections import deque
import numpy as np
import torch, torch.nn as nn
import gymnasium as gym
torch.set_num_threads(1)

def criar_rede(n_obs, n_acoes, ocultas=128):
    return nn.Sequential(nn.Linear(n_obs, ocultas), nn.ReLU(),
                         nn.Linear(ocultas, ocultas), nn.ReLU(),
                         nn.Linear(ocultas, n_acoes))

def treinar_dqn(semente=0, n_ep=300, usar_replay=True, usar_alvo=True, duplo=False, lr=5e-4, gamma=0.99,
                lote=64, tam_memoria=50_000, aquecimento=1000, troca_alvo=250, decaimento_eps=5000,
                env_id="CartPole-v1", verbose=False):
    random.seed(semente); np.random.seed(semente); torch.manual_seed(semente)
    env = gym.make(env_id); n_obs = env.observation_space.shape[0]; n_acoes = env.action_space.n
    q = criar_rede(n_obs, n_acoes); q_alvo = criar_rede(n_obs, n_acoes); q_alvo.load_state_dict(q.state_dict())
    if not usar_alvo: q_alvo = q                                   # sem rede-alvo: o alvo usa a própria rede
    if not usar_replay: tam_memoria, lote, aquecimento = 1, 1, 1   # sem memória: só a transição mais recente
    opt = torch.optim.Adam(q.parameters(), lr=lr)
    memoria = deque(maxlen=tam_memoria); passo = 0; retornos = []
    for ep in range(n_ep):
        obs, _ = env.reset(seed=semente * 10_000 + ep); fim, total = False, 0.0
        while not fim:
            eps = max(0.05, 1 - passo / decaimento_eps)             # ε decresce linearmente
            if random.random() < eps: a = env.action_space.sample()
            else:
                with torch.no_grad(): a = int(q(torch.as_tensor(obs, dtype=torch.float32)).argmax())
            obs2, r, term, trunc, _ = env.step(a); fim = term or trunc; total += r
            memoria.append((obs, a, r, obs2, float(term))); obs = obs2; passo += 1
            if len(memoria) >= aquecimento:
                O, A, R, O2, T = map(np.array, zip(*random.sample(memoria, min(lote, len(memoria)))))
                O, O2, R, T = [torch.as_tensor(x, dtype=torch.float32) for x in (O, O2, R, T)]; A = torch.as_tensor(A)
                with torch.no_grad():
                    if duplo:                                        # Double DQN
                        a_star = q(O2).argmax(1, keepdim=True); proximo = q_alvo(O2).gather(1, a_star).squeeze(1)
                    else:
                        proximo = q_alvo(O2).max(1).values
                    y = R + gamma * (1 - T) * proximo                # alvo (sem valor futuro se terminou)
                pred = q(O).gather(1, A.unsqueeze(1)).squeeze(1)     # Q(s, a) das ações tomadas
                perda = nn.functional.smooth_l1_loss(pred, y)        # perda de Huber
                opt.zero_grad(); perda.backward(); nn.utils.clip_grad_norm_(q.parameters(), 10.0); opt.step()
            if usar_alvo and passo % troca_alvo == 0: q_alvo.load_state_dict(q.state_dict())
        retornos.append(total)
        if verbose and (ep + 1) % 50 == 0:
            print(f"episódio {ep+1:4d} | retorno médio (últimos 50) = {np.mean(retornos[-50:]):6.1f}", flush=True)
    return q, np.array(retornos)

t0 = time.time()
q_treinada, retornos = treinar_dqn(semente=0, n_ep=300, verbose=True)
print(f"Tempo de treino: {time.time() - t0:.0f} s")
```

**O que observar:** o retorno médio sobe de cerca de 20 (comportamento aleatório) para valores na casa das centenas, com **oscilações**: o DQN é instável, e é comum o desempenho cair depois de subir. Rode outras sementes e veja a variação.

### 8.10.2 Avaliando a política treinada

Para avaliar, usamos a política **gulosa** (sem exploração) e um intervalo de confiança por *bootstrap* do scikit-learn.

```python
from sklearn.utils import resample

def avaliar_rede(q, n=30, env_id="CartPole-v1"):
    env = gym.make(env_id); ret = []
    for i in range(n):
        obs, _ = env.reset(seed=50_000 + i); fim, total = False, 0.0
        while not fim:
            with torch.no_grad(): a = int(q(torch.as_tensor(obs, dtype=torch.float32)).argmax())
            obs, r, term, trunc, _ = env.step(a); total += r; fim = term or trunc
        ret.append(total)
    return np.array(ret)

ret_av = avaliar_rede(q_treinada)
boot = [resample(ret_av, random_state=b).mean() for b in range(300)]
print(f"Política gulosa: retorno médio = {ret_av.mean():.1f} (IC 95%: {np.percentile(boot, 2.5):.1f} a {np.percentile(boot, 97.5):.1f})")
print(f"Durante o treino, nos últimos 50 episódios (com exploração): {retornos[-50:].mean():.1f}")
```

## 8.11 Projeto do capítulo: um DQN para o estoque de uma loja

**Contexto.** Uma loja precisa decidir, a cada dia, **quanto repor** de um produto. Se pedir demais, paga estoque parado; se pedir de menos, perde vendas. Vamos construir um **ambiente próprio** (no padrão do Gymnasium, Apêndice F) usando a **demanda diária real** do produto mais vendido da base **Online Retail** (UCI), e treinar um DQN com o Stable-Baselines3.

:::atencao Limitações
A demanda histórica é uma **única trajetória** do mundo: o ambiente assume que as decisões de reposição **não afetam a demanda** (razoável para um produto de oferta abundante) e que o pedido chega imediatamente (sem prazo de entrega). Discuta essas simplificações no seu relatório.
:::

**Tarefas:**

1. Construa a série de demanda diária do produto mais frequente (dias sem venda contam como 0).
2. Complete o ambiente `EstoqueEnv` (abaixo), com estado = estoque, demanda do dia anterior, média de 7 dias e dia da semana; ações = quantidade a pedir; recompensa = receita − custo de compra − custo de estocagem − multa por venda perdida.
3. Separe **70% dos dias para treino** e **30% para teste** (em ordem cronológica).
4. Treine um DQN (30.000 passos ou mais) com o Stable-Baselines3.
5. Compare, no período de teste, com uma política (s, S) (pedir até S se o estoque ficar abaixo de s) com s e S ajustados por busca em grade (`ParameterGrid`) **no período de treino**.
6. Escreva uma conclusão (8 a 10 linhas): o DQN superou o baseline? Por que sim ou não?

**Ponto de partida:**

```python
import pandas as pd
from gymnasium import spaces
from ucimlrepo import fetch_ucirepo
from sklearn.model_selection import ParameterGrid
from stable_baselines3 import DQN
from stable_baselines3.common.evaluation import evaluate_policy

df = fetch_ucirepo(id=352).data.original.copy()
df = df[(df["Quantity"] > 0) & (df["UnitPrice"] > 0) & (~df["InvoiceNo"].astype(str).str.startswith("C"))]
top = df["StockCode"].value_counts().index[0]
d = df[df["StockCode"] == top].copy(); d["dia"] = pd.to_datetime(d["InvoiceDate"]).dt.normalize()
serie = d.groupby("dia")["Quantity"].sum()
serie = serie.reindex(pd.date_range(serie.index.min(), serie.index.max(), freq="D"), fill_value=0)
demanda = serie.to_numpy().astype(float); dias_sem = serie.index.dayofweek.to_numpy()
corte = int(0.7 * len(demanda)); preco_medio = float(d["UnitPrice"].median())

class EstoqueEnv(gym.Env):
    PEDIDOS = np.array([0, 10, 20, 40, 80]); EST_MAX = 200
    def __init__(self, demanda, dias_sem, horizonte=30, preco=preco_medio):
        super().__init__()
        self.dem, self.dsem, self.H, self.p = demanda, dias_sem, horizonte, preco
        self.custo, self.estoc, self.multa = 0.6 * preco, 0.01 * preco, 0.3 * preco
        self.escala = max(demanda.mean(), 1.0)
        self.action_space = spaces.Discrete(len(self.PEDIDOS))
        self.observation_space = spaces.Box(0.0, 10.0, shape=(4,), dtype=np.float32)
    def _obs(self):
        ontem = self.dem[self.i - 1] if self.i > 0 else 0.0
        media7 = self.dem[max(0, self.i - 7):self.i].mean() if self.i > 0 else 0.0
        return np.array([self.estoque / self.EST_MAX * 10, ontem / self.escala, media7 / self.escala, self.dsem[self.i] / 6 * 10], dtype=np.float32)
    def reset(self, seed=None, options=None):
        super().reset(seed=seed)
        self.i0 = int(self.np_random.integers(7, len(self.dem) - self.H - 1)); self.i = self.i0; self.t = 0; self.estoque = 20.0
        return self._obs(), {}
    def step(self, acao):
        self.estoque = min(self.estoque + self.PEDIDOS[acao], self.EST_MAX)
        d = self.dem[self.i]; vendas = min(d, self.estoque)
        r = vendas * self.p - self.PEDIDOS[acao] * self.custo - (self.estoque - vendas) * self.estoc - (d - vendas) * self.multa
        self.estoque -= vendas; self.i += 1; self.t += 1
        return self._obs(), float(r), False, self.t >= self.H, {}

env_tr = EstoqueEnv(demanda[:corte], dias_sem[:corte]); env_te = EstoqueEnv(demanda[corte:], dias_sem[corte:])
modelo = DQN("MlpPolicy", env_tr, learning_rate=5e-4, buffer_size=30_000, learning_starts=500, batch_size=64,
             target_update_interval=250, exploration_fraction=0.3, policy_kwargs=dict(net_arch=[64, 64]), verbose=0, seed=0)
modelo.learn(total_timesteps=15_000)
print("DQN no teste:", round(evaluate_policy(modelo, env_te, n_eval_episodes=100)[0], 1))

def politica_sS(env, s, S):
    obs, _ = env.reset(seed=0); total, ret = 0.0, []
    for _ in range(100):
        obs, _ = env.reset(); fim, total = False, 0.0
        while not fim:
            falta = S - env.estoque if env.estoque < s else 0
            a = int(np.argmin(np.abs(env.PEDIDOS - falta)))               # pedido mais próximo da quantidade desejada
            obs, r, term, trunc, _ = env.step(a); total += r; fim = term or trunc
        ret.append(total)
    return np.mean(ret)

melhor = max(ParameterGrid({"s": [5, 10, 20, 40], "S": [30, 60, 100]}), key=lambda p: politica_sS(env_tr, **p))
print("melhor (s, S) no treino:", melhor, "| desempenho no teste:", round(politica_sS(env_te, **melhor), 1))
```

**O que observar:** com poucos passos de treino (15.000), é comum o DQN ficar **atrás** de uma política (s, S) bem ajustada, que é um baseline forte para estoques. Aumente o treino, ajuste os hiperparâmetros e compare com várias sementes antes de concluir. Saber que um baseline simples é difícil de bater é parte da lição.
