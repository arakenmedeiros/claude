## 11.1 Uma agulha no palheiro

Imagine um guarda de segurança que olha mil câmeras. Quase tudo é rotina. Seu trabalho é perceber **aquela cena diferente**: alguém pulando o muro, uma mala abandonada.

Detectar anomalias é exatamente isso. Uma **anomalia** (ou *outlier*, ou "valor atípico") é um dado que **destoa do padrão esperado**. Hawkins (1980) a definiu como "uma observação que se desvia tanto das demais que desperta a suspeita de ter sido gerada por um mecanismo diferente".

Aplicações:

- **Finanças:** fraude em cartão, lavagem de dinheiro.
- **Indústria:** falhas de máquinas antes da quebra (manutenção preditiva).
- **Saúde:** exames atípicos, eletrocardiogramas anormais.
- **TI e segurança:** intrusões em redes, comportamento incomum de usuário.
- **Qualidade de dados:** erros de digitação e sensores defeituosos.

![f11_agulha](Figura 11.1 — Anomalias são raras e diferentes: o desafio é achar os poucos pontos que fogem do comportamento normal.)

## 11.2 Tipos de anomalia

Chandola, Banerjee e Kumar (2009) organizam as anomalias em três tipos.

1. **Pontual:** um único ponto muito diferente do resto. *Exemplo:* uma compra de R$ 50.000 num cartão cujo gasto médio é R$ 300.
2. **Contextual:** um valor normal em um contexto, mas anormal em outro. *Exemplo:* 30 °C é normal em janeiro e anormal em julho no Sul do Brasil.
3. **Coletiva:** um **conjunto** de pontos é anormal, embora cada um, isolado, seja normal. *Exemplo:* uma sequência de batimentos cardíacos que, individualmente, parecem normais, mas juntos revelam arritmia.

![f11_tipos](Figura 11.2 — Os três tipos de anomalia numa série temporal: pontual, contextual e coletiva.)

## 11.3 Os três cenários de aprendizado

- **Supervisionado:** há exemplos rotulados de normal **e** de anômalo. Vira um problema de classificação, mas com classes muito desbalanceadas.
- **Semissupervisionado (*one-class*):** só há exemplos **normais** para treinar. Qualquer coisa muito diferente é suspeita.
- **Não supervisionado:** **nenhum rótulo.** Assume-se que anomalias são **raras** e **diferentes**. É o foco deste capítulo.

## 11.4 Métodos estatísticos simples

Antes de algoritmos sofisticados, experimente o básico. Funcionam surpreendentemente bem.

### 11.4.1 Z-score

Calcula quantos desvios padrão um ponto está da média. Regra comum: |z| > 3 é suspeito.

$$ z = (x − média) / desvio padrão $$

**Fraqueza:** média e desvio são afetados pelos próprios outliers ("mascaramento").

### 11.4.2 Z-score modificado (MAD)

Usa a **mediana** e o **desvio absoluto mediano** (MAD), robustos a extremos (Iglewicz; Hoaglin, 1993):

$$ z_mod = 0,6745 · (x − mediana) / MAD $$

Regra: |z_mod| > 3,5 é suspeito.

### 11.4.3 Regra do IQR (boxplot)

Calcule o primeiro quartil (Q1, abaixo do qual estão 25 % dos dados) e o terceiro (Q3). O **IQR** = Q3 − Q1. São suspeitos os valores abaixo de Q1 − 1,5·IQR ou acima de Q3 + 1,5·IQR (Tukey, 1977).

```python
import numpy as np

rng = np.random.default_rng(1)
x = np.concatenate([rng.normal(100, 10, 200), [180, 195, 20]])   # 3 anomalias plantadas

z = (x - x.mean()) / x.std()
mad = np.median(np.abs(x - np.median(x)))
zmod = 0.6745 * (x - np.median(x)) / mad
q1, q3 = np.percentile(x, [25, 75])
iqr = q3 - q1

print("Z-score  |z|>3     :", np.where(np.abs(z) > 3)[0])
print("MAD      |z|>3.5   :", np.where(np.abs(zmod) > 3.5)[0])
print("IQR  (1,5 x IQR)   :", np.where((x < q1 - 1.5 * iqr) | (x > q3 + 1.5 * iqr))[0])
```

### 11.4.4 Distância de Mahalanobis

Para vários atributos, a distância Euclidiana ignora as correlações. A **distância de Mahalanobis** leva em conta a covariância: mede a distância em "desvios padrão" na direção do ponto, considerando a forma da nuvem (Mahalanobis, 1936).

*Exemplo:* uma pessoa de 1,90 m e 50 kg. Cada medida é comum, mas **a combinação** é incomum, pois altura e peso costumam andar juntos. Mahalanobis percebe isso; a Euclidiana, não.

```python
import numpy as np
from sklearn.covariance import EmpiricalCovariance, MinCovDet

rng = np.random.default_rng(0)
altura = rng.normal(170, 8, 300)
peso = 0.9 * (altura - 100) + rng.normal(0, 5, 300)
X = np.column_stack([altura, peso])
X = np.vstack([X, [190, 50]])                      # combinação atípica

robusto = MinCovDet(random_state=0).fit(X)         # estimador robusto de covariância
d2 = robusto.mahalanobis(X)                        # distância ao quadrado
print("Índices mais suspeitos:", np.argsort(d2)[-3:][::-1], " (o último é", len(X) - 1, ")")
```

## 11.5 Isolation Forest

### 11.5.1 A ideia genial

Liu, Ting e Zhou (2008) tiveram uma ideia diferente: em vez de modelar o "normal" e ver quem destoa, **isolar** os pontos.

Anomalias são **poucas e diferentes**, portanto, são **fáceis de isolar**.

*Analogia:* o jogo "20 perguntas". Para adivinhar uma pessoa comum numa multidão, você precisa de muitas perguntas. Para adivinhar o único homem de smoking numa festa de camiseta, basta uma.

### 11.5.2 Como funciona

1. Construa uma **árvore de isolamento**: escolha um atributo ao acaso e um valor de corte ao acaso entre o mínimo e o máximo. Divida os dados. Repita recursivamente até cada ponto ficar sozinho.
2. Repita para centenas de árvores com subamostras diferentes (a **floresta**).
3. Para cada ponto, calcule a **profundidade média** em que ele ficou isolado.
4. **Profundidade pequena = isolamento rápido = anomalia.**

![f11_iforest](Figura 11.3 — Isolation Forest: o ponto anômalo é isolado com poucos cortes; um ponto normal, no meio da multidão, exige muitos.)

O **escore de anomalia** é normalizado entre 0 e 1: perto de 1, anomalia; abaixo de 0,5, normal.

```python
import numpy as np
from sklearn.ensemble import IsolationForest

rng = np.random.default_rng(0)
normais = rng.normal(0, 1, size=(500, 2))
anomalias = rng.uniform(-6, 6, size=(15, 2))
X = np.vstack([normais, anomalias])

iso = IsolationForest(n_estimators=200, contamination=0.03, random_state=0).fit(X)
pred = iso.predict(X)                 # +1 normal, -1 anomalia
escore = -iso.score_samples(X)        # quanto maior, mais anômalo

print("Anomalias apontadas:", (pred == -1).sum())
print("Acertos entre as 15 plantadas:", (pred[-15:] == -1).sum())
```

**Vantagens:** rápido (linear), poucos parâmetros, funciona em muitas dimensões. **Limites:** cortes paralelos aos eixos podem falhar com anomalias muito específicas; o parâmetro `contamination` precisa de estimativa.

## 11.6 LOF: Fator de Outlier Local

### 11.6.1 O problema da densidade variável

Em um bairro central, as casas são vizinhas de parede. Em um bairro rural, ficam a quilômetros. Uma casa a 200 m da vizinha é **normal** no campo, mas seria **estranha** no centro. A anomalia depende da **densidade local**.

O **LOF** (*Local Outlier Factor*; Breunig et al., 2000) compara a densidade em torno de um ponto com a densidade em torno de seus vizinhos.

- **LOF ≈ 1:** densidade parecida com a dos vizinhos (normal).
- **LOF >> 1:** o ponto está numa região muito menos densa que a dos vizinhos (anomalia).

![f11_lof](Figura 11.4 — LOF: o ponto vermelho está mais isolado que os vizinhos do grupo denso, então tem LOF alto, mesmo estando mais perto que pontos normais do grupo esparso.)

```python
import numpy as np
from sklearn.neighbors import LocalOutlierFactor

rng = np.random.default_rng(0)
denso   = rng.normal([0, 0], 0.3, size=(300, 2))
esparso = rng.normal([5, 5], 1.5, size=(100, 2))
suspeito = np.array([[1.2, 1.2]])                  # perto do denso, mas fora dele
X = np.vstack([denso, esparso, suspeito])

lof = LocalOutlierFactor(n_neighbors=20, contamination=0.01)
pred = lof.fit_predict(X)
escore = -lof.negative_outlier_factor_
print("Escore LOF do ponto suspeito:", round(escore[-1], 2))
print("Escore LOF mediano do resto :", round(float(np.median(escore[:-1])), 2))
```

Por padrão, o LOF só rotula os dados de treino. Para pontos novos, use `novelty=True` (e `predict` em dados novos).

:::atencao O LOF e os grupos de anomalias
O parâmetro `n_neighbors` precisa ser **maior que o tamanho dos grupos de anomalias**. Se há, por exemplo, 200 fraudes parecidas entre si e você usa 30 vizinhos, cada fraude só enxerga outras fraudes e parece normal: o LOF falha. No projeto do Capítulo 11, o AUPRC do LOF sobe de cerca de 0,02 (com 30 vizinhos) para cerca de 0,91 (com 300).
:::

## 11.7 One-Class SVM

Schölkopf et al. (2001) propuseram aprender a **fronteira** que envolve os dados normais.

*Ideia:* usando um kernel (Capítulo 8), mapeie os dados para um espaço de alta dimensão e procure o hiperplano que separa os dados da **origem** com a maior margem. Tudo que ficar do lado da origem é anomalia.

*Analogia:* você desenha uma "cerca" em volta da multidão. Quem está fora é suspeito.

![f11_ocsvm](Figura 11.5 — One-Class SVM: a fronteira envolve a região normal e deixa de fora os pontos atípicos.)

Parâmetros: `nu` (limite superior da fração de anomalias, entre 0 e 1) e `gamma` (flexibilidade da fronteira).

:::atencao O gamma faz muita diferença
Com `gamma="scale"`, o One-Class SVM pode ficar estreito demais e marcar muitos pontos normais como anomalias, ou ter desempenho pior que o acaso. Nos exercícios do capítulo, o mesmo modelo passa de AUC-ROC de 0,44 (gamma padrão) para 0,95 (gamma = 0,005). Ajuste e compare sempre.
:::

```python
import numpy as np
from sklearn.svm import OneClassSVM
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
treino = rng.normal(0, 1, size=(400, 2))              # só dados normais
teste = np.vstack([rng.normal(0, 1, (50, 2)),         # normais
                   rng.uniform(-6, 6, (10, 2))])      # possíveis anomalias

esc = StandardScaler().fit(treino)
modelo = OneClassSVM(kernel="rbf", gamma=0.3, nu=0.05).fit(esc.transform(treino))
pred = modelo.predict(esc.transform(teste))
print("Marcados como anomalia:", (pred == -1).sum(), "de", len(teste))
```

## 11.8 Outros métodos importantes

- **Densidade com GMM** (Capítulo 6): pontos com baixa densidade sob o modelo são suspeitos. Use `score_samples`.
- **DBSCAN** (Capítulo 5): os pontos de ruído (rótulo −1) são candidatos.
- **kNN:** a distância ao *k*-ésimo vizinho como escore (Ramaswamy; Rastogi; Shim, 2000).
- **PCA:** o **erro de reconstrução** é alto para pontos que não seguem a estrutura principal.
- **Autoencoders** (Capítulo 12): treinados com dados normais, reconstroem mal os anômalos.
- **ECOD e COPOD** (Li et al., 2023; Li et al., 2020): métodos rápidos, baseados em caudas das distribuições, sem parâmetros.
- **Séries temporais:** modelos de previsão (ARIMA, redes recorrentes) e o erro de previsão como escore.

### 11.8.1 PCA para anomalias

```python
import numpy as np
from sklearn.decomposition import PCA

rng = np.random.default_rng(0)
base = rng.normal(size=(500, 3))
ruido = 0.1 * rng.normal(size=(500, 10))
X = base @ rng.normal(size=(3, 10)) + ruido    # dados em ~3 dimensões
X[0] += 5 * rng.normal(size=10)                # ponto que quebra a estrutura

pca = PCA(n_components=3).fit(X)
erro = np.sum((X - pca.inverse_transform(pca.transform(X))) ** 2, axis=1)
print("Ponto mais anômalo:", erro.argmax())
print("Erro dele:", erro.max().round(1), "| erro mediano:", np.median(erro).round(2))
```

## 11.9 Comparando os métodos

![f11_comparacao](Figura 11.6 — Quatro detectores no mesmo conjunto de dados: cada um desenha uma fronteira diferente.)

| Método | Ideia | Pontos fortes | Pontos fracos |
|---|---|---|---|
| Z-score / MAD / IQR | Estatística simples | Rápido, explicável | Pouco para multivariado |
| Mahalanobis | Distância com covariância | Capta correlações | Supõe formato elíptico |
| Isolation Forest | Facilidade de isolar | Escalável, poucos parâmetros | Parâmetro de contaminação |
| LOF | Densidade local | Densidades variáveis | Escolha de *k*, custo |
| One-Class SVM | Fronteira em espaço kernel | Fronteiras flexíveis | Sensível a gamma/nu, lento |
| GMM | Densidade probabilística | Probabilidades | Supõe gaussianas |
| Autoencoder | Erro de reconstrução | Alta dimensão, imagens | Treino, ajuste |

## 11.10 Definindo o limiar

Detectores devolvem um **escore**. Quem decide o que é anomalia é o **limiar**.

Opções:

1. **Fração esperada** (contaminação): marque os 1 % maiores escores.
2. **Percentil:** 99º percentil dos escores no treino.
3. **Teoria de valores extremos**: modela a cauda dos escores (Siffer et al., 2017).
4. **Custo:** escolha o limiar que minimiza o custo total de falsos positivos e falsos negativos.
5. **Capacidade operacional:** o time só consegue investigar 50 alertas por dia → o limiar é o 50º maior escore.

![f11_limiar](Figura 11.7 — Histograma dos escores: o limiar separa o "normal" do "suspeito". Mover o limiar troca falsos alarmes por anomalias perdidas.)

## 11.11 Como avaliar?

Em anomalias, as classes são muito desbalanceadas (ex.: 0,1 % de fraudes). Um modelo que sempre diz "normal" teria 99,9 % de **acurácia** e seria inútil!

Prefira:

- **Precisão (*precision*):** dos alertas, quantos eram anomalias reais?
- **Revocação (*recall*):** das anomalias reais, quantas foram pegas?
- **F1:** média harmônica de precisão e revocação.
- **Curva Precisão-Revocação e AUPRC:** mais informativas que a ROC em dados muito desbalanceados (Saito; Rehmsmeier, 2015).
- **AUC-ROC:** útil, mas otimista com desbalanceamento extremo.
- **Precisão@k:** dos *k* maiores escores, quantos são reais?

```python
import numpy as np
from sklearn.ensemble import IsolationForest
from sklearn.metrics import roc_auc_score, average_precision_score

rng = np.random.default_rng(0)
X = np.vstack([rng.normal(0, 1, (1000, 4)), rng.normal(3, 1.5, (20, 4))])
y = np.r_[np.zeros(1000), np.ones(20)]                    # só para avaliar!

escore = -IsolationForest(random_state=0).fit(X).score_samples(X)
print("AUC-ROC:", round(roc_auc_score(y, escore), 3))
print("AUPRC  :", round(average_precision_score(y, escore), 3))
print("Linha de base AUPRC (acaso):", round(y.mean(), 3))
```
