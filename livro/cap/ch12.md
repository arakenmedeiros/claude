## 12.1 Das técnicas clássicas às redes profundas

Nos capítulos anteriores, vimos técnicas clássicas: K-means, PCA, t-SNE. Elas funcionam muito bem, mas dependem de **atributos bem escolhidos**. Para imagens, textos e áudios, o "pixel cru" ou a "palavra crua" raramente é o melhor atributo.

O **aprendizado profundo** (*deep learning*) permite que a própria máquina **aprenda os atributos** a partir dos dados (LeCun; Bengio; Hinton, 2015). Quando isso é feito sem rótulos, temos o **aprendizado de representações não supervisionado** (Bengio; Courville; Vincent, 2013).

![f12_mapa](Figura 12.1 — Árvore de métodos profundos não supervisionados: autoencoders, modelos generativos e aprendizado auto-supervisionado.)

## 12.2 Redes neurais em cinco minutos

### 12.2.1 O neurônio artificial

Um **neurônio artificial** recebe números, multiplica cada um por um **peso**, soma tudo e aplica uma função não linear (a **ativação**).

$$ saída = ativação( w₁·x₁ + w₂·x₂ + … + b ) $$

- **Pesos (w):** a "importância" de cada entrada. São aprendidos.
- **Viés (b):** um deslocamento, também aprendido.
- **Ativação:** por exemplo, a **ReLU**, que devolve 0 para negativos e o próprio valor para positivos.

### 12.2.2 Camadas e profundidade

Neurônios são organizados em **camadas**. A saída de uma camada alimenta a seguinte. Uma rede com muitas camadas é **profunda**.

*Analogia:* uma linha de montagem. A primeira estação detecta bordas; a seguinte, formas; a seguinte, partes de objetos; a última, o objeto inteiro.

### 12.2.3 Como a rede aprende

1. A rede faz uma **previsão** com os pesos atuais.
2. Uma **função de perda** mede o quanto ela errou.
3. A **retropropagação** (*backpropagation*) calcula como cada peso contribuiu para o erro (Rumelhart; Hinton; Williams, 1986).
4. A **descida do gradiente** ajusta levemente cada peso para diminuir o erro.
5. Repete-se milhares de vezes.

:::memorize Em uma frase
Aprender é ajustar pesos, aos poucos, para errar cada vez menos.
:::

## 12.3 Autoencoders

### 12.3.1 A analogia do telegrama

Você precisa mandar uma mensagem longa por telegrama, em que cada palavra custa dinheiro. Então escreve um **resumo curtíssimo**. Quem recebe tenta **reconstruir** a mensagem original a partir do resumo.

Se a reconstrução for boa, o resumo guardou o essencial. O **autoencoder** faz exatamente isso (Hinton; Salakhutdinov, 2006).

![f12_ae_arquitetura](Figura 12.2 — Autoencoder: o codificador comprime a entrada num código curto (espaço latente); o decodificador tenta reconstruí-la.)

### 12.3.2 As três partes

- **Codificador (*encoder*):** comprime a entrada **x** em um vetor curto **z**.
- **Espaço latente:** o conjunto dos códigos **z**. É um espaço de baixa dimensão com os "fatores essenciais".
- **Decodificador (*decoder*):** reconstrói **x̂** a partir de **z**.

A rede é treinada para minimizar o **erro de reconstrução**, normalmente o erro quadrático médio:

$$ perda = (1/n) · Σ ‖x − x̂‖² $$

Note: **não há rótulos**. A entrada é, ela mesma, o alvo. É auto-supervisão no sentido mais simples.

### 12.3.3 Relação com o PCA

Um autoencoder **linear** (sem ativações não lineares), com perda quadrática, aprende o **mesmo subespaço do PCA** (Baldi; Hornik, 1989). Com ativações não lineares e várias camadas, ele consegue capturar **estruturas curvas**, algo além do PCA. Hinton e Salakhutdinov (2006) mostraram que autoencoders profundos reduzem dimensões muito melhor que o PCA em imagens e textos.

### 12.3.4 Implementação em PyTorch

```python
import numpy as np
import torch
from torch import nn
from sklearn.datasets import load_digits
from sklearn.preprocessing import MinMaxScaler

torch.manual_seed(0)

# 1) Dados: dígitos 8x8 (64 atributos) escalados em [0,1]
X, y = load_digits(return_X_y=True)
X = MinMaxScaler().fit_transform(X).astype("float32")
Xt = torch.from_numpy(X)

# 2) Modelo: 64 -> 32 -> 2 (código) -> 32 -> 64
class Autoencoder(nn.Module):
    def __init__(self, dim_latente=2):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(64, 32), nn.ReLU(),
                                 nn.Linear(32, dim_latente))
        self.dec = nn.Sequential(nn.Linear(dim_latente, 32), nn.ReLU(),
                                 nn.Linear(32, 64), nn.Sigmoid())
    def forward(self, x):
        z = self.enc(x)
        return self.dec(z), z

modelo = Autoencoder(dim_latente=2)
otimizador = torch.optim.Adam(modelo.parameters(), lr=1e-2)
perda_fn = nn.MSELoss()

# 3) Treino
for epoca in range(150):
    rec, z = modelo(Xt)
    perda = perda_fn(rec, Xt)
    otimizador.zero_grad()
    perda.backward()
    otimizador.step()
    if epoca % 50 == 0:
        print(f"época {epoca:3d}  perda = {perda.item():.4f}")

# 4) Usar o espaço latente (2D) para visualizar os dígitos
with torch.no_grad():
    Z = modelo.enc(Xt).numpy()
print("Formato do espaço latente:", Z.shape)
```

**O que acontece em cada bloco?**

1. Carregamos os dígitos e os escalamos para [0, 1].
2. Definimos o codificador (64 → 32 → 2) e o decodificador (2 → 32 → 64).
3. O laço de treino repete: reconstruir, medir o erro, calcular gradientes (`backward`) e atualizar os pesos (`step`).
4. O código **Z** de 2 dimensões pode ser desenhado, como fizemos com t-SNE.

![f12_latente](Figura 12.3 — Espaço latente de 2 dimensões de um autoencoder treinado nos dígitos: dígitos parecidos ficam próximos, sem que o modelo conheça os rótulos.)

## 12.4 Variações do autoencoder

### 12.4.1 Subcompleto e com gargalo

O código tem dimensão **menor** que a entrada. O "gargalo" **força** a rede a aprender o essencial. É o caso que vimos.

### 12.4.2 Autoencoder esparso

Permite um código grande, mas **penaliza** o número de neurônios ativos, de modo que cada exemplo usa poucos. Gera "dicionários" de partes, como o NMF. A ideia remonta ao trabalho de Olshausen e Field (1996) sobre codificação esparsa.

### 12.4.3 Autoencoder de remoção de ruído (*denoising*)

Corrompe a entrada (adiciona ruído ou apaga pedaços) e pede que a rede reconstrua a **versão limpa** (Vincent et al., 2008; 2010). Assim, a rede não pode apenas copiar a entrada: precisa aprender a **estrutura** dos dados.

![f12_denoising](Figura 12.4 — Remoção de ruído: da esquerda para a direita, imagem limpa, imagem ruidosa e imagem recuperada pelo autoencoder.)

```python
import torch
from torch import nn
from sklearn.datasets import load_digits
from sklearn.preprocessing import MinMaxScaler

torch.manual_seed(0)
X = MinMaxScaler().fit_transform(load_digits().data).astype("float32")
limpo = torch.from_numpy(X)

dae = nn.Sequential(nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 16), nn.ReLU(),
                    nn.Linear(16, 32), nn.ReLU(), nn.Linear(32, 64), nn.Sigmoid())
opt = torch.optim.Adam(dae.parameters(), lr=5e-3)

for epoca in range(200):
    ruidoso = (limpo + 0.3 * torch.randn_like(limpo)).clamp(0, 1)   # corrompe
    perda = nn.functional.mse_loss(dae(ruidoso), limpo)             # alvo = versão limpa
    opt.zero_grad(); perda.backward(); opt.step()

with torch.no_grad():
    teste = (limpo + 0.3 * torch.randn_like(limpo)).clamp(0, 1)
    print("Erro da imagem ruidosa    :", nn.functional.mse_loss(teste, limpo).item())
    print("Erro da imagem recuperada :", nn.functional.mse_loss(dae(teste), limpo).item())
```

### 12.4.4 Autoencoder convolucional

Para imagens, usam-se **camadas convolucionais**, que aplicam pequenos filtros deslizantes e respeitam a estrutura espacial (LeCun et al., 1998).

### 12.4.5 Aplicações

- **Redução de dimensionalidade** não linear.
- **Detecção de anomalias:** treina-se só com exemplos normais; anomalias têm **erro de reconstrução alto**.
- **Remoção de ruído** em imagens e sinais.
- **Pré-treinamento** de representações.

```python
import torch
from torch import nn
from sklearn.datasets import load_digits
from sklearn.preprocessing import MinMaxScaler

torch.manual_seed(0)
X, y = load_digits(return_X_y=True)
X = MinMaxScaler().fit_transform(X).astype("float32")
normal = torch.from_numpy(X[y != 9])        # treina SEM o dígito 9
raro   = torch.from_numpy(X[y == 9])        # o "9" será a anomalia

ae = nn.Sequential(nn.Linear(64, 16), nn.ReLU(), nn.Linear(16, 8), nn.ReLU(),
                   nn.Linear(8, 16), nn.ReLU(), nn.Linear(16, 64), nn.Sigmoid())
opt = torch.optim.Adam(ae.parameters(), lr=5e-3)
for _ in range(300):
    perda = nn.functional.mse_loss(ae(normal), normal)
    opt.zero_grad(); perda.backward(); opt.step()

with torch.no_grad():
    e_normal = ((ae(normal) - normal) ** 2).mean(1)
    e_raro = ((ae(raro) - raro) ** 2).mean(1)
print("Erro médio nos dígitos normais:", e_normal.mean().item())
print("Erro médio nos dígitos '9'    :", e_raro.mean().item())
```

## 12.5 Autoencoders variacionais (VAE)

### 12.5.1 O limite do autoencoder comum

O espaço latente de um autoencoder comum pode ter "buracos". Se escolhermos um ponto qualquer e o decodificarmos, obteremos lixo. Ele **reconstrói**, mas não **gera** bem.

O **VAE** (Kingma; Welling, 2014) corrige isso com uma ideia probabilística.

### 12.5.2 A ideia

- O codificador não devolve um ponto **z**, e sim uma **distribuição** (uma média μ e um desvio σ).
- Sorteia-se **z** dessa distribuição.
- O decodificador reconstrói a partir de **z**.
- A perda tem **duas partes**:
  1. **Reconstrução:** a saída deve se parecer com a entrada.
  2. **Regularização (divergência KL):** a distribuição de cada exemplo deve ficar **perto de uma normal padrão**.

$$ perda = erro de reconstrução + KL( N(μ, σ²) ‖ N(0, 1) ) $$

*Analogia:* o bibliotecário que não só guarda cada livro numa posição exata, mas organiza **regiões** de uma grande sala: ficção aqui, ciência ali, sem espaços vazios. Qualquer ponto da sala corresponde a algo plausível.

![f12_vae](Figura 12.5 — VAE: o codificador gera média e desvio; sorteamos z; o decodificador gera a saída. O espaço latente fica contínuo e "preenchido".)

### 12.5.3 O truque da reparametrização

Sortear **z** é um processo aleatório e não se pode retropropagar por um sorteio. O truque: escreva

$$ z = μ + σ · ε, com ε ~ N(0, 1) $$

O acaso fica todo em ε (que não precisa de gradiente). Agora μ e σ são contribuições determinísticas e a rede treina normalmente (Kingma; Welling, 2014).

### 12.5.4 VAE em PyTorch

```python
import torch
from torch import nn
from sklearn.datasets import load_digits
from sklearn.preprocessing import MinMaxScaler

torch.manual_seed(0)
X = MinMaxScaler().fit_transform(load_digits().data).astype("float32")
Xt = torch.from_numpy(X)

class VAE(nn.Module):
    def __init__(self, dim_z=2):
        super().__init__()
        self.enc = nn.Sequential(nn.Linear(64, 32), nn.ReLU())
        self.mu = nn.Linear(32, dim_z)
        self.logvar = nn.Linear(32, dim_z)          # log da variância (mais estável)
        self.dec = nn.Sequential(nn.Linear(dim_z, 32), nn.ReLU(),
                                 nn.Linear(32, 64), nn.Sigmoid())
    def forward(self, x):
        h = self.enc(x)
        mu, logvar = self.mu(h), self.logvar(h)
        eps = torch.randn_like(mu)
        z = mu + torch.exp(0.5 * logvar) * eps      # reparametrização
        return self.dec(z), mu, logvar

def perda_vae(rec, x, mu, logvar):
    r = nn.functional.binary_cross_entropy(rec, x, reduction="sum")
    kl = -0.5 * torch.sum(1 + logvar - mu.pow(2) - logvar.exp())
    return (r + kl) / x.shape[0]

vae = VAE()
opt = torch.optim.Adam(vae.parameters(), lr=5e-3)
for epoca in range(200):
    rec, mu, logvar = vae(Xt)
    perda = perda_vae(rec, Xt, mu, logvar)
    opt.zero_grad(); perda.backward(); opt.step()
print("Perda final por exemplo:", round(perda.item(), 2))

# GERAR dígitos novos: sorteie z ~ N(0,1) e decodifique
with torch.no_grad():
    novos = vae.dec(torch.randn(16, 2))
print("Imagens geradas:", novos.shape)
```

### 12.5.5 Por que o VAE é importante?

- Permite **gerar** dados novos e **interpolar** entre exemplos (caminhar no espaço latente: um "7" vira um "1" suavemente).
- Dá uma **representação probabilística**.
- Gerou extensões como o β-VAE, que busca fatores independentes e interpretáveis (Higgins et al., 2017).

## 12.6 Redes Adversariais Generativas (GANs)

### 12.6.1 A analogia do falsificador e da polícia

Goodfellow et al. (2014) propuseram um jogo entre duas redes.

- O **gerador** é um falsificador de quadros. Parte de ruído aleatório e tenta criar imagens que pareçam reais.
- O **discriminador** é um policial especializado. Recebe imagens (reais e falsas) e tenta dizer quais são falsas.

![f12_gan](Figura 12.6 — GAN: o gerador tenta enganar o discriminador; o discriminador tenta desmascarar o gerador. Ambos melhoram.)

Cada vez que o policial fica mais esperto, o falsificador precisa melhorar. Com o tempo, as falsificações ficam tão boas que o policial acerta apenas 50 % das vezes (o chute).

### 12.6.2 A formulação do jogo

$$ min_G max_D  E[ log D(x) ] + E[ log (1 − D(G(z))) ] $$

Em palavras: o discriminador **D** quer maximizar a chance de rotular corretamente reais e falsos; o gerador **G** quer minimizar essa chance.

### 12.6.3 Problemas conhecidos

- **Instabilidade do treino:** o equilíbrio entre as redes é delicado.
- **Colapso de modos:** o gerador produz poucas variedades de imagens.
- **Avaliação difícil:** como medir a qualidade de imagens geradas? Usam-se métricas como a FID (Heusel et al., 2017).

Melhorias: DCGAN (Radford; Metz; Chintala, 2016), Wasserstein GAN (Arjovsky; Chintala; Bottou, 2017) e StyleGAN (Karras; Laine; Aila, 2019).

### 12.6.4 Um esboço em PyTorch

```python
import torch
from torch import nn

torch.manual_seed(0)
# Dados "reais": uma distribuição 1D bimodal (duas corcovas)
def reais(n):
    metade = n // 2
    return torch.cat([torch.randn(metade, 1) * 0.5 - 2, torch.randn(n - metade, 1) * 0.5 + 2])

G = nn.Sequential(nn.Linear(4, 16), nn.ReLU(), nn.Linear(16, 1))
D = nn.Sequential(nn.Linear(1, 16), nn.ReLU(), nn.Linear(16, 1), nn.Sigmoid())
optG = torch.optim.Adam(G.parameters(), lr=2e-3)
optD = torch.optim.Adam(D.parameters(), lr=2e-3)
bce = nn.BCELoss()

for passo in range(1500):
    # 1) treina o discriminador: reais -> 1, falsos -> 0
    real = reais(128)
    falso = G(torch.randn(128, 4)).detach()
    perdaD = bce(D(real), torch.ones(128, 1)) + bce(D(falso), torch.zeros(128, 1))
    optD.zero_grad(); perdaD.backward(); optD.step()
    # 2) treina o gerador: quer que o discriminador diga "1" para os falsos
    perdaG = bce(D(G(torch.randn(128, 4))), torch.ones(128, 1))
    optG.zero_grad(); perdaG.backward(); optG.step()

with torch.no_grad():
    amostra = G(torch.randn(2000, 4)).flatten()
print("Média do gerado:", amostra.mean().item(), "| desvio:", amostra.std().item())
frac = (amostra < 0).float().mean().item()
print("Fração negativa (próxima de 0,5 se houver duas corcovas):", frac)
```

## 12.7 Modelos de difusão (visão geral)

Hoje, muitos dos geradores de imagens mais impressionantes usam **modelos de difusão** (Ho; Jain; Abbeel, 2020). A ideia:

1. **Processo direto:** pegue uma imagem e vá **adicionando ruído** em muitos pequenos passos, até restar apenas ruído puro.
2. **Processo reverso:** treine uma rede para **remover um pouco de ruído** a cada passo.
3. **Gerar:** comece com ruído e aplique a rede repetidamente. Do caos, emerge uma imagem.

*Analogia:* uma gota de tinta se espalhando num copo d'água (direto). Imagine "desfazer" a difusão, passo a passo, para recuperar a gota.

Os modelos de difusão são treinados sem rótulos de classe (embora possam receber textos como orientação) e são parentes próximos dos autoencoders de remoção de ruído.

## 12.8 Aprendizado auto-supervisionado

### 12.8.1 A grande ideia

Em vez de depender de humanos para rotular, **criamos o rótulo a partir dos próprios dados**. Resolve-se uma tarefa artificial, chamada **tarefa-pretexto** (*pretext task*). Para resolvê-la bem, a rede é obrigada a aprender **representações úteis**.

Exemplos de tarefas-pretexto:

- **Prever palavras ocultas** (BERT; Devlin et al., 2019).
- **Prever a próxima palavra** (modelos de linguagem).
- **Prever a rotação** aplicada a uma imagem (Gidaris; Singh; Komodakis, 2018).
- **Reconstruir partes ocultas** de uma imagem (autoencoders mascarados; He et al., 2022).
- **Resolver quebra-cabeças** de pedaços de imagem.
- **Colorir** imagens em preto e branco.

![f12_pretexto](Figura 12.7 — Tarefas-pretexto: esconder palavras, girar imagens, mascarar regiões. Os "rótulos" saem dos próprios dados.)

### 12.8.2 Depois do pré-treino

Após treinar na tarefa-pretexto com milhões de exemplos sem rótulo, **reaproveitamos** a rede para tarefas reais (classificação, por exemplo) com **poucos rótulos**. Esse é o **ajuste fino** (*fine-tuning*) ou a **avaliação linear**.

*Analogia:* um estudante lê milhares de livros sem prova (pré-treino). Depois, com poucas aulas específicas, passa em concurso (ajuste fino).

## 12.9 Aprendizado contrastivo

### 12.9.1 A ideia

O aprendizado **contrastivo** ensina a rede o que é "parecido" e o que é "diferente".

1. Pegue uma imagem. Aplique **duas transformações aleatórias** (recortar, mudar cores, borrar). Essas duas versões formam um **par positivo**: devem ter representações **próximas**.
2. Imagens **diferentes** formam **pares negativos**: devem ter representações **distantes**.
3. Treine para **aproximar positivos e afastar negativos**.

![f12_contrastivo](Figura 12.8 — Aprendizado contrastivo: visões diferentes da mesma imagem se atraem; imagens distintas se repelem no espaço de representação.)

### 12.9.2 A função de perda InfoNCE (NT-Xent)

Para um par positivo (*i*, *j*) num lote com outros exemplos:

$$ perda = − log [ exp( sim(zᵢ, zⱼ) / τ ) / Σ_k exp( sim(zᵢ, z_k) / τ ) ] $$

- **sim** é a similaridade do cosseno (Capítulo 2).
- **τ** (temperatura) controla a "dureza" da comparação.
- O denominador soma sobre todos os outros exemplos do lote (os negativos).

Quanto mais parecidos os positivos e mais diferentes os negativos, menor a perda (Oord; Li; Vinyals, 2018).

### 12.9.3 Principais métodos

- **SimCLR** (Chen et al., 2020): usa lotes enormes; os negativos são os outros exemplos do lote.
- **MoCo** (He et al., 2020): mantém uma **fila** de representações antigas como negativos, evitando lotes gigantes.
- **CLIP** (Radford et al., 2021): aprende a alinhar **imagens e textos**; sustenta a busca de imagens por descrição.
- **BYOL** (Grill et al., 2020) e **DINO** (Caron et al., 2021): funcionam **sem negativos explícitos**, com uma rede "aluna" e outra "professora".

### 12.9.4 Um exemplo mínimo

```python
import torch
import torch.nn.functional as F

def nt_xent(z1, z2, tau=0.5):
    """Perda contrastiva para um lote: z1[i] e z2[i] são duas visões do mesmo exemplo."""
    z = F.normalize(torch.cat([z1, z2]), dim=1)          # normaliza (cosseno)
    sim = z @ z.T / tau                                   # similaridades
    n = z1.shape[0]
    sim.fill_diagonal_(float("-inf"))                     # ignora a similaridade consigo mesmo
    alvo = torch.cat([torch.arange(n, 2 * n), torch.arange(0, n)])   # o positivo de cada um
    return F.cross_entropy(sim, alvo)

torch.manual_seed(0)
base = torch.randn(8, 16)
visao1 = base + 0.05 * torch.randn(8, 16)                 # duas "visões" quase iguais
visao2 = base + 0.05 * torch.randn(8, 16)
aleatorio = torch.randn(8, 16)

print("Perda com positivos parecidos:", nt_xent(visao1, visao2).item())
print("Perda com pares aleatórios   :", nt_xent(visao1, aleatorio).item())
```

A perda é bem menor quando as duas visões vêm de fato do mesmo exemplo.

## 12.10 Usando representações aprendidas

Uma vez treinado, o codificador vira uma **ferramenta**:

- **Agrupamento** sobre os códigos (K-means em **z**): em imagens grandes e complexas, costuma superar o agrupamento sobre pixels. Xie, Girshick e Farhadi (2016) combinaram os dois passos no *Deep Embedded Clustering*.
- **Visualização:** t-SNE ou UMAP sobre os códigos.
- **Busca por similaridade:** vizinhos mais próximos no espaço de representação.
- **Anomalias:** distância ao centro dos códigos normais.
- **Transferência:** a base para classificadores com poucos rótulos.

```python
import numpy as np
import torch
from torch import nn
from sklearn.datasets import load_digits
from sklearn.preprocessing import MinMaxScaler
from sklearn.cluster import KMeans
from sklearn.metrics import adjusted_rand_score

torch.manual_seed(0)
X, y = load_digits(return_X_y=True)
X = MinMaxScaler().fit_transform(X).astype("float32")
Xt = torch.from_numpy(X)

enc = nn.Sequential(nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 10))
dec = nn.Sequential(nn.Linear(10, 32), nn.ReLU(), nn.Linear(32, 64), nn.Sigmoid())
opt = torch.optim.Adam(list(enc.parameters()) + list(dec.parameters()), lr=5e-3)
for _ in range(300):
    perda = nn.functional.mse_loss(dec(enc(Xt)), Xt)
    opt.zero_grad(); perda.backward(); opt.step()

with torch.no_grad():
    Z = enc(Xt).numpy()

ari_pixels = adjusted_rand_score(y, KMeans(10, n_init=10, random_state=0).fit_predict(X))
ari_latente = adjusted_rand_score(y, KMeans(10, n_init=10, random_state=0).fit_predict(Z))
print("ARI K-means nos pixels  :", round(ari_pixels, 3))
print("ARI K-means no latente  :", round(ari_latente, 3))
```

:::atencao Resultado honesto
Neste exemplo pequeno (imagens 8×8), o K-means sobre os **pixels** foi *melhor* que sobre o código aprendido. Isso é uma lição valiosa: em dados simples, o autoencoder pode perder informação útil. As vantagens do aprendizado profundo aparecem com dados maiores e mais complexos. **Sempre compare com uma linha de base simples.**
:::

## 12.11 Boas práticas e limites

- **Comece simples.** Antes de uma rede profunda, teste PCA e UMAP. Muitas vezes bastam.
- **Dados:** redes profundas são "famintas". Precisam de muitos exemplos.
- **Reprodutibilidade:** fixe sementes e registre versões e hiperparâmetros.
- **Cuidado com o viés:** modelos generativos reproduzem preconceitos e estereótipos dos dados de treino.
- **Uso responsável:** conteúdo sintético (*deepfakes*) pode enganar e causar dano. Rotule e use com ética.
- **Interpretabilidade:** espaços latentes são difíceis de explicar.
- **Custo energético:** treinar grandes modelos consome muita energia (Strubell; Ganesh; McCallum, 2019).

## Resumo do capítulo

:::memorize Cartões de memorização
- **Autoencoder:** comprimir (codificador) e reconstruir (decodificador); o gargalo força o essencial.
- **Linear = PCA.** Não linear = mais poder.
- **Denoising:** aprende a limpar; **esparso:** poucas ativações.
- **VAE:** código probabilístico + KL; reparametrização; gera e interpola.
- **GAN:** falsificador contra polícia.
- **Difusão:** adicionar e remover ruído.
- **Auto-supervisionado:** o rótulo sai dos dados. **Contrastivo:** aproximar positivos, afastar negativos.
:::
