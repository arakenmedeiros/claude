## 2.2 Dados, modelo e erro

### 2.2.1 Os ingredientes

No **aprendizado supervisionado**, temos exemplos com a resposta correta.

- **Exemplo:** uma linha da tabela de dados, como um paciente.
- **Atributo** (*feature*): uma coluna, como idade ou tamanho do tumor.
- **Rótulo** (*label*): a resposta correta, como "benigno" ou "maligno".

Chamamos de **X** a tabela de atributos e de **y** os rótulos.

O **modelo** é uma função com números ajustáveis, os **parâmetros** (ou pesos), que chamaremos de **w**. Dado um exemplo x, o modelo produz uma previsão. Aprender é encontrar bons valores para **w**.

### 2.2.2 A função de perda

Como saber se o modelo está bom? Medimos o erro com uma **função de perda** (*loss*). Ela dá uma nota para cada previsão: nota baixa é bom, nota alta é ruim.

Para classificação, uma perda muito usada é a **entropia cruzada**. Para um exemplo cuja classe correta é *c*, ela vale:

$$ perda = − log( p_c ) $$

Em palavras: *p_c* é a probabilidade que o modelo deu à classe correta. Se ele deu 0,9, a perda é pequena (cerca de 0,11). Se deu 0,1, a perda é grande (cerca de 2,30). **Quanto mais confiante no acerto, menor a perda.**

### 2.2.3 Risco empírico: a média das perdas

O erro total é a média das perdas em todos os exemplos:

$$ F(w) = (1/n) · Σ_i perda( w ; x_i , y_i ) $$

Este número, chamado de **risco empírico**, é o que queremos reduzir. Treinar significa **minimizar F(w)**.

Observe a conexão com o Capítulo 1. Lá, o erro global era uma média ponderada dos erros de cada cliente. Cada *F_k(w)* é o risco empírico calculado só com os dados do cliente *k*.

## 2.3 Gradiente descendente: descendo a montanha

### 2.3.1 A analogia da neblina

Você está no alto de uma montanha, com neblina densa. Quer chegar ao vale, mas só enxerga o chão sob seus pés. O que fazer?

Sinta para onde o chão **desce mais** e dê um passo nessa direção. Repita.

Isso é o **gradiente descendente** (*gradient descent*). O **gradiente** é o vetor que aponta a direção em que o erro **mais sobe**. Andamos no sentido oposto:

$$ w ← w − η · ∇F(w) $$

Aqui, ∇F(w) é o gradiente, e **η** (letra grega "eta") é a **taxa de aprendizado**: o tamanho do passo.

![f2_montanha](Figura 2.1 — O gradiente descendente dá passos em direção ao vale do erro. Cada ponto é um valor dos parâmetros.)

### 2.3.2 A taxa de aprendizado

O tamanho do passo faz muita diferença.

- **Muito pequeno:** você chega ao vale, mas demora muito.
- **Adequado:** você chega rápido e para perto do vale.
- **Muito grande:** você passa por cima do vale e pode até se afastar dele (divergir).

![f2_lr](Figura 2.2 — Efeito da taxa de aprendizado em uma montanha simples de uma dimensão.)

:::dica Dica
Se a perda **sobe** ou fica "louca" durante o treino, quase sempre a taxa de aprendizado está alta demais. Reduza-a pela metade e tente de novo.
:::

### 2.3.3 Mini-lotes e o SGD

Calcular o gradiente com **todos** os exemplos é caro. A alternativa é usar um pequeno grupo, um **mini-lote** (*mini-batch*), de, digamos, 32 exemplos.

O gradiente fica um pouco "tremido", pois é uma estimativa. Mas é barato e, na média, aponta para o lugar certo. Esse método é o **gradiente descendente estocástico** (*stochastic gradient descent*, **SGD**). "Estocástico" quer dizer "com sorteio", pois os exemplos do lote são sorteados.

![f2_sgd](Figura 2.3 — Com todos os dados, o caminho é suave. Com mini-lotes, ele treme, mas chega à mesma região.)

Dois termos aparecem o tempo todo no livro.

- **Época:** uma passada completa por todos os exemplos de treino.
- **Passo** (ou iteração): uma atualização dos parâmetros com um mini-lote.

Se há 1.000 exemplos e o lote tem 50, uma época tem **20 passos**.

:::memorize Memorize
- Gradiente: direção em que o erro mais sobe. Andamos no sentido contrário.
- η (taxa de aprendizado): tamanho do passo.
- SGD: gradiente calculado em mini-lotes sorteados.
- Época: uma passada por todos os dados. Passo: uma atualização.
:::

### 2.3.4 Um gradiente descendente do zero

Vamos implementar o gradiente descendente para uma **regressão logística** em duas classes. Usaremos o conjunto *Breast Cancer Wisconsin*, da UCI.

A regressão logística calcula uma nota *z = x·w + b*, e transforma-a em probabilidade com a função **sigmoide**, *p = 1 / (1 + e^(−z))*. Quanto maior *z*, mais próxima de 1 é a probabilidade.

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)
esc = StandardScaler().fit(Xtr)
Xtr, Xte = esc.transform(Xtr), esc.transform(Xte)

def sigmoide(z):
    return 1 / (1 + np.exp(-z))

def perda_e_gradiente(w, b, X, y):
    p = sigmoide(X @ w + b)
    perda = -np.mean(y * np.log(p + 1e-12) + (1 - y) * np.log(1 - p + 1e-12))
    erro = p - y                       # diferença entre previsão e resposta
    return perda, X.T @ erro / len(y), erro.mean()

w, b, eta = np.zeros(X.shape[1]), 0.0, 0.1
for passo in range(201):
    perda, gw, gb = perda_e_gradiente(w, b, Xtr, ytr)
    w, b = w - eta * gw, b - eta * gb
    if passo % 50 == 0:
        acc = np.mean((sigmoide(Xte @ w + b) > 0.5) == yte)
        print(f"passo {passo:3d} | perda = {perda:.4f} | acurácia no teste = {acc:.3f}")
```

Repare que a perda **diminui** a cada passo. Esse é o sinal de que o treino está funcionando.

## 2.4 Generalizar: o que importa é o dado novo

### 2.4.1 Sobreajuste

Um aluno que decora as respostas da prova de treino tira 10, mas vai mal em uma prova nova. Em aprendizado de máquina, isso se chama **sobreajuste** (*overfitting*): o modelo "decora" os exemplos de treino e não **generaliza** para dados novos (Hastie; Tibshirani; Friedman, 2009).

![f2_overfit](Figura 2.4 — O erro de treino chega a zero, mas o erro em dados novos (validação) fica acima. Essa lacuna indica sobreajuste.)

### 2.4.2 Treino, validação e teste

Para medir de forma honesta, separamos os dados em três partes:

- **Treino:** ajusta os parâmetros.
- **Validação:** escolhe hiperparâmetros, como a taxa de aprendizado. **Hiperparâmetros** são as "regulagens" que não são aprendidas, mas escolhidas por nós.
- **Teste:** dá a nota final. Use **uma única vez**.

![f2_particao](Figura 2.5 — Uma divisão típica dos dados. No federado, cada cliente guarda suas próprias partes.)

:::atencao Atenção
Nunca escolha hiperparâmetros olhando o conjunto de teste. Isso "vaza" informação do teste para o modelo e deixa o resultado otimista demais.
:::

### 2.4.3 Regularização

Uma forma de combater o sobreajuste é a **regularização**: penalizar parâmetros muito grandes. Na **regularização L2**, somamos à perda um termo *λ‖w‖²*. O hiperparâmetro *λ* (lambda) controla a força da penalização. Modelos mais "contidos" tendem a generalizar melhor.

## 2.5 Medindo a qualidade

### 2.5.1 Acurácia e seus limites

A **acurácia** é a fração de acertos. É simples, mas pode enganar.

Imagine um banco em que 99% das transações são legítimas. Um modelo que responde "legítima" sempre tem **99% de acurácia**, e é **inútil**: nunca acha uma fraude.

### 2.5.2 Matriz de confusão, precisão, revocação e F1

A **matriz de confusão** conta acertos e erros em cada classe. Chamando "fraude" de classe positiva:

| | Previu fraude | Previu legítima |
|---|---|---|
| Era fraude | Verdadeiro positivo (VP) | Falso negativo (FN) |
| Era legítima | Falso positivo (FP) | Verdadeiro negativo (VN) |

Daí saem três métricas:

- **Precisão:** dos que o modelo chamou de fraude, quantos eram fraude? = VP / (VP + FP).
- **Revocação** (*recall*): das fraudes que existiam, quantas o modelo achou? = VP / (VP + FN).
- **F1:** a média harmônica das duas. Só é alta se **ambas** forem altas.

$$ F1 = 2 · precisão · revocação / ( precisão + revocação ) $$

:::dica Dica
Em problemas com classes desbalanceadas, olhe sempre **F1 ou revocação**, e não apenas a acurácia. Isso será essencial quando falarmos de clientes com dados diferentes.
:::

## 2.6 Os modelos usados neste livro

Usaremos dois tipos de modelo.

1. **Regressão logística** (e sua versão para várias classes, a **softmax**). É simples, rápida e fácil de interpretar. O modelo inteiro cabe em uma tabela de números.
2. **Rede neural pequena** (*perceptron* multicamadas, `MLPClassifier`). Tem camadas de "neurônios" e aprende padrões mais complexos.

Em ambos, os parâmetros são listas de números. Isso é crucial: **um modelo federado nada mais é que um vetor de números**, que podemos enviar, receber, somar e dividir.

| Modelo | Parâmetros (dígitos 8×8, 10 classes) | Observação |
|---|---|---|
| Softmax | 64 × 10 + 10 = **650** | Convexo: fácil de otimizar |
| MLP com 32 neurônios | 64 × 32 + 32 + 32 × 10 + 10 = **2.410** | Não convexo: mais flexível |

## 2.7 Treino que pausa e retoma: `partial_fit` e `warm_start`

No aprendizado federado, o cliente **recebe** um modelo, treina um pouco e **devolve**. Depois recebe de novo. Precisamos, portanto, de treino que possa **ser retomado** de onde parou.

O scikit-learn oferece duas ferramentas:

- **`partial_fit`:** continua o treino com mais dados, sem reiniciar. Disponível em `SGDClassifier`, `MLPClassifier` e outros.
- **`warm_start=True`:** ao chamar `fit` de novo, parte dos parâmetros atuais.

```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.linear_model import SGDClassifier
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

X, y = load_digits(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, random_state=0, stratify=y)
esc = StandardScaler().fit(Xtr)
Xtr, Xte = esc.transform(Xtr), esc.transform(Xte)

modelo = SGDClassifier(loss="log_loss", learning_rate="constant", eta0=0.01, random_state=0)
classes = np.arange(10)
for epoca in range(1, 11):
    modelo.partial_fit(Xtr, ytr, classes=classes)
    if epoca in (1, 2, 5, 10):
        print(f"após {epoca:2d} época(s): acurácia no teste = {modelo.score(Xte, yte):.3f}")

print("formato dos parâmetros:", modelo.coef_.shape, "+", modelo.intercept_.shape)
```

Veja como o modelo é só um conjunto de números: `coef_` (pesos) e `intercept_` (vieses). **É isso que o servidor vai enviar e receber.**

## 2.8 Pré-processamento federado: a padronização

### 2.8.1 O problema

Muitos modelos funcionam melhor quando os atributos têm escala parecida. A **padronização** subtrai a média e divide pelo desvio padrão de cada atributo.

Mas, em um sistema federado, **ninguém pode olhar todos os dados** para calcular essa média e esse desvio. O que fazer? Lembre da trapaça apontada no Capítulo 1.

### 2.8.2 A solução: somas locais

A média e a variância globais podem ser calculadas **a partir de somas parciais**. Cada cliente envia apenas três quantidades por atributo:

- *n_k*: quantos exemplos tem;
- *S1_k* = Σ x: a soma dos valores;
- *S2_k* = Σ x²: a soma dos quadrados.

O servidor soma tudo e calcula:

$$ μ = S1 / n        σ² = S2 / n − μ² $$

![f2_scaler](Figura 2.6 — Padronização federada: os clientes enviam só contagens e somas, e o servidor devolve a média e o desvio globais.)

```python
import numpy as np
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

# quatro clientes, cada um com um pedaço dos dados de treino
rng = np.random.default_rng(0)
clientes = np.array_split(rng.permutation(len(Xtr)), 4)

# cada cliente calcula e envia apenas: n, soma e soma dos quadrados
resumos = [(len(c), Xtr[c].sum(axis=0), (Xtr[c] ** 2).sum(axis=0)) for c in clientes]

# o servidor combina os resumos
n = sum(r[0] for r in resumos)
mu = sum(r[1] for r in resumos) / n
sigma = np.sqrt(sum(r[2] for r in resumos) / n - mu ** 2)

# conferência: igual ao StandardScaler que olhou todos os dados?
ref = StandardScaler().fit(Xtr)
print("diferença máxima na média :", np.abs(mu - ref.mean_).max())
print("diferença máxima no desvio:", np.abs(sigma - ref.scale_).max())
```

O resultado é **idêntico** (a menos de erros de arredondamento). Ou seja: conseguimos a padronização global **sem que nenhum dado bruto saísse do cliente**.

:::atencao Atenção
Esta fórmula simples pode perder precisão numérica quando as médias são muito grandes. Em sistemas reais, usa-se a combinação estável de médias e variâncias parciais (algoritmo de Chan). Além disso, mesmo médias e somas podem revelar informações em grupos muito pequenos. Veremos formas de proteger isso nos Capítulos 8 e 9.
:::

:::saibamais Saiba mais
Esse truque funciona porque média e variância são **estatísticas suficientes** que se combinam por soma. Muitas outras operações do aprendizado federado seguem a mesma lógica: o cliente calcula algo local e o servidor **soma**.
:::

## 2.9 Resumo do capítulo

:::memorize O essencial do Capítulo 2
- Um modelo é uma função com parâmetros **w**. Aprender é reduzir a perda média F(w).
- Gradiente descendente: w ← w − η∇F(w). **η** é o tamanho do passo.
- SGD usa mini-lotes. **Época** = uma passada pelos dados.
- Sobreajuste: boa nota no treino, má nota em dados novos. Use treino, validação e teste.
- Acurácia pode enganar em classes desbalanceadas. Use **precisão, revocação e F1**.
- Um modelo federado é um **vetor de números** que se envia, recebe e combina.
- `partial_fit` permite retomar o treino. Média e desvio globais saem de **somas locais**.
:::
