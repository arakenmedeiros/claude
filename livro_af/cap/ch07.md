## 7.1 O segredo que escapa

Voltemos às amigas dos cadernos de receitas. Elas combinaram enviar à coordenadora **só os ajustes**: "menos sal", "mais forno", "dobrar o açúcar".

Parece inofensivo. Mas imagine que Marta envie o ajuste "tirar toda a pimenta". A coordenadora conclui, sem ver o caderno, que a receita de Marta tinha **muita pimenta**.

Atualizações de modelo são assim: **não são os dados, mas carregam pistas sobre eles**. E, em certos casos, as pistas bastam para **reconstruir os dados** quase por completo.

:::cotidiano No seu dia a dia
Alguém que vê só a lista de compras do seu mercado (leite sem lactose, fraldas, ração) consegue adivinhar muito sobre a sua casa, sem nunca ter entrado nela. Atualizações de modelo são a "lista de compras" dos dados de um cliente.
:::

Neste capítulo, vamos **atacar de verdade** modelos simples, em laboratório, para entender o risco. O objetivo é **defensivo**: só quem conhece o ataque consegue se proteger dele.

:::atencao Atenção
Os experimentos deste capítulo usam dados públicos (dígitos manuscritos) em modelos pequenos, para fins educacionais. Nunca teste ataques de privacidade em dados reais de pessoas sem autorização formal e aprovação ética.
:::

## 7.2 Quem ataca e o que enxerga

Para falar de segurança, definimos um **modelo de ameaça**: quem é o adversário, o que ele sabe e o que ele pode fazer (Kairouz et al., 2021).

### 7.2.1 Os adversários

| Adversário | O que é | O que enxerga |
|---|---|---|
| **Servidor honesto-mas-curioso** | Segue o protocolo, mas tenta aprender o que puder | Atualização individual de cada cliente |
| **Servidor malicioso** | Quebra o protocolo para extrair informação | Tudo acima, mais a possibilidade de enviar modelos manipulados |
| **Cliente malicioso** | Participante que ataca os outros | Modelos globais de cada rodada |
| **Observador da rede** | Espiona a comunicação | Mensagens, se não houver criptografia |
| **Usuário do modelo final** | Quem consulta o modelo pronto | Previsões e confianças (caixa-preta) ou os pesos (caixa-branca) |

![f7_ameacas](Figura 7.1 — Onde cada adversário observa o sistema. O servidor honesto-mas-curioso é o mais estudado: ele vê cada atualização individual.)

### 7.2.2 O que trafega

Em cada rodada, o servidor recebe, de cada cliente, uma **atualização individual**. Também todos recebem o **modelo global**. Ao final, o **modelo treinado** pode ser publicado. Cada um desses três itens é uma fonte de vazamento.

## 7.3 Mapa dos ataques

![f7_taxonomia](Figura 7.2 — Principais famílias de ataques à privacidade em aprendizado federado.)

| Ataque | Pergunta do adversário | Quem costuma atacar |
|---|---|---|
| **Reconstrução** (inversão de gradientes) | "Quais eram os dados de entrada?" | Servidor |
| **Inferência de pertencimento** | "Este exemplo foi usado no treino?" | Servidor, cliente, usuário do modelo |
| **Inferência de propriedades** | "Os dados do cliente têm esta característica?" | Servidor, cliente |
| **Memorização e extração** | "Que trechos do treino o modelo decorou?" | Usuário do modelo |
| **Ataques ativos** | "Posso manipular o modelo para facilitar o vazamento?" | Servidor malicioso |

## 7.4 Inversão de gradientes: o gradiente entrega a entrada

### 7.4.1 A ideia

Zhu et al. (2019) mostraram que, em redes neurais, o gradiente de um lote pode ser usado para **recuperar as imagens de treino**. O atacante cria uma imagem falsa, calcula o gradiente dela e ajusta a imagem até que seu gradiente fique igual ao observado. Geiping et al. (2020) refinaram o ataque, e Huang et al. (2021) avaliaram sistematicamente ataques e defesas.

Em modelos simples, não precisamos de otimização: **a matemática entrega o resultado**.

### 7.4.2 Um caso em que a conta é exata

Considere a regressão logística multiclasse da `fedlib`. Para **um único exemplo** *x* com rótulo *y*, o gradiente da perda em relação aos pesos é:

$$ ∇W = x ⊗ ( p − y ) $$

Em palavras: é o **produto externo** entre a entrada *x* e o vetor de erros *(p − y)*, em que *p* são as probabilidades previstas e *y* é o rótulo em formato one-hot (1 na classe certa, 0 nas demais). Cada coluna *c* do gradiente é *x* multiplicado pelo número *(p_c − y_c)*.

E o gradiente do **viés** é justamente *(p − y)*. Logo, dividindo uma coluna do gradiente de pesos pelo gradiente do viés correspondente, obtemos:

$$ x = ∇W[:, c] / ∇b[c] $$

A entrada é recuperada **exatamente**, sem nenhum ruído.

![f7_inversao](Figura 7.3 — Imagens de dígitos reconstruídas a partir do gradiente de um lote: com 1 exemplo, a reconstrução é perfeita; com lotes maiores, ela se mistura.)

### 7.4.3 Pondo à prova

```python
import numpy as np
from fedlib import *

Xtr, Xte, ytr, yte = carregar_digits()
rng = np.random.default_rng(0)

# o atacante conhece o modelo global W, que foi enviado ao cliente
W, _ = fedavg(particao_iid(ytr, 10), Xtr, ytr, Xte, yte, rodadas=10, epocas=2, eta=0.1)

def gradiente_do_lote(idx):
    """O que o cliente envia: a soma dos gradientes dos exemplos do lote."""
    return gradiente(W, Xtr[idx], ytr[idx]) * len(idx)

def reconstruir(G):
    gb = G[-1]                          # última linha: gradiente do viés = soma de (p − y)
    c = int(np.argmax(np.abs(gb)))      # escolhe a classe com maior sinal
    return G[:-1, c] / gb[c]            # x = coluna de pesos / gradiente do viés

# caso exato: lote de 1 exemplo
i = int(rng.integers(len(ytr)))
x_rec = reconstruir(gradiente_do_lote([i]))
print("lote de 1: erro máximo de reconstrução =", float(np.abs(x_rec - Xtr[i, :-1]).max()))

# lotes maiores: quanto a melhor correlação com algum exemplo do lote?
print(f"{'tamanho do lote':>16} | correlação média (melhor exemplo)")
for B in (1, 2, 4, 8, 16, 32):
    cors = []
    for _ in range(30):
        idx = rng.choice(len(ytr), B, replace=False)
        xr = reconstruir(gradiente_do_lote(idx))
        cors.append(max(np.corrcoef(xr, Xtr[j, :-1])[0, 1] for j in idx))
    print(f"{B:>16} | {np.mean(cors):.3f}")
```

O que vemos:

- Com **um** exemplo, a reconstrução é **exata** (erro na casa do arredondamento).
- Com lotes maiores, o gradiente é uma **soma** de vários exemplos, e a reconstrução vira uma **mistura** parecida com algum deles.
- Mesmo com 32 exemplos, a imagem recuperada ainda se **parece bastante** com algum dado real.

:::atencao Atenção
Este é o **melhor caso para o atacante**: modelo linear, um único passo de gradiente e acesso ao gradiente puro. Em redes profundas, com vários passos locais e muitos exemplos, o ataque é mais difícil, mas **não impossível**: os trabalhos citados reconstroem imagens reais de redes convolucionais.
:::

## 7.5 Inferência de pertencimento

### 7.5.1 A pergunta

"O exemplo *z* participou do treino?" Parece uma pergunta pequena, mas é grave: se o modelo foi treinado com prontuários de uma clínica de tratamento de uma doença, saber que *z* foi usado revela que a pessoa é paciente.

### 7.5.2 O ataque mais simples: o limiar de perda

Modelos tendem a ter **perda menor** nos exemplos de treino do que em exemplos novos. O ataque do **limiar de perda** diz "membro" se a perda do exemplo for baixa (Yeom et al., 2018). Ataques mais sofisticados treinam "modelos-sombra" (Shokri et al., 2017) ou calibram o limiar por exemplo (Carlini et al., 2022). Nasr et al. (2019) estudaram esses ataques em cenários federados.

Mede-se o sucesso pela **AUC** (área sob a curva ROC): 0,5 é "chute"; 1,0 é ataque perfeito.

### 7.5.3 Pondo à prova

```python
import numpy as np
from sklearn.metrics import roc_auc_score
from fedlib import *

Xtr, Xte, ytr, yte = carregar_digits()

def perdas(W, X, y):
    P = softmax(X @ W)
    return -np.log(P[np.arange(len(y)), y] + 1e-12)

print(f"{'dados de treino':>16}{'rodadas':>9}{'acurácia treino':>17}{'acurácia teste':>16}{'AUC do ataque':>15}")
for n_membros, rodadas, epocas in [(150, 10, 2), (150, 50, 20), (600, 50, 20), (1347, 50, 20)]:
    aucs, a_tr, a_te = [], [], []
    for s in range(5):
        idx = np.random.default_rng(s).permutation(len(ytr))[:n_membros]       # membros
        partes = [idx[p] for p in particao_iid(ytr[idx], 6, s)]                  # 6 clientes
        W, _ = fedavg(partes, Xtr, ytr, Xte, yte, rodadas=rodadas, epocas=epocas, eta=0.1, seed=s)
        lm, ln = perdas(W, Xtr[idx], ytr[idx]), perdas(W, Xte, yte)             # membros x não membros
        rotulo = np.r_[np.ones(len(lm)), np.zeros(len(ln))]
        aucs.append(roc_auc_score(rotulo, -np.r_[lm, ln]))                       # perda baixa => membro
        a_tr.append(acuracia(W, Xtr[idx], ytr[idx])); a_te.append(acuracia(W, Xte, yte))
    print(f"{n_membros:>16}{rodadas:>9}{np.mean(a_tr):>17.3f}{np.mean(a_te):>16.3f}{np.mean(aucs):>15.3f}")
```

![f7_membership](Figura 7.4 — À esquerda: perdas de membros e não membros (ataque com poucos dados e muitas rodadas). À direita: a AUC do ataque cai quando há mais dados de treino.)

Resultados:

- Com **poucos dados e muito treino**, a AUC passa de **0,6**: o ataque acerta mais do que um chute.
- Com **mais dados**, a AUC se aproxima de **0,5**: o modelo "decora" menos cada exemplo.
- A lição: **sobreajuste e privacidade andam juntos**. Quanto mais o modelo decora, mais vaza.

:::memorize Memorize
Risco de pertencimento ↑ quando: poucos dados, muitas épocas, modelo grande, sobreajuste forte. Risco ↓ quando: mais dados, regularização, parada antecipada.
:::

## 7.6 Inferência de propriedades

Em vez de perguntar sobre **um exemplo**, o atacante pergunta sobre uma **propriedade do conjunto**: "os dados deste cliente incluem pessoas de óculos?". Melis et al. (2019) mostraram que um participante pode inferir propriedades que **não têm relação com a tarefa** do modelo, usando as atualizações do modelo compartilhado.

## 7.7 Memorização e extração

Modelos grandes, em especial de linguagem, **memorizam trechos** do treino. Carlini et al. (2021) extraíram, de um modelo de linguagem, sequências literais do treino, incluindo informações pessoais. Em modelos de fundação federados, esse risco continua presente (Capítulo 11).

## 7.8 Ataques ativos de um servidor malicioso

Se o servidor trapaceia, ele pode **enviar modelos construídos para vazar**. Fowl et al. (2022) mostraram que um servidor pode inserir, no modelo enviado, uma camada que "captura" os dados de cada exemplo, mesmo com lotes grandes. Boenisch et al. (2023) estenderam o ataque. Isso reforça o recado: **não basta confiar no servidor**.

## 7.9 Por que isso acontece?

- **Gradientes carregam informação.** Eles são funções diretas dos dados.
- **Modelos memorizam.** Principalmente com poucos dados, muitos parâmetros e muito treino.
- **O servidor controla o protocolo.** Ele escolhe o modelo enviado e vê as atualizações.
- **Clientes contribuem de forma desigual.** Quem tem poucos dados é mais exposto.

## 7.10 O que ajuda, e o que não ajuda

Algumas práticas **diminuem** o risco, mas **não são garantias**:

| Prática | Efeito |
|---|---|
| Lotes maiores e mais passos locais | Mistura mais exemplos, dificultando a reconstrução |
| Regularização e parada antecipada | Menos memorização |
| Compressão e esparsificação | Menos informação enviada |
| **Agregação segura** | O servidor só vê a **soma** das atualizações (Capítulo 8) |
| **Privacidade diferencial** | Garantia formal por meio de ruído (Capítulo 8) |
| **Criptografia homomórfica** | Cálculos sobre dados cifrados (Capítulo 8) |

:::atencao Atenção
Esconder o servidor da atualização individual **não protege** contra o modelo final. A agregação segura, sozinha, não impede inferência de pertencimento contra o modelo publicado. Defesas se **combinam**.
:::

## 7.11 Resumo do capítulo

:::memorize O essencial do Capítulo 7
- Atualizações **não são** os dados, mas **carregam pistas**.
- Adversários: servidor curioso ou malicioso, clientes maliciosos, observadores e usuários do modelo.
- Ataques: **reconstrução**, **pertencimento**, **propriedades**, **memorização** e **ativos**.
- Na softmax, o gradiente de **um exemplo** é x ⊗ (p − y): a entrada é recuperada **exatamente**.
- A inferência de pertencimento explora a **perda menor** nos exemplos de treino. Aumenta com sobreajuste e poucos dados.
- Mitigações reduzem o risco; **garantias** exigem privacidade diferencial e agregação segura.
:::
