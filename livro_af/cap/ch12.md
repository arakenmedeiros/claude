## 12.1 O desafio

Você chegou ao final da jornada. Agora, em vez de estudar uma técnica por vez, vai **juntar todas**.

Imagine a **Federa Saúde** (fictícia): uma rede de **20 clínicas** que quer treinar um modelo de apoio ao diagnóstico **sem centralizar os dados** dos pacientes. A diretoria tem cinco preocupações:

1. **Qualidade:** o modelo precisa funcionar bem **em cada clínica**, e não só na média.
2. **Dados diferentes:** as clínicas atendem públicos muito distintos (dados não-IID).
3. **Segurança:** **duas** clínicas podem estar comprometidas e tentarão implantar um **backdoor**.
4. **Custo:** a rede entre as clínicas é lenta. Cada byte conta.
5. **Privacidade:** o comitê de ética pergunta qual é o preço de proteger os pacientes.

![f12_etapas](Figura 12.1 — As nove etapas do projeto, do diagnóstico dos dados ao relatório.)

:::cotidiano No seu dia a dia
Um projeto real nunca é "rodar um algoritmo". É uma sequência de decisões com compromissos: qualidade contra custo, privacidade contra utilidade, robustez contra eficiência. O seu trabalho é **medir esses compromissos** e **explicá-los** a quem decide.
:::

## 12.2 Os dados e o cenário

Como não temos dados clínicos reais, usamos o conjunto de **dígitos manuscritos** (UCI, via scikit-learn) como substituto didático. Cada "clínica" é um cliente. O cenário fixo é:

- **20 clientes**, com dados **muito heterogêneos nos rótulos** (Dirichlet, α = 0,3).
- Cada cliente separa **70% para treino e 30% para teste local**.
- **2 clientes maliciosos** (os de índice 0 e 1) executam um **ataque de *backdoor***: treinam também com imagens com gatilho rotuladas como "0".
- Um **teste global** (`Xte`) mede a acurácia geral e o **ASR**, a taxa de sucesso do backdoor.

## 12.3 O motor de simulação `projeto.py`

Para facilitar, o código abaixo reúne, em uma só função, as peças dos capítulos anteriores: **agregador** (média, mediana ou média aparada), **quantização** das atualizações, **privacidade diferencial no nível do cliente** (corte e ruído), **clientes maliciosos** e **contagem de bytes**. Salve-o como **`projeto.py`**. Ele usa também `compressao.py`, `robustez.py` e `personalizacao.py`.

```python
import numpy as np
from fedlib import *
from compressao import quantizar
from robustez import agg_media, agg_mediana, agg_media_aparada, com_gatilho
from personalizacao import dividir_local, acuracias_locais

AGREGADORES = {"media": agg_media, "mediana": agg_mediana, "aparada": lambda D: agg_media_aparada(D, 0.25)}


def fedavg_integrado(treino, X, y, Xte, yte, agregador="media", bits=None, dp_z=None, S=0.5,
                     maliciosos=(), gama=1.0, alvo=0, rodadas=30, epocas=5, eta=0.1, lote=32, seed=0, classes=10):
    """Motor do projeto final: junta agregador robusto, compressão por quantização, DP no nível do cliente
    (corte + ruído) e clientes maliciosos com backdoor. Devolve o modelo, a acurácia, o ASR e os bytes de subida."""
    rng = np.random.default_rng(seed)
    W = np.zeros((X.shape[1], classes))
    n_par = W.size
    maliciosos = set(maliciosos)
    Xte_gat = com_gatilho(Xte[yte != alvo])
    bytes_subida = 0
    for r in range(rodadas):
        deltas = []
        for c, p in enumerate(treino):
            if len(p) == 0:
                continue
            Xc, yc = X[p], y[p]
            if c in maliciosos:                                           # backdoor: metade extra com gatilho
                n_g = len(p) // 2
                Xc = np.vstack([Xc, com_gatilho(Xc[:n_g])]); yc = np.r_[yc, np.full(n_g, alvo)]
            d = treino_local(W, Xc, yc, epocas, eta, lote, 0.0, seed * 1000 + r * 50 + c) - W
            if c in maliciosos:
                d = gama * d
            if dp_z is not None:                                          # corte à norma S
                d = d * min(1.0, S / (np.linalg.norm(d) + 1e-12))
            if bits is not None:
                d = quantizar(d, bits, rng); bytes_subida += int(np.ceil(n_par * bits / 8)) + 8
            else:
                bytes_subida += 4 * n_par
            deltas.append(d)
        D = np.array(deltas)
        if dp_z is not None:
            media = D.mean(axis=0) + rng.normal(0, dp_z * S / len(D), W.shape)    # DP: ruído na média
            W = W + media
        else:
            W = W + AGREGADORES[agregador](D)
    acc = acuracia(W, Xte, yte)
    asr = float(np.mean(np.argmax(Xte_gat @ W, axis=1) == alvo))
    return W, acc, asr, bytes_subida
```

Observe duas decisões de projeto.

- A **DP** (`dp_z`) usa a **média com corte e ruído**, e não a mediana: a garantia formal do Capítulo 8 depende da sensibilidade controlada por corte e média.
- A **quantização** é aplicada **depois** do corte e **antes** da agregação, como faria um cliente real.

## 12.5 Modelo de relatório

Um bom relatório técnico tem **uma página** e segue esta estrutura.

1. **Resumo executivo** (3 linhas): o que foi feito e a recomendação.
2. **Cenário e método**: dados, clientes, ameaças, métricas.
3. **Resultados**: uma tabela (e, se quiser, um gráfico) com as configurações.
4. **Riscos e limitações**: o que o estudo **não** garante.
5. **Recomendação e próximos passos**.

:::dica Dica
Escreva para **quem não é técnico**. Em vez de "o ASR caiu para 0,00", diga "com a mediana, o ataque deixou de funcionar". Em vez de "ε = 14", diga "a proteção formal é fraca com tão poucos clientes".
:::

## 12.6 Critérios de avaliação

- **Correção técnica** (30%): experimentos corretos, com várias sementes.
- **Cobertura** (20%): todas as nove etapas atendidas.
- **Análise** (25%): interpretação honesta dos compromissos, com números.
- **Comunicação** (15%): relatório claro e acessível.
- **Rigor e ética** (10%): limitações reconhecidas; sem alegar privacidade formal sem garantia.

:::memorize Para levar
- Meça **por cliente**, **sob ataque** e **por byte**.
- Nenhuma técnica resolve tudo; as defesas **se combinam**.
- Privacidade e robustez estão em tensão; heterogeneidade e robustez também.
- Documente **limitações**. Um resultado honesto vale mais que um resultado bonito.
:::
