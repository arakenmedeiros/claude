@@EX 1 | Escolhendo k no K-means federado | básico
No conjunto *Wine* (padronizado), em 5 clientes Dirichlet (α = 0,3), rode `kmeans_federado` para k = 1 a 6, com inicialização por `np.random.default_rng(0)`. Calcule a **soma dos quadrados dentro dos grupos** (SSE) de forma federada (cada cliente envia seu SSE local, e o servidor soma). Compare com a `inertia_` do `KMeans` do scikit-learn com a mesma inicialização.

*Pergunta:* o "cotovelo" aparece em k = 3? Os valores federados coincidem com os centralizados?
@@SOL
```python
import numpy as np
from sklearn.cluster import KMeans
from sklearn.datasets import load_wine
from sklearn.preprocessing import StandardScaler
from fronteiras import *

X, y = load_wine(return_X_y=True)
X = StandardScaler().fit_transform(X)
partes = particao_dirichlet(y, 5, 0.3, seed=0)
rng = np.random.default_rng(0)

def sse_federado(partes, X, C):
    total = 0.0
    for p in partes:                                       # cada cliente calcula o seu SSE local
        d = ((X[p][:, None, :] - C[None]) ** 2).sum(-1)
        total += d.min(1).sum()
    return total                                           # o servidor soma

print(f"{'k':>3}{'SSE federado':>15}{'inertia sklearn':>18}")
for k in range(1, 7):
    C0 = X[rng.choice(len(X), k, replace=False)]
    Cf = kmeans_federado(partes, X, C0, iteracoes=100)
    km = KMeans(k, init=C0, n_init=1, max_iter=300, tol=0, algorithm="lloyd").fit(X)
    print(f"{k:>3}{sse_federado(partes, X, Cf):>15.2f}{km.inertia_:>18.2f}")
```
@@NOTE Os valores federados e centralizados coincidem (a mesma inicialização produz a mesma solução). A queda do SSE é forte até k = 3 e depois suaviza, sugerindo k = 3 (o "cotovelo"), que corresponde às três classes de vinho. Observe que SSE sempre diminui com k, e por isso o cotovelo é um critério visual, e não exato.

@@EX 2 | PCA federado nos dígitos | básico
Nos dígitos (`load_digits`, 64 atributos, padronizados), em 10 clientes Dirichlet (α = 0,5), calcule o PCA federado e a **variância explicada acumulada** com as primeiras 5, 10, 20 e 30 componentes. Compare com `PCA` do scikit-learn e determine quantas componentes explicam 90% da variância.

*Pergunta:* o PCA federado coincide com o centralizado? Quanto se reduz a dimensão?
@@SOL
```python
import numpy as np
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.preprocessing import StandardScaler
from fronteiras import *

X, y = load_digits(return_X_y=True)
X = StandardScaler().fit_transform(X)
X = X[:, X.std(axis=0) > 1e-8]                 # remove colunas constantes
partes = particao_dirichlet(y, 10, 0.5, seed=0)

mu, valores, vetores = pca_federado(partes, X, X.shape[1])
total = np.var(X, axis=0, ddof=1).sum()
acum_fed = np.cumsum(valores) / total
pca = PCA().fit(X)
acum_cen = np.cumsum(pca.explained_variance_ratio_)

print(f"{'componentes':>12}{'federado':>12}{'centralizado':>14}")
for k in (5, 10, 20, 30):
    print(f"{k:>12}{acum_fed[k - 1]:>12.4f}{acum_cen[k - 1]:>14.4f}")
print("componentes para 90% da variância (federado)    :", int(np.searchsorted(acum_fed, 0.90) + 1), "de", X.shape[1])
print("componentes para 90% da variância (centralizado):", int(np.searchsorted(acum_cen, 0.90) + 1))
```
@@NOTE Os valores coincidem (a matriz de covariância federada é exatamente a centralizada). Cerca de 31 componentes (de 61 atributos não constantes) explicam 90% da variância, ou seja, metade da dimensão. Isto serve para economizar comunicação em etapas posteriores, desde que a redução seja feita de modo federado e com os devidos cuidados de privacidade.

@@EX 3 | Regressão linear federada exata | intermediário
No conjunto de diabetes (`load_diabetes`, 10 atributos, alvo numérico), reparta os dados em 6 clientes de tamanhos diferentes. Cada cliente envia `XᵀX` e `Xᵀy` (com uma coluna de 1 para o intercepto). O servidor soma e resolve as equações normais. Compare os coeficientes com `LinearRegression`. Depois repita com regularização de Ridge (λ = 1) e compare com `Ridge(alpha=1)`.

*Pergunta:* por que o resultado é exatamente igual ao centralizado?
@@SOL
```python
import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression, Ridge

X, y = load_diabetes(return_X_y=True)
n = len(y)
rng = np.random.default_rng(0)
idx = rng.permutation(n)
clientes = np.split(idx, [30, 90, 160, 250, 350])             # 6 clientes de tamanhos diferentes
print("tamanhos:", [len(c) for c in clientes])

d = X.shape[1] + 1
XtX, Xty = np.zeros((d, d)), np.zeros(d)
for c in clientes:                                             # cada cliente envia só estas somas
    Xk = np.hstack([X[c], np.ones((len(c), 1))])
    XtX += Xk.T @ Xk
    Xty += Xk.T @ y[c]

beta = np.linalg.solve(XtX, Xty)                               # servidor: equações normais
ref = LinearRegression().fit(X, y)
print("OLS: diferença máxima nos coeficientes :", float(np.abs(beta[:-1] - ref.coef_).max()))
print("OLS: diferença no intercepto           :", float(abs(beta[-1] - ref.intercept_)))

# Ridge (sem penalizar o intercepto)
lam = 1.0
P = np.eye(d) * lam; P[-1, -1] = 0
beta_r = np.linalg.solve(XtX + P, Xty)
ref_r = Ridge(alpha=lam).fit(X, y)
print("Ridge: diferença máxima nos coeficientes:", float(np.abs(beta_r[:-1] - ref_r.coef_).max()))
```
@@NOTE A diferença fica na casa dos erros de arredondamento. As somas XᵀX e Xᵀy são **somas sobre exemplos**, e portanto se combinam exatamente entre clientes. A regularização de Ridge só acrescenta uma matriz no servidor. Atenção: XᵀX e Xᵀy também revelam informação sobre os dados (por exemplo, em clientes muito pequenos); combine com agregação segura e DP quando necessário.

@@EX 4 | Quanto posto o adaptador precisa? | intermediário
Reproduza o experimento de LoRA do capítulo com **três tarefas novas**, cada uma trocando o nome de mais classes: (a) 3 ↔ 5; (b) 3 ↔ 5 e 4 ↔ 9; (c) 3 ↔ 5, 4 ↔ 9 e 1 ↔ 7. Para os postos 1, 2, 4 e 8, relate a acurácia na rodada 20 (média de 2 sementes, 20 clientes Dirichlet α = 0,5).

*Pergunta:* como o posto necessário cresce com o número de trocas?
@@SOL
```python
import numpy as np
from fronteiras import *

Xtr, Xte, ytr, yte = carregar_digits()
W0 = np.zeros((65, 10))
for _ in range(300):
    W0 -= 0.5 * gradiente(W0, Xtr, ytr)

def tarefa(trocas):
    perm = np.arange(10)
    for a, b in trocas:
        perm[a], perm[b] = b, a
    return perm[ytr], perm[yte]

tarefas = {"1 troca": [(3, 5)], "2 trocas": [(3, 5), (4, 9)], "3 trocas": [(3, 5), (4, 9), (1, 7)]}
print(f"{'tarefa':<10}" + "".join(f"{'r = ' + str(r):>9}" for r in (1, 2, 4, 8)))
for nome, trocas in tarefas.items():
    ytr2, yte2 = tarefa(trocas)
    linha = []
    for posto in (1, 2, 4, 8):
        accs = []
        for s in range(2):
            partes = particao_dirichlet(ytr, 20, 0.5, seed=s)
            h, _ = fedavg_adaptador(partes, Xtr, ytr2, Xte, yte2, W0, posto, seed=s)
            accs.append(h[-1])
        linha.append(np.mean(accs))
    print(f"{nome:<10}" + "".join(f"{a:>9.3f}" for a in linha))
```
@@NOTE Cada troca de duas classes corresponde a uma correção de posto 2 (trocam-se duas colunas dos pesos). Com uma troca, o posto 1 basta (0,97); com duas, é preciso posto 2 ou mais (0,96); com três, o posto 2 já não basta (0,82), e os postos 4 e 8 chegam a cerca de 0,95. A capacidade do adaptador precisa crescer com a complexidade da mudança.

@@PROJ Perfil de clientes sem juntar os cadastros | Cap11
**Contexto.** Uma rede de 5 lojas (fictícia) quer entender **perfis de clientes** sem juntar os cadastros. Como não há dados reais, use o conjunto *Wine* da UCI como substituto: cada vinho é um "cliente" descrito por 13 atributos, e as 3 classes são perfis "ocultos". As lojas têm perfis muito desiguais (Dirichlet α = 0,3).

**Tarefas.**
1. Faça a **padronização federada** (n, Σx, Σx² por loja).
2. Faça o **PCA federado** e reduza a 2 componentes.
3. Faça o **K-means federado** (k = 3) nos dados projetados.
4. Compare com o pipeline centralizado equivalente (padronização, PCA e K-means do scikit-learn, com os mesmos exemplos como centroides iniciais): proximidade das componentes principais e ARI entre os agrupamentos.
5. Meça o ARI do agrupamento federado contra as classes ocultas.
6. **Efeito da privacidade:** repita o K-means federado somando ruído gaussiano de desvio σ às somas agregadas por grupo (e à contagem) em cada iteração, para σ ∈ {0; 1; 5; 20}. Reporte o ARI contra o agrupamento sem ruído.
7. Escreva uma recomendação em cinco linhas.

**Entregáveis.** Código, tabela e recomendação.
@@SOL
```python
import numpy as np
from sklearn.cluster import KMeans
from sklearn.datasets import load_wine
from sklearn.decomposition import PCA
from sklearn.metrics import adjusted_rand_score
from fronteiras import *

X, y = load_wine(return_X_y=True)
partes = particao_dirichlet(y, 5, 0.3, seed=0)

# 1) padronização federada
n = sum(len(p) for p in partes)
mu = sum(X[p].sum(0) for p in partes) / n
sigma = np.sqrt(sum((X[p] ** 2).sum(0) for p in partes) / n - mu ** 2)
Xs = (X - mu) / sigma

# 2) PCA federado (2 componentes) e projeção
mu_p, val, vet = pca_federado(partes, Xs, 2)
Z = (Xs - mu_p) @ vet

# 3) K-means federado
C0 = Z[np.random.default_rng(0).choice(len(Z), 3, replace=False)]
Cf = kmeans_federado(partes, Z, C0, iteracoes=50)
rot_f = ((Z[:, None, :] - Cf[None]) ** 2).sum(-1).argmin(1)

# 4) pipeline centralizado equivalente: mesma padronização, PCA e K-means do scikit-learn,
#    com os mesmos exemplos como centroides iniciais
Xc = (X - X.mean(0)) / X.std(0)
Zc = PCA(2).fit_transform(Xc)
indices = np.random.default_rng(0).choice(len(Z), 3, replace=False)
kmC = KMeans(3, init=Zc[indices], n_init=1, max_iter=300, tol=0, algorithm="lloyd").fit(Zc)
print("padronização: diferença máxima na média  :", float(np.abs(mu - X.mean(0)).max()))
print("PCA: |cos| entre componentes federadas e centralizadas:", np.round([abs(vet[:, i] @ PCA(2).fit(Xc).components_[i]) for i in range(2)], 6))
print("K-means: ARI federado x centralizado      :", adjusted_rand_score(rot_f, kmC.labels_))
print("K-means: ARI do federado contra as classes:", round(adjusted_rand_score(y, rot_f), 3))

# 6) privacidade: ruído nas somas e contagens agregadas
def kmeans_federado_ruidoso(partes, X, C0, sigma, iteracoes=50, seed=0):
    rng = np.random.default_rng(seed)
    C = C0.copy()
    for _ in range(iteracoes):
        S, N = np.zeros_like(C), np.zeros(len(C))
        for p in partes:
            a = ((X[p][:, None, :] - C[None]) ** 2).sum(-1).argmin(1)
            for j in range(len(C)):
                S[j] += X[p][a == j].sum(0); N[j] += (a == j).sum()
        S = S + rng.normal(0, sigma, S.shape); N = np.maximum(N + rng.normal(0, sigma, N.shape), 1)
        C = S / N[:, None]
    return C

print(f"\n{'σ':>5}{'ARI vs. sem ruído (média de 10 sementes)':>45}")
for sg in (0, 1, 5, 20):
    aris = []
    for s in range(10):
        Cr = kmeans_federado_ruidoso(partes, Z, C0, sg, seed=s)
        rr = ((Z[:, None, :] - Cr[None]) ** 2).sum(-1).argmin(1)
        aris.append(adjusted_rand_score(rot_f, rr))
    print(f"{sg:>5}{np.mean(aris):>45.3f}")
```
@@RUBRICA
- Padronização, PCA e K-means federados implementados com somas locais.
- Comparação com o centralizado mostrando equivalência (diferença próxima de zero e ARI = 1).
- Experimento com ruído, com interpretação do compromisso entre privacidade e qualidade.
- Recomendação que mencione a necessidade de agregação segura e DP, e os limites (ruído sem garantia formal; dados de vinho como substituto).
@@NOTE O pipeline federado coincide com o centralizado (componentes principais iguais até o sinal e ARI = 1 entre os agrupamentos). O ARI contra as classes mostra que os grupos recuperam bem os perfis ocultos. Com ruído pequeno (σ = 1), o agrupamento praticamente não muda; com σ = 20, as somas ficam muito ruidosas e o ARI cai. Isto ilustra o preço da privacidade, mas esse ruído, por si só, não oferece garantia formal: seria preciso calibrá-lo à sensibilidade (corte dos dados) e contabilizar ε.
